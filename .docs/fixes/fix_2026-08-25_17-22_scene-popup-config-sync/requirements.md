## Исходный текст

Для «Сцены 1» через настраиваемую задержку после настоящего клика убрать отображённые popup-окна с переднего плана, не закрывая их, и вернуть фокус главному окну. Задержка настраивается в UI от 0 до 5 секунд с шагом 0,1 секунды, по умолчанию равна 1,0 секунды и сохраняется между перезапусками. Во время активного таймера последующие настоящие клики не влияют на него и не создают независимые таймеры. В «Сцене 1» выполняется ровно два фейковых клика. Все значения UI всех сцен должны сохраняться в файлы и после сохранения синхронизироваться через Git.

---

## Функциональные требования

- **Запуск единственного таймера:** После настоящего, а не программно сгенерированного клика система должна запустить один таймер с задержкой, заданной в UI.
  - **Пояснение:** Таймер управляет моментом переноса popup-окон с переднего плана.
  - **Источник:** «Через 1 секунду … после настоящего клика».
  - **Acceptance hint:** Настоящий клик запускает один таймер; фейковый клик таймер не запускает.

- **Игнорирование повторных кликов:** Пока таймер активен, дополнительные настоящие клики не должны сбрасывать, продлевать, сокращать или отменять его, создавать дополнительные или параллельные таймеры либо изменять момент выполнения действия. После завершения таймера следующий настоящий клик может запустить новый таймер.
  - **Пояснение:** Одновременно может выполняться только один обратный отсчёт.
  - **Источник:** «Если до истечения задержки произойдёт ещё один настоящий клик — это никак не должно влиять на задержку»; «не должны [создавать независимые таймеры]».
  - **Acceptance hint:** Несколько настоящих кликов во время активного таймера приводят ровно к одному действию в момент, рассчитанный от исходного клика.

- **Игнорирование фейковых кликов:** Программно сгенерированные клики не должны запускать таймер перемещения popup-окон.
  - **Пояснение:** Требование относится только к настоящему пользовательскому вводу.
  - **Источник:** «После настоящего клика».
  - **Acceptance hint:** Выполнение фейковых кликов не создаёт таймер перемещения popup.

- **Увод popup-окон с переднего плана:** По истечении задержки система должна убрать отображённые popup-окна приложения с переднего плана и вернуть фокус главному окну.
  - **Пояснение:** Popup должны оставаться открытыми; их нельзя закрывать или минимизировать на панель задач.
  - **Источник:** «Оставить popup открытыми, но убрать их с переднего плана и вернуть фокус главному окну».
  - **Acceptance hint:** После срабатывания таймера главное окно находится в фокусе, а ранее отображённые popup остаются открытыми и доступными.

- **Настройка задержки:** UI должен позволять настроить задержку от 0 до 5 секунд с шагом 0,1 секунды; при отсутствии сохранённой настройки должно использоваться значение 1,0 секунды. При значении 0 действие выполняется без дополнительной задержки.
  - **Пояснение:** Пользователь управляет временем показа popup перед возвратом к главному окну.
  - **Источник:** «Дай настроить на UI от 0 до 5 цена деления 0.1»; «Через 1 секунду».
  - **Acceptance hint:** UI принимает все значения диапазона с шагом 0,1, а поведение использует выбранное значение.

- **Количество фейковых кликов:** За один полный запуск «Сцены 1» система должна выполнить ровно два фейковых клика и не генерировать дополнительные.
  - **Пояснение:** Количество фиксировано и не настраивается через UI.
  - **Источник:** «Зафиксируй: всего 2 фейковых клика».
  - **Acceptance hint:** Один полный запуск «Сцены 1» регистрирует ровно два программно сгенерированных клика.

- **Полное сохранение UI-конфигурации:** Каждое настраиваемое значение UI во всех сценах должно записываться в конфигурационный файл или файлы при сохранении.
  - **Пояснение:** Пользовательские настройки не должны теряться между сеансами.
  - **Источник:** «Все значения из UI со всех сцен сохраняются в файлы».
  - **Acceptance hint:** После сохранения, перезапуска приложения и загрузки конфигурации каждое поле имеет последнее сохранённое значение.

- **Git-синхронизация конфигурации:** После успешного локального сохранения система должна запускать предусмотренную проектом Git-синхронизацию файлов, содержащих значения UI всех сцен.
  - **Пояснение:** Используется существующая архитектура Git-синхронизации проекта.
  - **Источник:** «Синхронизируются через git после сохранения».
  - **Acceptance hint:** Сохранённые значения присутствуют в отслеживаемых Git файлах и передаются через настроенный механизм синхронизации.

- **Проверка всех сцен:** Необходимо проверить элементы UI каждой сцены и устранить случаи, когда значение не записывается в файл, не восстанавливается при запуске либо не участвует в Git-синхронизации.
  - **Пояснение:** Требование распространяется на всю существующую UI-конфигурацию, а не только на новую задержку «Сцены 1».
  - **Источник:** «Проверь что все значения из UI со всех сцен сохраняются в файлы и синхронизируются через git после сохранения».
  - **Acceptance hint:** Для каждого настраиваемого поля подтверждены запись, восстановление и включение файла в Git-синхронизацию.

## Нефункциональные требования

- **Сохранение состояния popup:** Изменение фокуса и порядка окон не должно приводить к потере состояния или содержимого popup.
  - **Пояснение:** Popup остаются открытыми и пригодными для дальнейшего использования.
  - **Источник:** «Оставить popup открытыми».
  - **Acceptance hint:** Состояние и содержимое popup до и после потери переднего плана совпадают.

- **Точность настройки:** Задержка должна сохраняться и восстанавливаться с точностью 0,1 секунды.
  - **Пояснение:** Точность хранения соответствует шагу элемента UI.
  - **Источник:** «Цена деления 0.1».
  - **Acceptance hint:** Значения с десятичной частью, например 0,1 и 4,9 секунды, не округляются к целым.

- **Долговременное хранение:** Сохранённые значения UI должны сохраняться между перезапусками приложения.
  - **Пояснение:** Настройки восстанавливаются из файлов при следующем запуске.
  - **Источник:** «Значение задержки должно сохраняться между перезапусками приложения»; «все значения из UI со всех сцен сохраняются в файлы».
  - **Acceptance hint:** После полного завершения и повторного запуска приложения отображаются последние сохранённые значения.

- **Полнота конфигурации:** Сохранение и восстановление должны охватывать все изменяемые пользователем значения во всех существующих сценах.
  - **Пояснение:** В UI не должно быть несохраняемых настроек.
  - **Источник:** «Все значения из UI со всех сцен».
  - **Acceptance hint:** Инвентаризация UI и сериализуемой конфигурации не выявляет пропущенных значений.

- **Детерминированность таймера:** Одновременно может существовать не более одного таймера перемещения popup-окон.
  - **Пояснение:** Повторный ввод во время ожидания не порождает конкурирующее действие.
  - **Источник:** «Не должны [создавать независимые таймеры]».
  - **Acceptance hint:** Серия кликов во время ожидания создаёт одно срабатывание.

## Проблемы и замечания, превращённые в требования

- **Popup остаются на переднем плане:** Сейчас popup могут перекрывать главное окно после настоящего клика. Требуемое поведение: по истечении задержки оставить popup открытыми, убрать их с переднего плана и вернуть фокус главному окну.
  - **Источник:** «Убрать их с переднего плана и вернуть фокус главному окну».
  - **Acceptance hint:** Главное окно получает фокус без закрытия или минимизации popup.

- **Повторные клики могут влиять на ожидание:** Требуемое поведение: дополнительные настоящие клики во время активного таймера игнорируются этим механизмом и не создают новые таймеры.
  - **Источник:** «Это никак не должно влиять на задержку»; «не должны».
  - **Acceptance hint:** Момент и количество срабатываний не меняются после повторных кликов.

- **Количество фейковых кликов должно быть фиксированным:** Требуемое поведение: в «Сцене 1» всегда выполняются ровно два фейковых клика.
  - **Источник:** «Всего 2 фейковых клика».
  - **Acceptance hint:** При повторных запусках сцены количество остаётся равным двум.

- **Настройки UI могут сохраняться неполно:** Требуемое поведение: все значения UI всех сцен записываются в файлы, восстанавливаются после перезапуска и участвуют в Git-синхронизации.
  - **Источник:** «Проверь что все значения из UI со всех сцен сохраняются в файлы и синхронизируются через git после сохранения».
  - **Acceptance hint:** Проверка каждого поля подтверждает полный цикл сохранения, загрузки и синхронизации.

## Открытые вопросы

- Под Git-синхронизацией предполагается существующий механизм проекта. Если его нет, требуется уточнить ожидаемые операции: только commit либо commit и push.
- Не определено требуемое поведение при ошибке Git-синхронизации: достаточно ли показать ошибку или нужны автоматические повторные попытки.

## Не включено / требует уточнения

- Popup не сворачиваются на панель задач: они только теряют передний план и фокус.
- Количество фейковых кликов фиксировано и не настраивается через UI.
- Конкретный формат конфигурационных файлов, Git remote и ветка не задаются; предполагается использование существующей архитектуры проекта.
