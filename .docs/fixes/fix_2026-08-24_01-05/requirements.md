## Исходный текст

Для сцен 1, 2 и 3 нужно вывести общие параметры, дублирующиеся между соседними сценами, и пометить их в UI всех трёх сцен. Если общий параметр изменён в любой сцене, после перезагрузки остальных страниц там должны примениться последние изменения. Имеющиеся рассинхроны общих параметров нужно привести к состоянию предыдущей сцены, считая предыдущую сцену эталоном.

Принятая при апруве трактовка: общий параметр определяется одинаковым внутренним именем в соседних сценах; эталон применяется каскадно `сцена 1 → сцена 2 → сцена 3`; обычное завершённое изменение контрола считается последним изменением; синхронизация одновременно открытых вкладок без перезагрузки не требуется.

## Функциональные требования

- **Состав общих параметров:** Система должна считать общим параметр с одинаковым внутренним именем, отображаемый в соседних сценах.
  - **Пояснение:** Найдено 84 уникальных общих параметра: 20 присутствуют во всех трёх сценах, ещё 64 — только в сценах 2 и 3; отдельных параметров только для пары сцен 1 и 2 нет.
  - **Источник:** «Выведи общие параметры дублирующиеся между соседними сценами».
  - **Acceptance hint:** Автоматическая проверка множества контролов возвращает 20 общих для сцен 1–3 и 64 дополнительных для сцен 2–3.

- **Общие параметры сцен 1–3:** Единое состояние должны использовать следующие параметры: тема; три цвета светлого фона; три цвета тёмного фона; изображение основного камня; кривая размера; уменьшение при нажатии; включение пульса; уменьшение при пульсе; частота пульса; начальный размер; включение и размер курсора; отображение руки; задержка смены изображения руки; звуки руки; размер руки.
  - **Пояснение:** Эти 20 контролов присутствуют на каждой странице сцены.
  - **Источник:** «общие параметры дублирующиеся между соседними сценами».
  - **Acceptance hint:** Изменение любого из перечисленных параметров из любой сцены восстанавливается во всех трёх сценах после перезагрузки.

- **Общие параметры сцен 2–3:** Единое состояние должны использовать: высота страницы; четыре настройки камеры; шесть настроек 3D Fold; семь настроек физики; случайное выпадение, пять настроек выпрыгивания/массы и четыре настройки размера/изображения камня; пять настроек руки; 27 настроек траектории и glow; четыре настройки капели.
  - **Пояснение:** Эти 64 контрола отсутствуют в сцене 1 и не должны добавляться на её страницу.
  - **Источник:** «общие параметры дублирующиеся между соседними сценами».
  - **Acceptance hint:** Изменение тяготения или другого параметра этой группы в сцене 2 восстанавливается в сцене 3 и наоборот; в сцене 1 соответствующий контрол не появляется.

- **Единое состояние общих параметров:** Каждый общий параметр должен иметь одно актуальное сохранённое значение для всех сцен, в которых он присутствует.
  - **Пояснение:** У сцен сохраняются независимые страницы и уникальные параметры, но дублирующиеся контролы больше не имеют независимых значений.
  - **Источник:** «общие параметры могут изменять любая сцена и они должны изменить везде».
  - **Acceptance hint:** После последовательного изменения общего параметра в разных сценах следующая загрузка использует последнее завершённое изменение.

- **Синхронизация после перезагрузки:** Изменение общего параметра в любой допустимой сцене должно автоматически сохраняться, а при открытии или перезагрузке другой сцены общее значение должно применяться поверх старого scene-specific значения.
  - **Пояснение:** Отдельное нажатие кнопки сохранения версии для обычного изменения контрола не требуется.
  - **Источник:** «при перезагрузке других страниц подтягиваются последние изменения».
  - **Acceptance hint:** Изменить тему в сцене 3, перезагрузить сцены 1 и 2 и убедиться, что обе получили новую тему.

- **Маркировка в UI:** Каждый общий контрол должен иметь видимую метку «Общий» и доступную подсказку с областью действия «сцены 1–3» или «сцены 2–3».
  - **Пояснение:** Пользователь должен до изменения понимать, что значение влияет на другие страницы.
  - **Источник:** «Пометь на UI всех 3 сцен общие параметры».
  - **Acceptance hint:** В сцене 1 помечены 20 контролов, в сценах 2 и 3 — по 84; смысл метки доступен не только через цвет.

- **Последнее изменение побеждает:** После первичного выравнивания любое новое завершённое изменение общего контрола должно становиться эталонным для последующих загрузок всех применимых сцен.
  - **Пояснение:** Общий параметр можно редактировать с любой страницы, на которой он присутствует.
  - **Источник:** «общие парамтеры могут изменять любая сцена».
  - **Acceptance hint:** Последовательно задать разные значения в сценах 1 и 3; после перезагрузки всех применимых страниц должно использоваться значение сцены 3.

- **Первичное выравнивание:** Если нового общего хранилища ещё нет, система должна мигрировать существующие значения каскадно: для параметров сцен 1–3 приоритет имеет сохранённое значение сцены 1; для параметров только сцен 2–3 — значение сцены 2; если значения предыдущей сцены нет, используется значение следующей сцены, затем default.
  - **Пояснение:** Сцена 1 сначала нормализует сцену 2, после чего уже нормализованная сцена 2 является эталоном для сцены 3.
  - **Источник:** «приведи к состоянию предыдущей сцены (считай предыдущую сцену эталоном общих параметров)».
  - **Acceptance hint:** Старые разные scene-specific ключи после первой загрузки формируют один детерминированный общий набор и больше не применяются поверх него.

- **Выравнивание текущих шаблонов:** Актуальные scene-specific записи в `config/settings-templates.json` должны быть приведены к той же каскадной модели эталона.
  - **Пояснение:** Репозиторный каталог не должен хранить противоречащие друг другу текущие значения общих параметров.
  - **Источник:** «Текущие рассинхроны общих парамтеров если они есть приведи к состоянию предыдущей сцены».
  - **Acceptance hint:** Общие поля актуальных записей сцен 1–3 совпадают согласно областям действия после нормализации.

- **Применение именованной версии:** При выборе именованной версии её общие поля должны становиться последним изменением общего состояния, а уникальные поля — применяться только к текущей сцене.
  - **Пояснение:** Сохранённая версия является одним из способов изменения параметров сцены и не должна обходить общую модель.
  - **Источник:** Требование о возможности изменить общий параметр из любой сцены.
  - **Acceptance hint:** Выбрать версию в сцене 2, перезагрузить сцену 3 и проверить общие поля; уникальные поля сцены 2 не должны попасть в сцену 3.

- **Сохранение уникальных параметров:** Параметры, отсутствующие в соседней сцене, должны продолжать сохраняться независимо и не перезаписываться при загрузке или сохранении общего состояния.
  - **Пояснение:** Новый общий слой не объединяет всю конфигурацию сцен.
  - **Источник:** Запрос относится только к дублирующимся общим параметрам.
  - **Acceptance hint:** Изменение уникального параметра сцены 2 не изменяет значение или поведение сцены 3.

- **Единый контракт параметра пульса:** Параметр «Уменьшение при пульсе, %» во всех трёх сценах должен использовать контракт сцены 1: диапазон `0–10`, шаг `0.1`.
  - **Пояснение:** Текущие диапазоны `0–10 / 0.1` и `0–50 / 1` несовместимы с единым значением без потерь; предыдущая сцена является эталоном.
  - **Источник:** «считай предыдущую сцену эталоном общих параметров».
  - **Acceptance hint:** Все три материализованных контрола имеют одинаковые `min`, `max` и `step`, а дробное значение восстанавливается без округления.

## Нефункциональные требования

- **Идемпотентная миграция:** Повторные перезагрузки не должны повторно применять старые scene-specific значения поверх нового общего состояния.
  - **Пояснение:** После первого выравнивания действует только последнее общее значение.
  - **Источник:** Требование постоянной синхронизации после перезагрузки.
  - **Acceptance hint:** Две и более последовательные перезагрузки не меняют уже согласованное значение.

- **Обратная совместимость данных:** Миграция должна сохранять существующие уникальные параметры и корректно обрабатывать отсутствие части старых scene-specific ключей.
  - **Пояснение:** Пользовательские настройки не должны сбрасываться целиком из-за введения общего слоя.
  - **Источник:** Требование привести только общие параметры к эталону.
  - **Acceptance hint:** При частично заполненном старом хранилище общие поля получают безопасный fallback, уникальные поля остаются прежними.

- **Надёжность хранения:** Недоступный или повреждённый `localStorage` не должен блокировать загрузку сцены; применяются безопасные значения по умолчанию.
  - **Пояснение:** Клиентское хранилище уже используется приложением и должно сохранять текущую отказоустойчивость.
  - **Источник:** Требование работы страниц после перезагрузки.
  - **Acceptance hint:** Некорректный JSON или исключение storage не приводит к падению runtime.

- **Стабильность UI:** Метки общих параметров не должны создавать дубликаты контролов или изменять их количество: `38 / 103 / 106` для сцен 1 / 2 / 3.
  - **Пояснение:** Меняется только подпись области действия, а не состав UI.
  - **Источник:** Требование пометить существующие параметры.
  - **Acceptance hint:** Smoke-проверка подтверждает прежнее количество `[data-setting-control]` и требуемое количество общих маркеров.

- **Регрессионная проверяемость POC B:** Изменение должно быть покрыто unit-проверками классификации, merge и приоритетов, а также smoke-сценарием изменения и перезагрузки трёх прямых URL.
  - **Пояснение:** Затронут основной демонстрационный путь настроек POC B.
  - **Источник:** Текущая стадия проекта и approved требования.
  - **Acceptance hint:** Релевантные unit- и smoke-тесты проходят в Docker; вручную подтверждены маркеры и межсценовая перезагрузка.

- **Актуальность документации:** README, `.docs/product.md`, `.docs/technical.md` и `.docs/demo.md` должны описывать общий слой параметров вместо полной изоляции одинаковых значений.
  - **Пояснение:** Новый запрос пересматривает часть предыдущего утверждённого решения о разделении сцен.
  - **Источник:** Изменение продуктовой и технической модели параметров.
  - **Acceptance hint:** В актуальных документах нет утверждений, что одинаковые параметры всех сцен всегда независимы.

## Проблемы и замечания, превращённые в требования

- **Раздельные ключи хранения:** Сейчас каждая сцена использует отдельный ключ, поэтому одинаковые контролы сохраняют разные значения. Требуемое поведение: общие поля загружаются и обновляются через единое постоянное состояние.
  - **Источник:** «при перезагрузке других страниц подтягиваются последние изменения».
  - **Acceptance hint:** Старое значение текущей сцены не перекрывает более новое общее значение.

- **Неочевидная область действия:** Сейчас UI не показывает, какие настройки воздействуют на соседние сцены. Требуемое поведение: каждый общий контрол имеет явную видимую и доступную метку.
  - **Источник:** «Пометь на UI всех 3 сцен общие параметры».
  - **Acceptance hint:** Пользователь может определить область действия до изменения значения.

- **Рассинхрон текущих версий:** В актуальных отслеживаемых версиях найдено пять расхождений между сценами 1 и 2 и четырнадцать между сценами 2 и 3. Требуемое поведение: значения нормализованы каскадно по предыдущей сцене.
  - **Источник:** «Текущие рассинхроны общих парамтеров если они есть приведи к состоянию предыдущей сцены».
  - **Acceptance hint:** Сравнение общих полей актуальных записей не показывает расхождений в пределах их области действия.

- **Несовместимый диапазон пульса:** Сейчас один общий параметр имеет разные диапазоны и шаги. Требуемое поведение: UI-контракт предыдущей сцены применяется во всех трёх сценах.
  - **Источник:** «считай предыдущую сцену эталоном общих параметров».
  - **Acceptance hint:** Значение `3.7` одинаково сохраняется и отображается во всех сценах.

- **Устаревшие проверки и документация:** Сейчас тесты и документы утверждают полную изоляцию одинаковых параметров. Требуемое поведение: они отражают общий слой и сохранение независимости только для уникальных полей.
  - **Источник:** Новый approved запрос пересматривает прежнее требование «общих параметров нет».
  - **Acceptance hint:** Релевантные assertions и демонстрационные шаги проверяют новую модель.

## Не включено / требует уточнения

- Не объединяются уникальные параметры сцен и не добавляются отсутствующие контролы на другие страницы.
- Не объединяются игровое состояние, физический lifecycle или финальные состояния сцен.
- Не меняются навигация и прямые URL сцен.
- Не требуется live-синхронизация между одновременно открытыми вкладками без перезагрузки.
- Каталоги именованных версий остаются scene-specific; общими становятся только значения общих полей при применении версии.
