## Исходный текст

Пользователь потребовал сохранять общий каталог шаблонов настроек в файле,
который хранится и синхронизируется через репозиторий, полностью удалить
slave-руку из приложения и UI, а затем удалить саму роль `slave`, оставив
единственную роль `master` для всех участников общей сессии.

---

## Функциональные требования

- **Общий файл шаблонов:** Система должна хранить каталог шаблонов в
  отслеживаемом Git файле `config/settings-templates.json`.
  - **Пояснение:** Каталог должен переноситься между окружениями через обычный
    commit/push/pull репозитория.
  - **Источник:** "Сохраняй шаблоны настроек куда-то в общий файл, который хранится и синхронизируется через репозиторий".
  - **Acceptance hint:** После сохранения шаблона файл меняется и отображается в
    `git status`; после pull и перезапуска сервера шаблон доступен другому
    окружению.

- **Полный цикл записи:** Сохранение, импорт, удаление и создание конфликтной
  версии должны атомарно обновлять общий файл.
  - **Пояснение:** Git-файл является canonical каталогом, а не одноразовым seed.
  - **Источник:** "Сохраняй шаблоны настроек ... в общий файл".
  - **Acceptance hint:** Все операции каталога изменяют один и тот же JSON без
    временных файлов после завершения операции.

- **Загрузка и Docker-доступ:** Сервер должен загружать каталог при старте, а
  dev и debug-production должны подключать репозиторный каталог как
  записываемый bind mount.
  - **Пояснение:** Изменения из контейнера должны попадать в рабочее дерево.
  - **Источник:** "... хранится и синхронизируется через репозиторий".
  - **Acceptance hint:** Сохранение из браузера меняет файл на хосте; recreate
    контейнера сохраняет каталог.

- **Миграция существующего каталога:** Найденный шаблон `v1` должен быть
  перенесён с сохранением актуальных настроек; удалённые slave-поля в него не
  переносятся.
  - **Пояснение:** Смена хранилища не должна уничтожить пользовательские данные.
  - **Источник:** Требование перенести каталог из текущего общего хранилища в
    репозиторий.
  - **Acceptance hint:** После перехода `v1` загружается из репозиторного файла
    и не содержит slave-настроек.

- **Единственная роль master:** Каждый подключённый участник общей сессии
  должен получать роль `master`; роль `slave` не должна создаваться или
  передаваться.
  - **Пояснение:** Multiplayer сохраняется без ролевого разделения участников.
  - **Источник:** "Убери роль slave. Остается только роль master".
  - **Acceptance hint:** Два одновременно подключённых браузера получают
    `clientRole: master` и одинаковые возможности.

- **Удаление назначения ролей:** Сервер не должен выбирать первого master и
  назначать остальных slave; `masterClientId` и связанная логика восстановления
  должны быть удалены.
  - **Пояснение:** Одноролевая модель не нуждается в владельце комнаты.
  - **Источник:** "Остается только роль master".
  - **Acceptance hint:** Новые session-store записи не содержат
    `masterClientId`; старые записи с ним загружаются без ошибки.

- **Равные возможности:** Все участники должны иметь одинаковые права на
  управление камнем и доступные в текущем режиме настройки.
  - **Пояснение:** Роль больше не может ограничивать действия пользователя.
  - **Источник:** "Остается только роль master".
  - **Acceptance hint:** Второй подключённый браузер может выполнять те же
    разрешённые действия, что и первый.

- **Удаление slave-руки:** Отдельная slave-рука не должна существовать в модели,
  рендеринге, UI или сохранённых настройках.
  - **Пояснение:** Все участники используют единое master-представление руки и
    указателя.
  - **Источник:** "Убери slave руку как сущность отовсюду в том числе из UI".
  - **Acceptance hint:** В DOM, панели, runtime и данных нет slave-руки и её
    параметров.

- **Очистка реализации и ресурсов:** Slave-поля, UI-контролы, CSS-ветки,
  специализированные изображения, тестовые данные и документация должны быть
  удалены.
  - **Пояснение:** После изменения не должно оставаться мёртвой сущности.
  - **Источник:** "... как сущность отовсюду в том числе из UI".
  - **Acceptance hint:** Поиск по исходникам и актуальной документации не
    находит role-specific slave-hand реализации.

## Нефункциональные требования

- **Надёжность каталога:** Запись должна оставаться атомарной, ограничение в 50
  шаблонов и защита от повреждённых данных должны сохраниться.
  - **Пояснение:** Перенос в Git не должен ухудшить устойчивость store.
  - **Источник:** Требование изменить место хранения, не поведение каталога.
  - **Acceptance hint:** Unit-тесты подтверждают atomic save, reload и fallback.

- **Читаемые изменения:** JSON каталога должен форматироваться для понятных
  Git-диффов.
  - **Пояснение:** Файл предназначен для синхронизации и ревью через репозиторий.
  - **Источник:** "... синхронизируется через репозиторий".
  - **Acceptance hint:** Файл записан многострочным JSON с завершающей новой
    строкой.

- **Обратная совместимость:** Старые шаблоны и сессии со slave-полями должны
  загружаться без падения; устаревшие поля игнорируются и больше не записываются.
  - **Пояснение:** Обновление не должно требовать ручной очистки volume.
  - **Источник:** Удаление slave-сущностей из существующего приложения.
  - **Acceptance hint:** Тестовые legacy-записи загружаются, а повторная запись
    не содержит устаревших полей.

- **Сохранение realtime:** Совместная работа нескольких участников должна
  продолжить работать после перехода на одну роль.
  - **Пояснение:** Удаляется ролевое различие, а не multiplayer.
  - **Источник:** "Остается только роль master".
  - **Acceptance hint:** Integration/smoke-тесты двух браузеров проходят.

- **Чистота:** В проекте не должно оставаться неиспользуемого slave-кода и
  специализированных ресурсов.
  - **Пояснение:** Требование относится к сущности целиком, а не только к UI.
  - **Источник:** "... отовсюду".
  - **Acceptance hint:** Линтер и поиск по проекту подтверждают отсутствие
    актуальной slave-логики.

## Проблемы и замечания, превращённые в требования

- **Изолированный каталог:** Сейчас Docker volume скрывает шаблоны от Git.
  Требуемое поведение: репозиторий является переносимым источником каталога.
  - **Источник:** "... общий файл, который хранится и синхронизируется через репозиторий".
  - **Acceptance hint:** Изменение каталога появляется в рабочем дереве.

- **Ролевое разделение:** Сейчас участники делятся на `master` и `slave`.
  Требуемое поведение: существует только роль `master`, одинаковая для всех.
  - **Источник:** "Убери роль slave. Остается только роль master".
  - **Acceptance hint:** Сервер, frontend и контракты не создают значение
    `slave`.

- **Отдельная slave-рука:** Сейчас slave-рука имеет собственное визуальное
  представление и настройки. Требуемое поведение: такой сущности нет.
  - **Источник:** "Убери slave руку как сущность отовсюду в том числе из UI".
  - **Acceptance hint:** Все участники используют единое представление руки.

## Не включено / требует уточнения

- Автоматические `git commit`, `push` и `pull` не требуются.
- Выбранный production preset остаётся в отдельном runtime volume.
- Горячая перезагрузка каталога после `git pull` без перезапуска сервера не
  требуется.
- Общая сессия не ограничивается одним участником.
