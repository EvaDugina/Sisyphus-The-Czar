## Исходный текст

Сцена 1: для фейкового клика и для отскакивания нужны разные звуковые настройки в UI. Для отскакивания требуется такой же select, как для фейкового клика. Звук отскакивания по умолчанию — «Смех», звук фейкового клика по умолчанию — «Симуляция оргазма». В обоих списках должны быть эти два звука и каждый поддерживаемый аудиофайл из папки `gachi`.

## Функциональные требования

- **Звук фейкового клика:** Система должна один раз воспроизводить выбранный звук при каждом зарегистрированном фейковом клике сцены 1.
  - **Пояснение:** Звуковая реакция относится к событию клика независимо от последующего движения камня.
  - **Источник:** «Для фейкового клика ... нужна возможность на UI выбирать разные звуки».
  - **Acceptance hint:** Назначить звук фейкового клика, выполнить фейковый клик и проверить один запуск выбранного файла.

- **Звук отскакивания:** Система должна предоставить отдельный select «Звук отскакивания» и один раз воспроизводить выбранный в нём звук при каждом отскакивании камня в сцене 1.
  - **Пояснение:** Звук движения камня настраивается отдельно от звука фейкового клика.
  - **Источник:** «для отскакивания нужна возможность на UI выбирать разные звуки, добавь такой же select для отскакивания».
  - **Acceptance hint:** Назначить отдельный звук отскакивания, вызвать отскок без фейкового клика и проверить один запуск выбранного файла.

- **Независимость настроек:** Система должна хранить и применять значения двух select независимо друг от друга.
  - **Пояснение:** Изменение одного звука не должно менять другой.
  - **Источник:** «выбирать разные звуки».
  - **Acceptance hint:** Выбрать разные значения, изменить только одно и убедиться, что второе осталось прежним.

- **Общий набор вариантов:** Оба select должны содержать «Без звука», «Смех», «Симуляция оргазма» и каждый поддерживаемый аудиофайл из папки `gachi` как отдельный вариант.
  - **Пояснение:** Для обоих событий доступен одинаковый полный каталог звуков.
  - **Источник:** «добавь такой же select» и ранее утверждённый набор звуков.
  - **Acceptance hint:** Сверить оба списка между собой и с поддерживаемыми файлами `assets/audio/gachi`.

- **Значения по умолчанию:** Система должна использовать «Симуляцию оргазма» для фейкового клика и «Смех» для отскакивания.
  - **Источник:** «Звук отскакивания по умолчанию смех. Звук фейкового клика по умолчанию Симмуляция оргазма».
  - **Acceptance hint:** Открыть сцену 1 с настройками по умолчанию и проверить выбранные значения обоих select.

- **Совмещённое событие:** Если фейковый клик одновременно запускает отскакивание, система должна независимо воспроизвести звук фейкового клика и звук отскакивания.
  - **Пояснение:** Два разных события не должны подавлять звуковую реакцию друг друга.
  - **Acceptance hint:** Назначить событиям разные звуки и проверить запуск обоих файлов на фейковом клике с отскоком.

- **Сохранение конфигурации:** Система должна отдельно сохранять и восстанавливать оба выбранных значения существующим механизмом конфигураций сцены 1.
  - **Acceptance hint:** Сохранить конфигурацию с разными звуками, изменить значения, загрузить конфигурацию и проверить восстановление обоих select и runtime.

- **Изоляция области действия:** Новые настройки не должны изменять начальный клик, другие игровые звуки и поведение сцен 2 и 3.
  - **Источник:** «СЦЕНА 1».
  - **Acceptance hint:** Проверить, что начальный клик и звуки других сцен работают по прежним настройкам.

## Нефункциональные требования

- **Понятность UI:** Названия вариантов должны быть понятными и одинаковыми в обоих select.
  - **Пояснение:** Оператор должен однозначно различать настраиваемое событие и выбранный файл.
  - **Источник:** Требование двух независимых select.
  - **Acceptance hint:** В UI видны два различимо подписанных поля без пустых или дублирующихся пунктов.

- **Фильтрация файлов:** Система должна показывать только поддерживаемые и воспроизводимые аудиофайлы.
  - **Пояснение:** Служебные и неподдерживаемые файлы не должны попадать в список.
  - **Источник:** «звуками из папки gachi».
  - **Acceptance hint:** Каждый отображаемый пункт соответствует реально загружаемому аудиофайлу.

- **Неблокирующее воспроизведение:** Аудио не должно задерживать отскок, popup, обработку клика или завершение сцены.
  - **Пояснение:** Звуки остаются побочными эффектами игровых событий.
  - **Источник:** Контекст существующего игрового сценария.
  - **Acceptance hint:** Сценарий проходит с каждым вариантом, включая «Без звука».

- **Независимые аудиоканалы:** Одновременные звуки фейкового клика и отскакивания не должны останавливать или перезапускать друг друга.
  - **Пояснение:** Совмещённое событие должно сохранять обе звуковые реакции.
  - **Acceptance hint:** При разных выбранных файлах фиксируется по одному запуску каждого.

## Проблемы и замечания, превращённые в требования

- **Одна настройка для разных событий:** Сейчас звук фейкового клика и звук отскакивания не настраиваются независимо. Требуемое поведение: каждое событие имеет собственный select, собственное значение по умолчанию и отдельное сохранённое значение.
  - **Источник:** «Для фейкового клика и для отскакивания нужна возможность на UI выбирать разные звуки».
  - **Acceptance hint:** Назначить разные значения и подтвердить раздельное воспроизведение и восстановление конфигурации.
