## Исходный текст

В сцене 1 после настоящего клика должны заново подниматься все ранее открытые и не закрытые пользователем popup-окна, а затем открываться два новых окна: одно в позиции клика и второе в случайном месте, полностью внутри доступной рабочей области экрана. При двух живых старых окнах после настоящего клика должно оставаться четыре окна.

---

## Функциональные требования

- **Повторный focus старых окон:** При настоящем клике система должна вызвать `focus()` для каждого ранее созданного и не закрытого popup-окна до открытия новых окон.
  - **Пояснение:** Старые popup должны получить пользовательскую активацию раньше новых `window.open()`, чтобы браузер мог поднять их на передний план.
  - **Источник:** "должны заново обретать фокус все уже всплывшие окна"
  - **Acceptance hint:** При двух живых старых окнах вызов `focus()` фиксируется для каждого из них до открытия двух новых окон.

- **Два новых окна:** После поднятия старых окон система должна создать ровно два новых popup с изображениями.
  - **Пояснение:** Первое окно размещается у настоящего клика, второе получает независимую случайную позицию.
  - **Источник:** "открываться два новых (одно в позиции клика и второе в произвольном месте)"
  - **Acceptance hint:** Один настоящий клик создаёт ровно два новых окна с требуемыми типами размещения.

- **Общее количество окон:** После настоящего клика количество живых popup должно равняться количеству ранее открытых и не закрытых окон плюс два.
  - **Пояснение:** Старые окна не должны заменяться новыми или исчезать при завершении preclick-последовательности.
  - **Источник:** "Почему после настоящего клика сейчас отображаются только два всплывающих окна, а не 4?"
  - **Acceptance hint:** Два окна от фейковых кликов плюс два новых окна дают четыре живых окна.

- **Последовательное отображение:** Все старые окна должны быть последовательно подняты на передний план, после чего оба новых окна должны открыться и оставаться открытыми вместе со старыми.
  - **Пояснение:** Операционная система допускает только одно активное окно с keyboard-focus, поэтому требуемый наблюдаемый результат достигается последовательным focus всех старых popup.
  - **Источник:** "все уже всплывшие окна+ открываться два новых"
  - **Acceptance hint:** Старые окна получают новые focus-события, а итоговый набор живых окон не уменьшается.

- **Сохранение закрытых окон:** Окна, которые пользователь закрыл до настоящего клика, не должны открываться повторно и не учитываются в итоговом количестве.
  - **Пояснение:** Повторный focus применяется только к живым popup.
  - **Источник:** Контекст согласованного поведения ранее открытых окон.
  - **Acceptance hint:** Закрытый popup не восстанавливается, живые popup сохраняются и дополняются двумя новыми.

## Нефункциональные требования

- **Границы случайного окна:** Второе новое окно должно полностью находиться внутри доступной рабочей области экрана с учётом внешней рамки браузерного окна.
  - **Пояснение:** Координаты и размер должны ограничиваться значениями `screen.avail*` после определения browser chrome.
  - **Источник:** "в произвольном месте, но полностью в пределах окна"
  - **Acceptance hint:** Левая и верхняя координаты не выходят за начало рабочей области, а правый и нижний внешние края не превышают её границы.

- **Совместимость с popup-политиками:** Повторный focus старых окон должен выполняться непосредственно в обработчике настоящего клика и до новых `window.open()`.
  - **Пояснение:** Это сохраняет пользовательскую активацию для максимально надёжного поднятия popup в Chromium-подобных браузерах.
  - **Источник:** Наблюдаемая проблема с показом только двух новых окон.
  - **Acceptance hint:** Порядок операций подтверждается тестом или инструментированным контроллером.

- **Проверяемость:** Автоматические тесты должны проверять счётчик `N + 2`, повторный focus каждого живого старого окна и допустимые внешние границы случайного окна.
  - **Пояснение:** Проверки только внутреннего счётчика недостаточно для воспроизведённого дефекта.
  - **Источник:** Уточнение ожидаемого наблюдаемого поведения.
  - **Acceptance hint:** Тест падает при открытии новых окон до focus старых или при выходе случайного окна за рабочую область.

- **Изоляция:** Поведение сцен 2 и 3 не должно измениться.
  - **Пояснение:** Исправление относится только к финальному настоящему клику сцены 1.
  - **Источник:** Контекст задачи по сцене 1.
  - **Acceptance hint:** Изменение находится в ветке сцены 1, а общие popup-API сохраняют прежнее поведение по умолчанию.

## Проблемы и замечания, превращённые в требования

- **Старые popup не поднимаются перед новыми:** Сейчас два новых `window.open()` выполняются раньше `revealPreclickWindows()`. Браузер гарантированно показывает новые окна, но старые popup могут не получить повторный focus. Требуемое поведение: сначала поднять каждый живой старый popup, затем открыть два новых и сохранить итоговый набор `N + 2` окон.
  - **Источник:** "сейчас отображаются только два всплывающих окна, а не 4"
  - **Acceptance hint:** При двух живых старых popup после настоящего клика остаются четыре живых окна, а оба старых получают повторный focus.

- **Недостаточная автоматическая проверка:** Текущий smoke-тест проверяет количество зарегистрированных окон, но не подтверждает повторный focus старых popup. Требуемое поведение: тестировать и количество, и focus-события, и границы случайного окна.
  - **Источник:** Диагностика текущей реализации после пользовательского наблюдения.
  - **Acceptance hint:** Регрессия порядка `open → focus` обнаруживается автоматическим тестом.
