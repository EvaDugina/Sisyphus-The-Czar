## Исходный текст

Пользователь запросил UI-задержку запуска parallax в диапазоне `0–1000 мс`, настраиваемый радиус захвата курсором `0–10 vh` и исправление нестабильной работы parallax, в том числе после перезагрузки страницы. Дополнительно явно уточнено: «параллакс должен работать всегда».

## Функциональные требования

- **Задержка запуска parallax:** В категории «Камень» должна быть versioned UI-настройка задержки `0–1000 мс`, шаг `10 мс`, default `0 мс`.
  - **Пояснение:** После входа курсора в активный радиус камень остаётся без parallax-offset до завершения задержки.
  - **Источник:** «добавь задержку при старте параллакса в ms на UI в диапазоне от 0 до 1000 ms».
  - **Acceptance hint:** При `500 мс` offset остаётся нулевым до завершения задержки, затем рассчитывается по актуальной позиции курсора.

- **Управление задержкой:** Выход курсора из радиуса до завершения задержки отменяет таймер; повторный вход запускает полную задержку заново.
  - **Пояснение:** Таймер не должен продолжаться вне активной зоны или переноситься между входами.
  - **Источник:** Approved трактовка старта как каждого нового входа в активный радиус.
  - **Acceptance hint:** Выход на `490 мс` при задержке `500 мс` оставляет offset нулевым; повторный вход требует ещё `500 мс`.

- **Актуальная позиция после задержки:** После завершения задержки parallax должен рассчитываться по последней известной позиции курсора, даже если курсор во время ожидания не двигался.
  - **Пояснение:** Для запуска не должно требоваться дополнительное движение после истечения таймера.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** Курсор остаётся неподвижным внутри зоны, но после timeout камень получает ожидаемый offset.

- **Отмена ожидающего запуска:** Первый успешный захват, нулевые radius/max, перезагрузка страницы и уничтожение runtime должны отменять pending delay.
  - **Пояснение:** Отложенный callback не должен менять камень после смены состояния.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** После любого перечисленного события offset не появляется по старому timeout.

- **Радиус захвата курсором:** В категории «Рука» должна быть versioned UI-настройка `0–10 vh`, шаг `0.1 vh`, default `0 vh`.
  - **Пояснение:** Радиус расширяет доступную мышью область захвата вокруг камня.
  - **Источник:** «добавь радиус курсору в пределах которого будет считаться захват камня (от 0 до 10vh)».
  - **Acceptance hint:** UI показывает допустимый диапазон и сохраняет выбранное значение.

- **Геометрия расширенного захвата:** Основное нажатие должно захватывать камень, если круг заданного радиуса вокруг курсора пересекает прямоугольные визуальные DOM-границы камня.
  - **Пояснение:** Значение `0 vh` сохраняет непосредственный захват по камню; pixel-perfect проверка прозрачности изображения не требуется.
  - **Источник:** Approved трактовка радиуса захвата.
  - **Acceptance hint:** При `5 vh` клик в пределах `5 vh` от границы захватывает камень, за пределами — нет.

- **Область действия радиуса захвата:** Расширенная зона должна работать для первого и последующих игровых захватов, не обходя препятствия, неверную фазу, touch-ввод или неосновную кнопку мыши.
  - **Пояснение:** Радиус меняет hit-test, но не правила доступа к управлению.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** Заблокированный препятствием клик внутри расширенной зоны не активирует физику.

- **Первый расширенный захват:** Успешный захват через расширенную область должен отключить preclick parallax, активировать физику и включить camera-follow так же, как непосредственный клик по камню.
  - **Пояснение:** Первый захват имеет единый lifecycle независимо от точки попадания.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** После расширенного захвата класс parallax снят, offset равен нулю, физика и камера активны.

- **Постоянная работа parallax:** До первого успешного захвата при ненулевых radius/max parallax должен работать после загрузки и повторных reload, при `prefers-reduced-motion`, в обоих режимах руки, после открытия настроек, resize, изменения параметров, выхода/возврата в радиус и завершения delay/return.
  - **Пояснение:** «Всегда» относится к preclick-фазе; после первого успешного захвата сохраняется утверждённое отключение parallax.
  - **Источник:** «проблема: параллакс камня работает не всегда», «иногда параллкс камня перестает работать при перезагрузке страницы», «параллакс должен работать всегда».
  - **Acceptance hint:** Все перечисленные последовательности завершаются ожидаемым ненулевым offset внутри активной зоны.

- **Инициализация после reload:** Каждая загрузка должна создавать новый preclick-цикл с `completed=false`, нулевым offset, активным parallax-классом, восстановленными настройками и без старых timeout/rAF.
  - **Пояснение:** Завершённое или зависшее состояние предыдущего runtime не переносится на новую страницу.
  - **Источник:** «параллкс камня перестает работать при перезагрузке страницы».
  - **Acceptance hint:** Последовательность «загрузка → parallax → reload → parallax» повторяется без потери поведения.

- **Reduced motion:** `prefers-reduced-motion` не должен отключать прямое parallax-смещение; он может делать возврат offset мгновенным.
  - **Пояснение:** Прямой preclick parallax обязан работать всегда, а accessibility-настройка влияет только на плавную return-анимацию.
  - **Источник:** «параллакс должен работать всегда».
  - **Acceptance hint:** При эмуляции reduced motion курсор внутри зоны всё равно создаёт ожидаемый offset.

## Нефункциональные требования

- **Versioned persistence:** Новые параметры должны сохраняться в localStorage, именованных версиях, server templates, room settings и production preset.
  - **Пояснение:** Старые настройки получают defaults `0 мс` и `0 vh` через schema migration.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** Unit-тесты sanitization/migration и browser persistence проходят.

- **Безопасный lifecycle:** Delay timeout и return rAF не должны одновременно управлять offset; все pending callbacks очищаются при смене состояния и dispose.
  - **Пояснение:** Асинхронные состояния не должны оставлять parallax зависшим или самопроизвольно отключённым.
  - **Источник:** Проблема нестабильной работы parallax.
  - **Acceptance hint:** Многократные входы/выходы, reload и изменение настроек не создают поздних offset-обновлений.

- **Невидимый hit-area:** Расширенная область захвата не должна менять layout, визуальный размер камня, accessibility tree или интерактивность UI настроек.
  - **Пояснение:** Hit-test реализуется логически, без дополнительного видимого слоя.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** Bounding box камня до и после изменения радиуса одинаков.

- **Маршрутная совместимость:** Поведение и UI должны совпадать на `/` и `/drafts/`.
  - **Пояснение:** Оба адреса используют одну полноценную реализацию.
  - **Источник:** Текущий контракт продукта POC B.
  - **Acceptance hint:** Draft smoke подтверждает одинаковые controls и runtime-поведение.

## Проблемы и замечания, превращённые в требования

- **Parallax иногда перестаёт работать:** Сейчас прямое смещение может не запускаться или оставаться в неактуальном async-состоянии. Требуемое поведение: до первого успешного захвата parallax не теряет обработчики и всегда возобновляет работу при выполнении настроенных условий.
  - **Источник:** «проблема: параллакс камня работает не всегда».
  - **Acceptance hint:** Регрессионные сценарии delay, return, settings, resize и hand modes стабильно проходят.

- **Parallax пропадает после reload:** Сейчас после перезагрузки страницы parallax иногда не работает. Требуемое поведение: reload полностью переинициализирует preclick-state и не наследует `completed`, таймеры или offset предыдущего runtime.
  - **Источник:** «Еще иногда параллкс камня перестает работать при перезагрузке страницы!!».
  - **Acceptance hint:** Повторные reload с сохранёнными настройками не приводят к пропуску parallax.

- **Reduced motion отключает прямой parallax:** Сейчас `prefers-reduced-motion` обнуляет offset. Требуемое поведение: прямой parallax работает, а reduced motion может отключить только плавность возврата.
  - **Источник:** «параллакс должен работать всегда».
  - **Acceptance hint:** Smoke с reduced motion получает ненулевой offset внутри зоны.

- **Конфликт асинхронных состояний:** Сейчас delay отсутствует, а return rAF может конкурировать с будущим запуском. Требуемое поведение: в каждый момент offset контролирует только одно актуальное состояние.
  - **Источник:** Approved черновик требований.
  - **Acceptance hint:** После re-entry return отменён до применения прямого parallax; после dispose callbacks не выполняются.

- Видимая отладочная зона захвата не добавляется.
- Pixel-perfect hit-test по непрозрачным пикселям изображения камня не добавляется.
