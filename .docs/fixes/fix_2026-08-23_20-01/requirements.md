## Функциональные требования

- **Последовательный цикл картин:** В режиме «Случайно циклично» сцена 1 должна показывать картины строго в порядке `01 → 02 → 03 → 01…`.
  - **Пояснение:** Режим использует стабильный каталог картин вместо перемешивания оставшихся вариантов.
  - **Источник:** «начинай с 01, затем 02, затем 03, затем снова 01».
  - **Acceptance hint:** Первые шесть срабатываний дают `01, 02, 03, 01, 02, 03`.

- **Сброс цикла:** Новый runtime сцены, перезагрузка, кнопка «Начать сначала» и повторный вход в режим «Случайно циклично» должны начинать цикл с `01`.
  - **Пояснение:** Это утверждённое определение начала нового цикла.
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** После каждого перечисленного сброса первой открывается `01`.

- **Изоляция режимов выбора:** Режимы независимого случайного выбора и одной выбранной картины должны сохранить текущее поведение.
  - **Пояснение:** Правка касается только режима «Случайно циклично».
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** `random` допускает повторы, `single` всегда возвращает выбранную картину.

- **Полный Git-снимок настроек:** Нажатие кнопки сохранения на сценах 1, 2 и 3 должно сохранять полный набор настроек текущей сцены в JSON-файл репозитория, отслеживаемый Git.
  - **Пояснение:** В снимок входят все настройки, представленные в UI текущей сцены, включая параметры, ранее считавшиеся локальными.
  - **Источник:** «Все настройки после нажатия на кнопки сохранить должны сохраняться в файлы, синхронизируемые через git».
  - **Acceptance hint:** После изменения любого контрола и сохранения соответствующее значение присутствует в Git-tracked JSON.

- **Разделение сцен:** Сохранение настроек одной сцены не должно перезаписывать сохранённые версии других сцен.
  - **Пояснение:** Допускается общий каталог с явным namespace сцены.
  - **Источник:** «Сцена 1, 2, 3».
  - **Acceptance hint:** После последовательного сохранения сцен 1–3 каталог содержит три независимых scene-namespaced снимка.

- **Восстановление из файлов:** После перезапуска контейнера, клонирования репозитория или `git pull` сохранённые версии должны загружаться из файлов и быть доступны соответствующей сцене.
  - **Пояснение:** Git-tracked JSON является переносимым источником сохранённых настроек.
  - **Источник:** «синхронизируемые через git».
  - **Acceptance hint:** Новый процесс сервера загружает сохранённую версию из файла без browser-local данных.

- **Синхронизация production preset:** Если сохраняемая версия назначена production preset, полный актуальный снимок должен также сохраняться в отслеживаемый файл production-конфигурации.
  - **Пояснение:** Production baseline не должен расходиться с сохранённой версией.
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** Сохранение активной production-версии обновляет `config/production-preset.json`.

- **Достоверный результат сохранения:** UI должен показывать успех только после фактической записи файла; при ошибке записи должен отображаться отказ, а черновик не должен считаться сохранённым.
  - **Пояснение:** Пользователь не должен получать ложное подтверждение сохранения.
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** Искусственная ошибка записи оставляет dirty-state и показывает ошибку.

## Нефункциональные требования

- **Атомарная запись:** JSON должен записываться через временный файл с последующей заменой целевого файла.
  - **Пояснение:** Частичная запись не должна повреждать Git-конфигурацию.
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** При ошибке commit старый документ остаётся валидным.

- **Git-читаемость:** Файлы должны оставаться валидными, форматированными и пригодными для обычного `git diff`.
  - **Пояснение:** Сохранённые изменения проверяются и синхронизируются стандартным Git workflow.
  - **Источник:** «синхронизируемые через git».
  - **Acceptance hint:** `git diff` показывает только содержательные изменения JSON.

- **Сохранность соседних данных:** Сохранение не должно удалять версии других сцен или чужие записи каталога.
  - **Пояснение:** Общий store обслуживает несколько scene namespaces и пользователей.
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** Store-тест подтверждает сохранение остальных entries.

- **Безопасный состав:** Конфигурация не должна содержать секреты, session ID или текущее состояние физики, не являющееся настройками.
  - **Пояснение:** В Git попадают только значения конфигурационных контролов.
  - **Источник:** Согласованный черновик требований.
  - **Acceptance hint:** Снимок ограничен allowlist всех UI-настроек сцены.

- **Детерминированность:** Последовательный режим картин не должен зависеть от `Math.random`.
  - **Пояснение:** Одинаковые действия должны давать одинаковый порядок.
  - **Источник:** «01, затем 02, затем 03».
  - **Acceptance hint:** Разные random-функции не меняют результат последовательного режима.

## Проблемы и замечания, превращённые в требования

- **Непредсказуемый цикл:** Сейчас `shuffle` случайно выбирает следующую картину из оставшихся. Требуемое поведение: фиксированный порядок `01 → 02 → 03 → 01`.
  - **Источник:** «В режиме \"случайно циклично\" начинай с 01, затем 02, затем 03, затем снова 01».
  - **Acceptance hint:** Unit-тест проверяет два полных последовательных цикла.

- **Неполное файловое сохранение:** Сейчас параметры со `scope: local` исключаются из общего шаблона. Требуемое поведение: кнопка сохраняет полный allowlisted снимок UI-настроек текущей сцены.
  - **Источник:** «Все настройки ... должны сохраняться в файлы».
  - **Acceptance hint:** Тест сохраняет и восстанавливает каждый ранее локальный параметр.

- Переименование режима «Случайно циклично» не требуется.
- Поведение режимов «Случайная картинка» и «Одна картинка» не меняется.
- Положение камня, прогресс сцены и пользовательская сессия не сохраняются в Git.
