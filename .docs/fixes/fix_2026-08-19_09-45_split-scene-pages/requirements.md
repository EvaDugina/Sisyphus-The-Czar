## Исходный текст

Три части текущего игрового процесса нужно разделить на три самостоятельные страницы и три файла. Параметры каждой сцены должны находиться прямо на её странице, принадлежать только этой сцене и не иметь общих значений с другими сценами. Сцена 1 завершается при первом настоящем нажатии руки на камень после всех фейковых кликов. Сцена 2 начинается с неподвижного камня в центре страницы, включает физику по первому клику по камню без освобождения из руки и завершается при касании отпечатка на вершине. Сцена 3 начинается на вершине с камнем в руке и завершается после помещения камня в отпечаток, падения камня, спуска камеры вслед за ним и начала дождя. После завершения страница остаётся в финальном состоянии. На каждой странице нужны кнопка «Начать сначала» и расположенная под ней ссылка на следующую сцену. Работа выполняется в отдельной ветке.

Принятая при апруве трактовка последовательности ссылок: сцена 1 → сцена 2 → сцена 3 → сцена 1.

## Функциональные требования

- **Три независимые страницы:** Система должна предоставлять отдельную страницу с прямым URL для каждой из трёх сцен.
  - **Пояснение:** Одновременно должна отображаться и исполняться только одна сцена.
  - **Источник:** «Разделить 3 сцены на 3 разные страницы».
  - **Acceptance hint:** Прямое открытие или перезагрузка URL запускает только соответствующую сцену с её начального состояния.

- **Одна сцена в одном файле:** Каждая сцена должна быть определена в отдельном корневом файле; один файл не должен содержать реализации нескольких сцен.
  - **Пояснение:** Переиспользуемые визуальные примитивы могут оставаться отдельными компонентами, но композиция и жизненный цикл сцен должны быть раздельными.
  - **Источник:** «В одном файле одна сцена».
  - **Acceptance hint:** В проекте существуют три самостоятельных корневых модуля сцен.

- **Параметры на странице сцены:** На каждой странице должен находиться UI с параметрами соответствующей сцены.
  - **Пояснение:** Для настройки пользователь не должен переходить на отдельную страницу.
  - **Источник:** «Параметры на UI для каждой сцены верни на UI. Не выноси параметры на отдельную страницу!»
  - **Acceptance hint:** Параметры доступны на странице рядом со сценой; отдельная страница `/settings` не используется в основном сценарии.

- **Изоляция параметров:** Каждый параметр должен принадлежать ровно одной сцене и использоваться только её интерфейсом и логикой.
  - **Пояснение:** Одинаковые по смыслу параметры разных сцен должны иметь независимые экземпляры и значения.
  - **Источник:** «У каждой сцены свои параметры, которые используются только в рамках неё. Общих параметров нет».
  - **Acceptance hint:** Изменение параметра одной сцены не меняет состояние или поведение остальных сцен; общей области параметров нет.

- **Сохранение финального состояния:** После выполнения финального события страница должна оставаться в достигнутом финальном состоянии без автоматического перехода.
  - **Пояснение:** Следующая сцена открывается только по явному действию пользователя.
  - **Источник:** «Оставаться в финальном положении».
  - **Acceptance hint:** Завершение сцены не меняет URL и не запускает другую сцену.

- **Перезапуск сцены:** На каждой странице должна присутствовать кнопка «Начать сначала», сбрасывающая только текущую сцену к её начальному состоянию.
  - **Пояснение:** Способ внутреннего сброса может быть реализационным, но пользователь должен получать чистый повторный запуск той же сцены.
  - **Источник:** «На каждой странице должна быть кнопка \"Начать сначала\"».
  - **Acceptance hint:** После нажатия восстановлены начальные позиции и состояние сцены, а её прохождение снова доступно.

- **Ссылка на следующую сцену:** Под кнопкой «Начать сначала» должна располагаться кликабельная ссылка на следующую сцену.
  - **Пояснение:** Используется циклическая последовательность: 1 → 2, 2 → 3, 3 → 1.
  - **Источник:** «Под кнопкой начать сначала url на следующую сцену» и апрув актуального черновика.
  - **Acceptance hint:** Ссылки ведут на корректные прямые URL и не срабатывают автоматически.

- **Начальное состояние сцены 1:** Сцена 1 должна сохранять этап фейковых кликов перед первым настоящим нажатием руки на камень.
  - **Пояснение:** Настоящее нажатие не может завершить сцену до окончания предусмотренной последовательности фейковых кликов.
  - **Источник:** «после всех фейковых кликов».
  - **Acceptance hint:** До выполнения нужного количества фейковых кликов сцена не переходит в финальное состояние.

- **Завершение сцены 1:** Сцена 1 должна завершаться при первом настоящем нажатии руки на камень после выполнения всех фейковых кликов.
  - **Пояснение:** Граница сцены — само нажатие, а не отпускание камня или последующее движение.
  - **Источник:** «Сцена 1 заканчивается когда рука нажимает на камень первый раз после всех фейковых кликов».
  - **Acceptance hint:** После первого допустимого нажатия дальнейшая игровая логика сцены 1 не развивается, а страница сохраняет финальное положение.

- **Начальное состояние сцены 2:** При открытии сцены 2 камень должен неподвижно висеть в середине видимой области страницы.
  - **Пояснение:** До первого клика физическое падение не начинается.
  - **Источник:** «Сцена 2 начинается с того, как камень висит в середине страницы».
  - **Acceptance hint:** Камень до взаимодействия неподвижен и расположен в центре viewport.

- **Первое взаимодействие сцены 2:** При первом клике по камню должна включаться его физическая симуляция, но камень должен оставаться захваченным рукой.
  - **Пояснение:** Включение физики не должно автоматически освобождать или ронять камень.
  - **Источник:** «По первому клику он обретает физику, но остается в руке» и апрув трактовки «клик непосредственно по камню».
  - **Acceptance hint:** После первого клика камень реагирует на физику и движение руки, сохраняя состояние захвата.

- **Завершение сцены 2:** Сцена 2 должна завершаться при первом касании камнем его отпечатка на верхушке.
  - **Пояснение:** Удержание в отпечатке, финальное падение и дождь не входят в сцену 2.
  - **Источник:** «Сцена 2 заканчивается, как только камень касается своего следа на верхушке».
  - **Acceptance hint:** Контакт камня с зоной отпечатка переводит сцену в сохраняемое финальное состояние.

- **Начальное состояние сцены 3:** При открытии сцены 3 камера должна находиться на верхушке, а камень — быть захваченным рукой рядом с местом установки.
  - **Пояснение:** Подъём по пути и доставка камня на вершину в этой сцене не воспроизводятся.
  - **Источник:** «камера уже на верхушке, камень в руке и осталось только поместить камень в свой след».
  - **Acceptance hint:** Пользователь сразу может поместить удерживаемый камень в отпечаток.

- **Финальная последовательность сцены 3:** После помещения камня в отпечаток должны произойти падение камня вниз, спуск камеры/игрока вслед за камнем и начало дождя.
  - **Пояснение:** Все три наблюдаемых события входят в обязательную финальную последовательность.
  - **Источник:** «камень падает вниз и игрок опускается вниз за камнем и идет дождь».
  - **Acceptance hint:** В финальной последовательности наблюдаются падение камня, спуск камеры и дождь.

- **Завершение сцены 3:** Сцена 3 должна считаться завершённой только после выполнения всей финальной последовательности.
  - **Пояснение:** Установка камня или начало падения сами по себе ещё не завершают сцену.
  - **Источник:** «Сцена 3 заканчивается, когда камень падает вниз и игрок опускается вниз за камнем и идет дождь».
  - **Acceptance hint:** После завершения страница остаётся в нижнем финальном положении с дождём.

## Нефункциональные требования

- **Изоляция исполнения:** Неактивные сцены не должны монтироваться, запускать физику, таймеры, обработчики, аудио или фоновые эффекты.
  - **Пояснение:** Раздельные страницы должны иметь независимые жизненные циклы.
  - **Источник:** Требования отдельных страниц и файлов.
  - **Acceptance hint:** На каждой странице существует runtime только текущей сцены, корректно освобождающий ресурсы при уходе или перезапуске.

- **Изоляция данных:** Сохранение, загрузка и применение параметров одной сцены не должны затрагивать параметры остальных сцен.
  - **Пояснение:** Общие настройки и общая область значений запрещены.
  - **Источник:** «Общих параметров нет».
  - **Acceptance hint:** Независимые значения сохраняются и восстанавливаются без межсценовых изменений.

- **Прямой запуск:** Каждая страница должна корректно работать при прямом открытии URL и после перезагрузки браузера.
  - **Пояснение:** Сцена не должна зависеть от предварительного прохождения другой страницы.
  - **Источник:** Требование трёх отдельных страниц.
  - **Acceptance hint:** Все три прямых URL проходят smoke-проверку.

- **Предсказуемый перезапуск:** Повторные нажатия «Начать сначала» должны создавать одинаковое чистое начальное состояние без накопления обработчиков и эффектов.
  - **Пояснение:** Перезапуск не должен ухудшать поведение сцены.
  - **Источник:** Требование кнопки «Начать сначала».
  - **Acceptance hint:** Несколько последовательных перезапусков не дублируют события, аудио, таймеры или анимации.

- **Регрессионная проверяемость POC B:** Автоматические проверки должны покрывать страницы, изоляцию параметров, начальные состояния, финальные события, перезапуск и навигационные ссылки.
  - **Пояснение:** Критический демонстрационный путь POC B должен оставаться воспроизводимым.
  - **Источник:** Текущая стадия проекта POC B и approved требования.
  - **Acceptance hint:** Релевантные unit/smoke-тесты, lint и production build проходят успешно.

- **Актуальность документации:** Изменившиеся продуктовые сценарии и архитектура должны быть отражены в `.docs/product.md`, `.docs/technical.md` и `.docs/demo.md`.
  - **Пояснение:** Изменение затрагивает основной демонстрационный путь и устройство frontend.
  - **Источник:** Стандарт проекта POC B для крупных изменений.
  - **Acceptance hint:** Три документа описывают самостоятельные страницы, их границы и способ запуска.

## Проблемы и замечания, превращённые в требования

- **Монолитная композиция сцен:** Сейчас сцены исполняются внутри общей страницы и общего runtime. Требуемое поведение: три независимо запускаемых страницы и жизненных цикла.
  - **Источник:** «Разделить 3 сцены на 3 разные страницы».
  - **Acceptance hint:** На каждой странице запускается только соответствующая сцена.

- **Отдельная страница параметров:** Сейчас параметры вынесены на `/settings`. Требуемое поведение: параметры располагаются непосредственно на соответствующих страницах сцен.
  - **Источник:** «Не выноси параметры на отдельную страницу!»
  - **Acceptance hint:** Для изменения параметра не требуется навигация со страницы сцены.

- **Общие параметры:** Сейчас часть настроек используется несколькими сценами. Требуемое поведение: общих значений и общего состояния параметров нет.
  - **Источник:** «Общих параметров нет».
  - **Acceptance hint:** Каждый параметр имеет единственного владельца-сцену.

- **Смешанные границы игрового процесса:** Сейчас единый runtime охватывает несколько этапов. Требуемое поведение: каждая страница ограничена собственным начальным и финальным событием.
  - **Источник:** Описанные пользователем границы сцен 1, 2 и 3.
  - **Acceptance hint:** Ни одна сцена не продолжает выполнять этап следующей сцены после своей точки завершения.

- **Неявный повторный запуск:** Сейчас нет общего утверждённого способа повторить самостоятельную сцену. Требуемое поведение: каждая страница предоставляет кнопку «Начать сначала».
  - **Источник:** «На каждой странице должна быть кнопка \"Начать сначала\"».
  - **Acceptance hint:** Кнопка доступна на каждой из трёх страниц и сбрасывает только текущую сцену.

## Не включено / требует уточнения

- Полный визуальный редизайн сцен и панели параметров не входит в fix.
- Состав пользовательских параметров не меняется сверх их распределения, независимого хранения и привязки к конкретным сценам.
- Автоматические переходы между сценами не входят в fix.
- Инфраструктура, деплой и серверные функции не изменяются без технической необходимости для маршрутизации страниц и изоляции параметров.
