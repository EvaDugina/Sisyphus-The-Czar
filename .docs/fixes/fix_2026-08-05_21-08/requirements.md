## Исходный текст

1. После первого клика по камню, когда включается физика, анимированно уменьшать камень до 10% ширины viewport (10vw) и вывести этот параметр в UI.
2. Дать в UI возможность настраивать базовый цвет и градиент фона отдельно для светлой и тёмной темы.
3. Согласованные уточнения: анимация 300 мс `ease-out`; геометрия градиента остаётся фиксированной: `180deg`, точки `0% / 48% / 100%`.

## Функциональные требования

- **Размер после запуска физики:** Система должна при первом клике, запускающем физическую фазу, анимированно изменять ширину камня до настраиваемого значения, по умолчанию `10vw`.
  - **Пояснение:** Анимация срабатывает один раз при переходе из вводной фазы в физическую; после перезапуска сценария может сработать снова.
  - **Источник:** "После первого клика по камню, когда включается физика, уменьшай камень до 10%".
  - **Acceptance hint:** После завершения перехода визуальная ширина камня равна 10% ширины viewport; повторные клики не запускают новое уменьшение.

- **Настройка размера в UI:** Система должна предоставить в группе размера камня числовое поле «Размер после запуска физики, %» со значением `10` по умолчанию и диапазоном, согласованным с существующими настройками размера.
  - **Пояснение:** Значение задаёт целевую ширину в единицах `vw`.
  - **Источник:** "дай этот параметр на UI".
  - **Acceptance hint:** Изменение поля изменяет целевой размер при следующем запуске физики.

- **Анимация размера:** Система должна анимировать изменение ширины за `300 мс` с функцией `ease-out`, не изменяя физическую позицию камня.
  - **Пояснение:** Переход должен оставаться визуальным эффектом и не конфликтовать с движением.
  - **Источник:** "Анимированно"; approved default `300 мс ease-out`.
  - **Acceptance hint:** CSS-переход или эквивалент длится 300 мс и не сбрасывает координаты камня.

- **Градиент светлой темы:** Система должна предоставить в UI отдельные цветовые параметры базового/верхнего, промежуточного и нижнего цвета фона светлой темы.
  - **Пояснение:** Значения по умолчанию соответствуют текущему светлому градиенту.
  - **Источник:** "Дай возможность на UI изменить цвет фона для светлой и темной темы".
  - **Acceptance hint:** При светлой теме сцена использует три настроенных цвета.

- **Градиент тёмной темы:** Система должна предоставить в UI отдельные цветовые параметры базового/верхнего, промежуточного и нижнего цвета фона тёмной темы.
  - **Пояснение:** Значения по умолчанию соответствуют текущему тёмному градиенту.
  - **Источник:** "Базовым цветом — дай возможность настраивать градиент".
  - **Acceptance hint:** При тёмной теме сцена использует три настроенных цвета.

- **Применение темы:** Система должна применять градиент фактически активной темы; в режиме `Авто` градиент меняется вместе с разрешённой темой.
  - **Пояснение:** Геометрия остаётся текущей: `linear-gradient(180deg, top 0%, middle 48%, bottom 100%)`.
  - **Источник:** approved clarification about base colors and configurable gradient.
  - **Acceptance hint:** Переключение `light`, `dark` и `auto` выбирает корректный набор цветов.

- **Хранение настроек:** Система должна сохранять, синхронизировать и сбрасывать новые параметры так же, как остальные настройки комнаты.
  - **Пояснение:** Параметры должны участвовать в текущем механизме room settings, presets и reset.
  - **Источник:** "дай этот параметр на UI".
  - **Acceptance hint:** Параметры сохраняются и передаются теми же путями, что и другие room settings.

## Нефункциональные требования

- **Плавность:** Анимация уменьшения не должна конфликтовать с физическим движением.
  - **Пояснение:** Изменяется визуальный масштаб, а не канонические координаты.
  - **Источник:** "Анимированно".
  - **Acceptance hint:** Во время перехода камень продолжает движение без скачка координат.

- **Валидация:** Система должна нормализовать некорректные размеры и цвета к безопасным fallback-значениям.
  - **Пояснение:** Невалидные room settings не должны ломать рендеринг.
  - **Источник:** approved requirement draft.
  - **Acceptance hint:** Серверная и клиентская санитизация возвращает допустимые значения.

- **Обратная совместимость:** Система должна использовать утверждённые значения по умолчанию для старых сессий, пресетов и локальных настроек, где новых ключей нет.
  - **Пояснение:** Обновление не требует ручной миграции данных.
  - **Источник:** approved requirement draft.
  - **Acceptance hint:** Настройки без новых ключей санитизируются к текущему визуальному поведению плюс `10vw` для нового размера.

- **Согласованность UI:** Система должна использовать стандартные цветовые и числовые контролы текущей панели настроек.
  - **Пояснение:** Новые поля не должны выглядеть чужеродными.
  - **Источник:** "на UI".
  - **Acceptance hint:** Контролы имеют подписи, output-значения и доступную клавиатурную форму.

## Проблемы и замечания, превращённые в требования

- **Отдельный размер после активации:** Сейчас после запуска физики нет отдельного анимированного целевого размера. Требуемое поведение: целевой размер задаётся в UI и применяется один раз за 300 мс при первом запуске физики.
  - **Источник:** "уменьшай камень до 10% + дай этот параметр на UI".
  - **Acceptance hint:** Поведение покрыто unit/UI и smoke-проверкой.

- **Ненастраиваемый фон:** Сейчас цвета фонового градиента жёстко заданы в CSS. Требуемое поведение: для каждой темы в UI доступны три цвета градиента.
  - **Источник:** "дай возможность на UI изменить цвет фона".
  - **Acceptance hint:** Изменение каждого color input видно в соответствующей теме и переживает сохранение/повторную загрузку.
