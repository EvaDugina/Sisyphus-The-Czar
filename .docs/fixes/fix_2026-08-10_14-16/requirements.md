## Исходный текст

1. Добавить на UI три режима отображения руки: показывать всегда, показывать по hover, не показывать.
2. Добавить на UI настройку задержки между кликом и сменой изображения руки в диапазоне от 0 до 1000 мс.

---

## Функциональные требования

- **Режим отображения руки:** UI должен предоставлять выбор одного из трёх взаимоисключающих режимов.
  - **Показывать всегда:** изображение руки постоянно видно.
  - **Показывать по hover:** рука скрыта и появляется при наведении указателя на существующую активную область взаимодействия с рукой или камнем; после ухода указателя снова скрывается.
  - **Не показывать:** рука не отображается при наведении, клике и в состоянии покоя.
  - **Пояснение:** изменение режима должно применяться сразу и не требовать перезагрузки страницы.
  - **Источник:** "Добавь на UI для руки три состояния на выбор: показывать всегда, показывать по hover, не показывать".
  - **Acceptance hint:** каждый режим выбирается отдельно и визуально соответствует описанному поведению.

- **Задержка смены изображения руки:** UI должен позволять задавать задержку между кликом и вызванной им сменой изображения руки.
  - **Пояснение:** диапазон составляет от `0` до `1000` мс включительно; `0` означает смену без дополнительной задержки. Текущее числовое значение должно быть видно пользователю. Настройка применяется ко всем сменам изображения руки, инициированным кликом.
  - **Источник:** "Добавь на UI задержку между сменой изображений рук при клике в ms от 0 до 1000ms".
  - **Acceptance hint:** при `0` мс изображение меняется сразу, при `1000` мс — приблизительно через одну секунду после клика.

- **Сохранение настроек:** выбранный режим видимости руки и задержка должны храниться и передаваться теми же механизмами, что и остальные настройки приложения.
  - **Пояснение:** новые параметры должны поддерживаться текущими UI-, room-, template- и production-preset-потоками настроек, где они применимы.
  - **Источник:** настройки запрошены как элементы существующего UI приложения.
  - **Acceptance hint:** после сохранения и восстановления настроек оба значения воспроизводятся без потери.

## Нефункциональные требования

- **Валидация задержки:** система не должна принимать значение меньше `0` или больше `1000` мс.
  - **Пояснение:** некорректное входное значение должно приводиться к допустимому диапазону тем же способом, что и остальные числовые настройки.
  - **Источник:** "от 0 до 1000ms".
  - **Acceptance hint:** граничные значения `0` и `1000` принимаются, выход за границы не сохраняется как рабочее значение.

- **Явные единицы измерения:** возле настройки должно быть указано, что задержка задаётся в миллисекундах.
  - **Пояснение:** пользователь должен однозначно понимать масштаб задаваемого значения.
  - **Источник:** "в ms".
  - **Acceptance hint:** UI отображает единицу `мс` или эквивалентную понятную подпись.

- **Изоляция поведения:** переключение режима руки не должно изменять остальные настройки или логику взаимодействия с камнем.
  - **Пояснение:** новая настройка управляет только видимостью руки.
  - **Источник:** область требования ограничена отображением руки.
  - **Acceptance hint:** клики и физика камня продолжают работать во всех трёх режимах.
