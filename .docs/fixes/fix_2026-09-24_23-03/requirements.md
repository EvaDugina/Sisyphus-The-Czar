## Функциональные требования

- **Три обязательных hover-отскока:** первые три допустимых входа руки в радиус камня в сцене 1 должны всегда вызывать отскок.
  - **Пояснение:** пользователь должен трижды получить гарантированную реакцию камня до первого подпускания.
  - **Источник:** «до первого подпускания должно быть 3 отскока».
  - **Acceptance hint:** при любом значении вероятности несрабатывания первые три входа после полного выхода из радиуса запускают hop.

- **Первое гарантированное подпускание:** четвёртый допустимый вход руки в радиус должен гарантированно оставить камень на месте.
  - **Пояснение:** первое подпускание следует строго после трёх выполненных hover-отскоков.
  - **Источник:** согласованный черновик требований.
  - **Acceptance hint:** четвёртый вход не меняет позицию камня, не запускает звук и не создаёт эхо-след.

- **Вероятность последующих hover:** начиная с пятого допустимого входа каждое сближение должно независимо подпускать руку с вероятностью `10%` и вызывать отскок с вероятностью `90%`.
  - **Пояснение:** после первого гарантированного подпускания больше нет специальных правил для номера попытки.
  - **Источник:** «для остальных hover вероятность подпускания 10%».
  - **Acceptance hint:** детерминированная случайная выборка ниже `0.1` пропускает hop, выборка `0.1` и выше запускает hop.

- **Повторный вход:** новое решение должно приниматься только после полного выхода руки из радиуса и повторного входа.
  - **Пояснение:** движение внутри радиуса не создаёт дополнительных попыток.
  - **Источник:** сохранение текущего hover-контракта сцены 1.
  - **Acceptance hint:** несколько pointermove внутри радиуса не меняют счётчики и не запускают повторную проверку.

- **Изоляция кликовых сценариев:** активационный клик режима «клик», два фейковых клика и настоящий завершающий клик должны сохранить текущее поведение.
  - **Пояснение:** новая последовательность относится только к автоматическим hover-входам.
  - **Источник:** согласованный черновик требований.
  - **Acceptance hint:** кликовые hop не расходуют и не изменяют состояние первого гарантированного hover-подпускания.

  - **Источник:** согласованный черновик требований.
  - **Acceptance hint:** тесты отдельно подтверждают три обязательных hop, первое гарантированное подпускание и порог `10%` последующих попыток.
