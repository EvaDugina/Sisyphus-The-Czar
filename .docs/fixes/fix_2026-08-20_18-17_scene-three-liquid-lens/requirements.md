## Исходный текст

Пользователь запросил изменения Сцены 3: после первого попадания в область следа камень должен притягиваться к центру, вставать на место и оставаться там до реального scroll вниз; большая рука больше не отображается, вместо неё используются курсоры из `assets/cursor`. Интерактивная деформация камня уточнена как эффект оптической жидкой линзы. В UI должен быть доступен выбор одного из пяти эффектов с настройкой параметров. Один из вариантов должен воспроизводить поведение эффекта фотографий `.tn-atom` на `https://brandon-mercer.com/` с его параметрами по умолчанию. Все эффекты должны полностью восстанавливать исходное изображение `rock-03`.

## Функциональные требования

- **Притягивание камня к следу:** при первом попадании камня в активную область следа система должна плавно притянуть его к центру области и установить в предусмотренное положение.
  - **Пояснение:** пользователь завершает физическое размещение одним попаданием в область, без точного ручного позиционирования.
  - **Источник:** «После первого попадания камня в область следа камень притягивается к центру следа, встает на своем место».
  - **Acceptance hint:** после первого пересечения камень самостоятельно достигает центра следа.

- **Фиксация камня:** установленный в след камень должен оставаться неподвижным и не реагировать на физику, указатель или автоматические таймеры до разрешающего действия пользователя.
  - **Пояснение:** положение камня сохраняется неограниченно долго.
  - **Источник:** «пока пользователь не сделает scroll вниз он находится на этом месте».
  - **Acceptance hint:** ожидание и перемещение указателя не освобождают камень.

- **Разблокировка по пользовательскому scroll:** продолжение Сцены 3 должно запускаться только после реального пользовательского scroll вниз, совершённого после фиксации камня.
  - **Пояснение:** системный или программный scroll и события до фиксации камня не должны засчитываться.
  - **Источник:** «пока пользователь не сделает scroll вниз».
  - **Acceptance hint:** первый scroll вниз после фиксации освобождает сценарий; без него продолжения нет.

- **Удаление визуальной руки:** существующее крупное изображение руки не должно отображаться в Сцене 3.
  - **Источник:** «Рука уже не отображается».
  - **Acceptance hint:** в DOM и рендере Сцены 3 отсутствует видимый спрайт большой руки.

- **Курсоры взаимодействия:** в Сцене 3 должны использоваться `assets/cursor/handopen.svg` для состояния готовности и `assets/cursor/handgrabbing.svg` для активного удержания `pointer down`.
  - **Источник:** «Вместо руки отображается курсоры из ... assets/cursor».
  - **Acceptance hint:** курсор меняется между состояниями open/grabbing на активной области камня.

- **Выбор эффекта:** UI настроек Сцены 3 должен предоставлять взаимоисключающий выбор одного из пяти эффектов: `Brandon Mercer Flowmap`, `Liquid Bulge`, `Vortex Lens`, `Pinch Tunnel`, `Ripple Glass`.
  - **Источник:** «Добавь в итоговые требования выбор на UI одного из всех 5 функций».
  - **Acceptance hint:** одновременно активен ровно один эффект; выбранное значение явно видно в UI.

- **Эффект по умолчанию:** при первом запуске должен быть выбран `Brandon Mercer Flowmap`.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** новая сессия запускается с выбранным первым пресетом.

- **Brandon Mercer Flowmap:** первый вариант должен самостоятельно воспроизводить flow-map-деформацию фотографий `.tn-atom` на `https://brandon-mercer.com/` со следующими значениями по умолчанию: WebGL canvas, flow-map `512 × 512`, `falloff = 0.3`, `alpha = 1.0`, `dissipation = 0.96`, коэффициент UV-смещения `0.49`, `DPR = 2`, aspect correction, скорость указателя относительно времени между событиями и интерполяция скорости `0.15` при движении / `0.10` при остановке.
  - **Пояснение:** вариант должен повторять исходную динамику, а не только иметь похожее название.
  - **Источник:** «Один из 5 сделай точь в точь как на сайте brandon mercer (параметры по умолчанию как на сайте)».
  - **Acceptance hint:** пресет использует указанные параметры и визуально повторяет направление, инерцию, локальный след и затухание референса.

- **Активация Brandon Mercer:** исходный пресет должен реагировать на движение mouse/touch без обязательного `pointer down` и плавно затухать после прекращения движения.
  - **Источник:** проанализированное поведение референсного сайта и утверждённый черновик.
  - **Acceptance hint:** наведение и движение создают деформацию; простой указателя запускает восстановление.

- **Настройки эффекта:** UI должен позволять изменять радиус воздействия, силу деформации, мягкость границы, дополнительное закручивание, длину/устойчивость следа, скорость восстановления и способ активации (`Наведение` или `Удержание pointer down`).
  - **Источник:** «с разными конфигурируемыми параметрами», «Дай контроль не только восстановления но и радиуса воздействия».
  - **Acceptance hint:** изменение любого параметра применяется к активному эффекту сразу, без перезапуска сцены.

- **Отображение исходных параметров Brandon Mercer:** при выборе первого пресета UI должен отображать эквиваленты исходных настроек: радиус `falloff = 0.3`, сила UV-смещения `0.49`, мягкость `alpha = 1.0`, дополнительное закручивание `0°`, след с интерполяцией `0.15 / 0.10`, восстановление `dissipation = 0.96` и активацию `Наведение`.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** сброс первого пресета возвращает перечисленные значения.

- **Переключение и сброс:** перед применением другого эффекта текущая деформация должна полностью сбрасываться; UI должен позволять восстановить значения по умолчанию выбранного пресета.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** новый пресет начинается с недеформированного камня и собственных настроек.

- **Локальная область воздействия:** каждый эффект должен деформировать изображение локально вокруг указателя в заданном радиусе.
  - **Источник:** референсный скриншот и запрос контроля радиуса.
  - **Acceptance hint:** пиксели за пределами радиуса остаются визуально неизменными.

- **Полное восстановление:** после `pointer leave`, `pointer up` или прекращения движения — в зависимости от режима активации — изображение должно плавно и полностью возвращаться к исходной текстуре `rock-03`.
  - **Источник:** «Не восстанавливаются обратно!», утверждённый итоговый черновик.
  - **Acceptance hint:** после завершения восстановления отсутствует видимый или накопленный остаточный след.

- **Гарантированное завершение восстановления:** при снижении величины деформации ниже незаметного порога система должна обнулить внутреннее состояние эффекта и отрисовать исходную текстуру.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** повторные взаимодействия не накапливают необратимую деформацию.

## Нефункциональные требования

- **Визуальная эквивалентность референсу:** `Brandon Mercer Flowmap` должен повторять характер движения, радиус, инерцию, след и затухание референсного эффекта; различия из-за формы и прозрачности `rock-03` допустимы.
  - **Источник:** «точь в точь как на сайте brandon mercer».
  - **Acceptance hint:** визуальное сравнение на одинаковой траектории указателя не выявляет принципиальных различий в динамике эффекта.

- **Неизменяемый оригинал:** восстановление и переключение должны опираться на неизменённую исходную текстуру, а не на накопленный результат предыдущих кадров.
  - **Источник:** требование полного восстановления.
  - **Acceptance hint:** после серии взаимодействий восстановленный результат совпадает с исходным изображением.

- **Корректные пропорции:** canvas и линза должны учитывать размеры, aspect ratio и прозрачность `rock-03` без растягивания исходника.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** форма камня вне области эффекта не искажена при изменении viewport.

- **Адаптивность и ввод:** UI и эффекты должны работать на desktop и мобильных размерах с mouse, Pointer Events и touch.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** элементы управления не перекрываются, а эффект доступен на основных брейкпоинтах проекта.

- **Производительность:** WebGL-эффект не должен блокировать scroll, физику сцены или переходы между сценами.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** основной цикл анимации остаётся отзывчивым во время деформации.

- **Доступность UI:** переключатели и параметры должны иметь видимые названия, текущие значения и поддерживать клавиатурное управление.
  - **Источник:** утверждённый итоговый черновик требований.
  - **Acceptance hint:** все controls доступны по Tab и имеют связанный label.

- **Независимая реализация:** flow-map-поведение должно быть воспроизведено самостоятельно; закрытый сторонний `water_effect.js` не должен копироваться в проект.
  - **Источник:** утверждённый итоговый черновик требований и ограничения источника референса.
  - **Acceptance hint:** реализация использует собственный код или совместимую библиотеку с допустимой лицензией.

## Проблемы и замечания, превращённые в требования

- **Остаточная деформация:** предыдущие прототипы сохраняли искажение. Требуемое поведение: гарантированный полный возврат к оригинальной текстуре после каждого взаимодействия.
  - **Источник:** «Не восстанавливаются обратно!».
  - **Acceptance hint:** состояние эффекта обнуляется после восстановления.

- **Неверный тип эффекта:** предыдущие варианты напоминали пластилин или размазывание. Требуемое поведение: локальная оптическая WebGL-линза с пятью конфигурациями.
  - **Источник:** «Я перепутал я имел ввиду эффект линзы с разными конфигурациями».
  - **Acceptance hint:** в UI отсутствуют прежние jelly/smear-эффекты, доступны пять утверждённых линз.

- **Визуальная рука:** крупный спрайт руки перекрывал сцену. Требуемое поведение: спрайт скрыт, обратная связь обеспечивается курсорами open/grabbing.
  - **Источник:** «Рука уже не отображается».
  - **Acceptance hint:** видимой руки нет при всех состояниях Сцены 3.

- **Преждевременное движение камня:** камень мог продолжать движение без пользовательского scroll. Требуемое поведение: после первого попадания камень фиксируется до реального scroll вниз.
  - **Источник:** исходное описание изменений Сцены 3.
  - **Acceptance hint:** таймеры и инерция не освобождают зафиксированный камень.

## Открытые вопросы

- Блокирующих вопросов нет. По умолчанию используется `Brandon Mercer Flowmap`; исходный режим активации — наведение, при этом пользователь может выбрать удержание; остальные четыре эффекта получают собственные редактируемые пресеты.

## Не включено / требует уточнения

- Jelly, gooey, elastic warp, soft-body и прежнее пластилиновое размазывание не включаются как отдельные варианты.
- Одноразовая анимация деформации только по клику заменена управляемой линзой.
- Копирование закрытого исходного скрипта Brandon Mercer не включено; реализуется самостоятельный эквивалент поведения.
