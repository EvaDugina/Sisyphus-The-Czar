## Исходный текст

- При открытии страницы dev-контейнера в другом браузере недоступны шаблоны настроек, созданные в первом браузере.
- Шаблоны должны быть доступны во всех браузерах и персональных сессиях одного dev-развёртывания.

---

## Функциональные требования

- **Единый каталог шаблонов:** Система должна предоставлять всем браузерам одного dev-развёртывания единый серверный каталог шаблонов настроек.
  - **Пояснение:** Каталог не принадлежит конкретному браузеру, комнате или персональной сессии.
  - **Источник:** "Шаблоны должны быть доступны везде."
  - **Acceptance hint:** Шаблон, сохранённый в браузере A, присутствует в списке браузера B.

- **Загрузка при подключении:** Система должна передавать каждому debug-браузеру актуальный серверный каталог после подключения персональной сессии.
  - **Пояснение:** Наличие шаблонов не зависит от `localStorage` текущего браузера или прежнего посещения страницы.
  - **Источник:** "В другом браузере мне недоступны шаблоны настроек из другого браузера."
  - **Acceptance hint:** Новый браузер с пустым хранилищем после открытия dev-страницы видит ранее сохранённые шаблоны.

- **Доступ из персональной сессии:** Система должна разрешать чтение, сохранение, импорт и удаление шаблонов debug-клиенту независимо от внутреннего идентификатора его персональной комнаты.
  - **Пояснение:** Доступ не требует подключения к legacy root-комнате.
  - **Источник:** "При открытии страницы в dev-контейнере в другом браузере мне недоступны шаблоны."
  - **Acceptance hint:** Сервер не отвечает `debug_only` для персональной сессии dev-контейнера с `DEBUG=true`.

- **Межсессионное обновление каталога:** После успешного сохранения, импорта или удаления шаблона система должна передавать изменение всем подключённым debug-браузерам без перезагрузки страницы.
  - **Пояснение:** Рассылка изменения не ограничивается комнатой автора.
  - **Источник:** "Шаблоны должны быть доступны везде."
  - **Acceptance hint:** Открытый браузер B обновляет список после действия браузера A.

- **Использование общего шаблона:** Система должна позволять любому браузеру выбрать и локально применить шаблон, полученный из общего каталога.
  - **Пояснение:** Шаблон передаётся вместе с поддерживаемыми настройками, а не только как название.
  - **Источник:** "Шаблоны должны быть доступны везде."
  - **Acceptance hint:** Браузер B выбирает шаблон браузера A и применяет его к своей персональной сессии.

- **Сохранение серверной каноничности:** Система должна сохранить действующие правила лимита, дедупликации, ветвления конфликтов и защиты выбранного production preset.
  - **Пояснение:** Меняется область доступности каталога, а не его модель данных.
  - **Источник:** Контекст существующего серверного каталога.
  - **Acceptance hint:** Повторный импорт и конфликтное сохранение обрабатываются по прежним правилам.

## Нефункциональные требования

- **Независимость от браузерного хранилища:** Серверный каталог должен оставаться источником истины между разными браузерами.
  - **Пояснение:** Локальное хранилище используется только для персонального UI-состояния и legacy-импорта.
  - **Источник:** "В другом браузере мне недоступны шаблоны настроек из другого браузера."
  - **Acceptance hint:** Очистка `localStorage` не удаляет серверные шаблоны.

- **Изоляция текущих настроек:** Общий каталог не должен синхронизировать выбранный шаблон, черновик или применённые параметры между персональными сессиями.
  - **Пояснение:** Общими являются только сохранённые шаблоны каталога; runtime каждого пользователя остаётся независимым.
  - **Источник:** Согласованная модель персональных сессий и общий каталог шаблонов.
  - **Acceptance hint:** Применение шаблона в браузере A не изменяет параметры браузера B.

- **Согласованность каталога:** Подключённые debug-браузеры должны получать одинаковое содержимое и ревизию каталога после успешной операции.
  - **Пояснение:** Межсессионная рассылка не должна создавать разные варианты списка.
  - **Источник:** "Шаблоны должны быть доступны везде."
  - **Acceptance hint:** После обработки события списки совпадают по `id` и `updatedAt`.

- **Сохранность данных:** Временное отключение браузера не должно удалять или повреждать ранее сохранённые серверные шаблоны.
  - **Пояснение:** Каталог продолжает храниться в существующем server store.
  - **Источник:** Требование межбраузерной доступности.
  - **Acceptance hint:** После повторного подключения каталог загружается из действующего server store.

## Проблемы и замечания, превращённые в требования

- **Root-only доступ:** Сейчас сервер разрешает операции с каталогом только клиенту `DEFAULT_SESSION_ID`. Требуемое поведение: каталог доступен любой персональной debug-сессии.
  - **Источник:** "При открытии страницы в dev-контейнере в другом браузере мне недоступны шаблоны."
  - **Acceptance hint:** Личная сессия получает страницу каталога вместо ошибки `debug_only`.

- **Рассылка внутри одной комнаты:** Сейчас изменение шаблона отправляется только клиентам комнаты автора. Требуемое поведение: изменение каталога получают все активные debug-сессии.
  - **Источник:** "Шаблоны должны быть доступны везде."
  - **Acceptance hint:** Сохранение и удаление отражаются в другом открытом браузере без reload.

- **Зависимость от локального браузера:** Сейчас новый браузер может остаться только со своим локальным списком или состоянием «Черновик». Требуемое поведение: он загружает общий серверный каталог.
  - **Источник:** "В другом браузере мне недоступны шаблоны настроек из другого браузера."
  - **Acceptance hint:** Пустой новый browser context получает существующие серверные записи.
