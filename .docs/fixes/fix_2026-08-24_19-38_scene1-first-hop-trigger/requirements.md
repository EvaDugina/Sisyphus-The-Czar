«Сцена 1: Дай на UI переключатель “Первое отпрыгивание” с двумя состояниями “hover” и “клик”. В выключенном состоянии как сейчас. Во включенном — камень первый раз отпрыгивает от руки не по hover, а по клику. При включенном состоянии первый клик в общее число фейковых не входит. Фейковые — дополнительно».

Утверждённая трактовка: выключенное состояние соответствует `hover`, включённое — `клик`.

## Функциональные требования

- **Переключатель «Первое отпрыгивание»:** В настройках Сцены 1 система должна отображать переключатель с состояниями `hover` и `клик`.
  - **Пояснение:** Пользователь должен управлять действием, которое запускает первое отпрыгивание камня.
  - **Источник:** «Дай на UI переключатель “Первое отпрыгивание” с двумя состояниями “hover” и “клик”».
  - **Acceptance hint:** В UI настроек Сцены 1 видны название настройки и текущее состояние.

- **Режим `hover`:** В выключенном состоянии переключателя камень должен впервые отпрыгивать при наведении руки, как в текущем поведении.
  - **Пояснение:** Это режим по умолчанию и обратная совместимость.
  - **Источник:** «В выключенном состоянии как сейчас».
  - **Acceptance hint:** Наведение запускает первое отпрыгивание; дальнейшие клики обрабатываются по существующей логике.

- **Режим `клик`:** Во включённом состоянии камень не должен впервые отпрыгивать от наведения; первое отпрыгивание должно запускаться первым кликом по камню.
  - **Пояснение:** Пользователь явно активирует первый отскок нажатием.
  - **Источник:** «Во включенном — камень первый раз отпрыгивает от руки не по hover, а по клику».
  - **Acceptance hint:** Hover не запускает отпрыгивание, первый клик запускает его.

- **Отдельный активационный клик:** Первый клик в режиме `клик` должен использоваться только для запуска первого отпрыгивания и не должен считаться фейковым или настоящим кликом основной последовательности.
  - **Пояснение:** Активация первого отскока отделена от счётчика фейковых кликов.
  - **Источник:** «Первый клик в общее число фейковых не входит».
  - **Acceptance hint:** Счётчик фейковых кликов не изменяется после активационного клика.

- **Сохранение числа фейковых кликов:** После активационного клика система должна дополнительно обработать полное настроенное количество фейковых кликов.
  - **Пояснение:** Например, при значении 3 последовательность состоит из одного активационного клика, трёх фейковых и следующего настоящего клика.
  - **Источник:** «Фейковые — дополнительно».
  - **Acceptance hint:** Количество фейковых реакций после активации точно равно настроенному значению.

- **Независимость режимов:** Переключение способа первого отпрыгивания не должно менять существующую механику фейковых и настоящего кликов, кроме отдельного активационного клика в режиме `клик`.
  - **Пояснение:** Изменение ограничено способом запуска первого отскока.
  - **Источник:** Совокупность утверждённых требований.
  - **Acceptance hint:** После первого отскока оба режима проходят одинаковую настроенную последовательность фейковых и настоящего кликов.

## Нефункциональные требования

- **Понятность UI:** Подпись и состояния переключателя должны однозначно показывать, какое действие запускает первое отпрыгивание.
  - **Пояснение:** Состояние настройки должно читаться без дополнительного объяснения.
  - **Источник:** «Переключатель “Первое отпрыгивание” с двумя состояниями “hover” и “клик”».
  - **Acceptance hint:** В UI одновременно различимы название настройки и выбранный режим.

- **Совместимость:** Режим `hover` должен полностью сохранять текущее поведение Сцены 1.
  - **Пояснение:** Новая настройка не должна менять существующий сценарий по умолчанию.
  - **Источник:** «В выключенном состоянии как сейчас».
  - **Acceptance hint:** Сценарий в режиме `hover` проходит существующие smoke-тесты.

- **Согласованность настроек:** Значение переключателя должно храниться и применяться тем же способом, что и остальные настройки Сцены 1.
  - **Пояснение:** Настройка должна участвовать в существующем UI и runtime-контракте конфигурации.
  - **Источник:** Требование добавить управление на UI.
  - **Acceptance hint:** После сохранения настроек runtime получает выбранное значение без отдельного канала состояния.

## Проблемы и замечания, превращённые в требования

- **Выбор триггера первого отпрыгивания:** Сейчас первое отпрыгивание всегда связано с hover. Требуемое поведение: пользователь выбирает запуск по hover или по клику.
  - **Источник:** «Камень первый раз отпрыгивает от руки не по hover, а по клику».
  - **Acceptance hint:** Оба режима доступны и дают различимое поведение до первого отскока.

- **Корректный подсчёт фейковых кликов:** Активационный клик не должен сокращать количество настроенных фейковых кликов.
  - **Источник:** «Первый клик в общее число фейковых не входит. Фейковые — дополнительно».
  - **Acceptance hint:** При любом настроенном N после активационного клика происходят ровно N фейковых кликов.
