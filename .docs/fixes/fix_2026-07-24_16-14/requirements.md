## Исходный текст

Пользователь запросил добавить в UI параметр максимальной громкости дождя и
снизить минимальную высоту страницы до `100vh`. Уточнено и утверждено:
громкость имеет диапазон `0–300%`, шаг `1%`, значение по умолчанию `50%`;
`100vh` становится только минимумом, текущий дефолт высоты `1000vh`
сохраняется; изменение громкости активного дождя выполняется плавно через
текущее время «Появление, мс».

## Функциональные требования

- **Максимальная громкость дождя:** Система должна показывать в разделе
  «Дождь» параметр «Максимальная громкость», определяющий целевой уровень
  звука дождя после завершения плавного появления.
  - **Пояснение:** Пользователь должен управлять предельной громкостью фонового
    дождя через общий UI параметров.
  - **Источник:** "Добавь на ui параметр максимального звука дождя"
  - **Acceptance hint:** Диапазон `0–300%`, шаг `1%`, значение по умолчанию
    `50%`.

- **Уровни громкости:** Система должна интерпретировать `0%` как полностью
  неслышимый дождь, `100%` как стандартный уровень аудиосигнала и `300%` как
  коэффициент усиления `3.0`.
  - **Пояснение:** Значения выше `100%` должны действительно усиливать сигнал,
    а не ограничиваться пределом свойства `HTMLAudioElement.volume`.
  - **Источник:** "От 0 до 300%. Дефолт 50%."
  - **Acceptance hint:** При `300%` целевой коэффициент усиления равен `3.0`;
    при `0%` — `0`.

- **Плавное применение громкости:** Система должна плавно переводить уже
  активный звук дождя к новому максимальному уровню без перезапуска аудиофайла.
  - **Пояснение:** Для перехода используется текущее значение параметра
    «Появление, мс».
  - **Источник:** "Подтверждаю"
  - **Acceptance hint:** Изменение параметра во время дождя не сбрасывает
    позицию воспроизведения и завершает fade на новом уровне.

- **Общая настройка комнаты:** Система должна синхронизировать максимальную
  громкость дождя между master и slave, сохранять её в сессии и включать в
  общие версии параметров.
  - **Пояснение:** UI доступен master, но фактическая громкость применяется у
    всех участников комнаты.
  - **Источник:** Контекст утверждённых общих параметров приложения.
  - **Acceptance hint:** После изменения master оба клиента получают одинаковое
    значение, а reconnect и восстановление сессии его сохраняют.

- **Высота страницы от одного экрана:** Система должна разрешать значение
  параметра «Высота страницы» начиная с `100vh`.
  - **Пояснение:** `100vh` становится только новым минимумом; значение по
    умолчанию остаётся `1000vh`.
  - **Источник:** "Сделай высоту страницы от 100vh" и подтверждение уточнения.
  - **Acceptance hint:** Диапазон `100–10000vh`, шаг `100vh`, дефолт `1000vh`.

- **Физика короткой страницы:** Система должна сохранять корректные границы
  сцены, положение камня и компенсацию вертикальной скорости при высоте
  `100vh`.
  - **Пояснение:** Сокращение страницы не должно ломать каноническую физику и
    проекцию сцены.
  - **Источник:** Требование минимальной высоты `100vh`.
  - **Acceptance hint:** При выборе `100vh` камень остаётся в допустимых
    границах, а вычисления не возвращают отрицательные или нечисловые значения.

## Нефункциональные требования

- **Обратная совместимость:** Система должна назначать максимальную громкость
  `50%` существующим сессиям и сохранённым версиям, в которых новый параметр
  отсутствует.
  - **Пояснение:** Старые данные должны продолжить загружаться без ошибок.
  - **Источник:** Утверждённый дефолт `50%`.
  - **Acceptance hint:** Legacy payload без нового ключа нормализуется в
    `0.5`.

- **Единообразие UI:** Система должна отображать максимальную громкость в
  процентах.
  - **Пояснение:** Формат согласуется с другими относительными параметрами.
  - **Источник:** Утверждённый диапазон `0–300%`.
  - **Acceptance hint:** UI показывает `0%`, `50%`, `100%` и `300%` без смены
    единиц измерения.

- **Стабильность аудио:** Изменение максимальной громкости не должно создавать
  второй аудиопоток, сбрасывать позицию воспроизведения или некорректно
  обрывать текущую fade-анимацию.
  - **Пояснение:** Управление уровнем должно работать поверх одного loop-аудио.
  - **Источник:** Подтверждение плавного изменения активного дождя.
  - **Acceptance hint:** Активный audio element сохраняется, меняется только
    целевой коэффициент усиления.

- **Усиление свыше 100%:** Система должна поддерживать коэффициент усиления до
  `3.0` без ошибки или остановки воспроизведения.
  - **Пояснение:** Браузерное ограничение `audio.volume <= 1` не должно
    ограничивать утверждённый диапазон.
  - **Источник:** "От 0 до 300%."
  - **Acceptance hint:** Значение `300%` принимается, синхронизируется и
    применяется аудиотрактом.

## Проблемы и замечания, превращённые в требования

- **Недоступная настройка громкости:** Сейчас громкость дождя зафиксирована в
  коде на `42%`. Требуемое поведение: общая UI-настройка с дефолтом `50%` и
  диапазоном до `300%`.
  - **Источник:** "Добавь на ui параметр максимального звука дождя"
  - **Acceptance hint:** В runtime отсутствует фиксированная целевая громкость
    `0.42`; используется нормализованное значение общей настройки.

- **Завышенный минимум страницы:** Сейчас минимальная высота страницы равна
  `500vh`. Требуемое поведение: пользователь может выбрать `100vh`.
  - **Источник:** "Сделай высоту страницы от 100vh"
  - **Acceptance hint:** Минимальное значение UI и общей схемы равно одному
    экрану.
