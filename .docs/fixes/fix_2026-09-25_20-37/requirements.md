## Исходный текст

Пользователь запросил для Сцены 1 отключить подпускание после двух первых фейковых кликов, не считая начального клика: все дальнейшие попытки относятся к постоянной третьей фейковой стадии. При вероятности подпускания `0%` пользователь всё равно может успеть нажать на движущийся камень; такой клик должен оставаться фейковой попыткой. Дополнительно после начального клика включённый режим окон должен показывать окна в местах кликов не только по камню, но и по свободному игровому полю.

---

## Функциональные требования

- **Начальный клик:** Первый клик по камню должен запускать игру, выполнять установленный отскок с эхо, но не считаться фейковым, не открывать окно и не воспроизводить звук.
  - **Пояснение:** Начальный клик остаётся отдельной фазой и не расходует два первых фейковых клика.
  - **Источник:** «после того как игра началась (после начального клика)» и ранее утверждённое поведение начального клика.
  - **Acceptance hint:** После начального клика `guardClicksUsed` остаётся равен `0`, popup и звук не создаются, камень выполняет click-hop.

- **Первые два фейковых клика:** Первый и второй фейковые клики должны сохранять существующую последовательность и всегда вызывать click-hop.
  - **Пояснение:** Вероятность подпускания не применяется к самому событию фейкового клика.
  - **Источник:** «после 2 первых фейковых кликов не считая начального клика».
  - **Acceptance hint:** Каждый из двух разрешённых фейковых pointerdown увеличивает `guardClicksUsed` ровно на один и запускает отскок.

- **Вероятность первых двух этапов:** Вероятность подпускания `10%` должна продолжать применяться при подготовке первого и второго фейковых кликов после предусмотренных обязательных отскоков.
  - **Пояснение:** Новое значение `0%` относится только к постоянной стадии после второго фейкового клика.
  - **Источник:** уточнение «Для третьего фейкового клика».
  - **Acceptance hint:** До второго фейкового клика действующая вероятность и обязательные hover-отскоки не меняются.

- **Постоянная третья стадия:** После выполнения второго фейкового клика вероятность подпускания должна быть `0%`, а каждый последующий hover-вход должен вызывать отскок.
  - **Пояснение:** Все попытки после двух первых фейковых кликов считаются попытками третьего фейкового клика; стадия не переходит к обычному настоящему клику.
  - **Источник:** «Для третьего фейкового клика (все попытки после 2 первых фейковых кликов не считая начального клика) отключи подпускание».
  - **Acceptance hint:** После `guardClicksUsed=2` многократные полные выходы и входы в радиус всегда запускают hop и никогда не выставляют обычное разрешение на настоящий клик.

- **Клик по движущемуся камню на третьей стадии:** Если после двух фейковых кликов пользователь успевает нажать на движущийся камень, нажатие должно считаться очередной фейковой попыткой, запускать отскок и не завершать сцену.
  - **Пояснение:** Нулевая вероятность подпускания не должна делать фактически достижимый pointerdown настоящим кликом.
  - **Источник:** «При вероятности подпускания 0 у пользователя все равно остается возможность успеть кликнуть».
  - **Acceptance hint:** Pointerdown по камню при `guardClicksUsed=2` не вызывает `completeScene`, не включает физику и оставляет guidance незавершённым.

- **Окна по игровому полю:** При включённой настройке «Открывать окно при любом клике» после начального клика каждый основной клик по свободной части игрового поля должен открывать ровно одно окно в месте клика.
  - **Пояснение:** Область показа окон расширяется с камня на всё игровое поле после запуска игры.
  - **Источник:** «После того как игра началась (после начального клика) начинай отрисовывать окна на местах клика не только по камню но и по полю».
  - **Acceptance hint:** После начального клика primary-click по нескольким свободным точкам поля создаёт по одному popup около каждой точки.

- **Окна по камню:** После начала игры клики по камню должны создавать ровно одно окно согласно действующим правилам popup; общий обработчик игрового поля не должен создавать дубль.
  - **Пояснение:** Один пользовательский клик должен иметь один визуальный результат.
  - **Источник:** «не только по камню но и по полю».
  - **Acceptance hint:** Счётчик popup увеличивается ровно на один на каждый post-initial клик по камню.

- **Граница начала показа:** До начального клика клики по свободному полю не должны открывать окна; сам начальный клик также не должен открывать окно.
  - **Пояснение:** Отображение окон по полю начинается только после запуска игры.
  - **Источник:** «После того как игра началась (после начального клика)».
  - **Acceptance hint:** До и во время начального клика количество popup не меняется.

- **Независимость фоновых кликов:** Клики по свободному полю должны открывать окна, но не изменять количество фейковых кликов, hover-счётчики и фазу игры.
  - **Пояснение:** Визуальный эффект окна не должен менять игровой прогресс.
  - **Источник:** требование показывать окна «по полю».
  - **Acceptance hint:** До и после фонового клика debug-состояние guidance совпадает.

- **Исключение интерфейса:** Клики по панели настроек, toolbar, кнопкам, ссылкам и полям ввода не должны создавать игровые окна.
  - **Пояснение:** Настройка относится только к игровой области.
  - **Источник:** сохранение утверждённой области действия переключателя.
  - **Acceptance hint:** Клики по UI не изменяют количество popup.

- **Действующие параметры окон:** Для окон по игровому полю должны использоваться существующие настройки задержки, размера и выбора изображения.
  - **Пояснение:** Новый путь открытия не должен создавать отдельную несовместимую конфигурацию.
  - **Источник:** расширение существующего режима окон.
  - **Acceptance hint:** Popup поля использует выбранную картину, задержку и общий размер последовательности.

## Нефункциональные требования

- **Точность расположения:** Окно должно позиционироваться относительно фактической точки клика с безопасной корректировкой у границ экрана.
  - **Пояснение:** Пользователь должен видеть связь между кликом и появившимся окном.
  - **Источник:** «окна на местах клика».
  - **Acceptance hint:** Клики в центре и у краёв создают видимые popup рядом с соответствующими точками.

- **Отсутствие дублей:** Один пользовательский клик должен создавать не более одного окна.
  - **Пояснение:** Обработчики камня и поля не должны независимо открывать два popup.
  - **Источник:** «не только по камню но и по полю».
  - **Acceptance hint:** На серии кликов число новых окон равно числу допустимых кликов.

- **Надёжность после смены фокуса:** Возврат из popup не должен позволять обойти нулевую вероятность подпускания третьей стадии или преждевременно завершить сцену.
  - **Пояснение:** Popup временно меняет фокус, но не игровую фазу.
  - **Источник:** утверждённая постоянная третья стадия и существующая логика popup.
  - **Acceptance hint:** После возврата фокуса следующий hover или быстрый click остаётся фейковой попыткой.

- **Сохранение настроек:** Переключатель окон по всем кликам должен продолжать сохраняться в параметрах Сцены 1, именованных/Git-шаблонах и синхронизироваться между браузерами комнаты.
  - **Пояснение:** Исправление runtime не должно менять существующий контракт настроек.
  - **Источник:** сохранение утверждённой настройки «Открывать окно при любом клике».
  - **Acceptance hint:** Значение переживает reload и передаётся второму клиенту той же комнаты.

## Проблемы и замечания, превращённые в требования

- **Подпускание после двух фейковых кликов:** Сейчас после двух фейковых кликов пользователь может быть подпущен к камню и завершить сцену обычным настоящим кликом. Требуемое поведение: все дальнейшие hover-входы имеют `0%` подпускания, а достижимый быстрый pointerdown считается фейковой попыткой и вызывает отскок.
  - **Источник:** «Для третьего фейкового клика ... отключи подпускание» и «у пользователя все равно остается возможность успеть кликнуть».
  - **Acceptance hint:** Сцена не завершается после второго фейкового клика ни через hover-допуск, ни через быстрый pointerdown по движущемуся камню.

- **Окна по свободному полю:** Сейчас включённый режим окон не во всех ожидаемых случаях показывает окно при клике по свободной части игрового поля. Требуемое поведение: после начального клика каждый допустимый primary-click по игровой области создаёт одно окно у точки клика.
  - **Источник:** «Почему не отображаешь окна на месте клика по игровому полю?».
  - **Acceptance hint:** Свободные клики после старта создают popup, до старта и на UI — нет.
