## Исходный текст

1. При фейковых кликах по камню в сцене «Кошки-мышки» не проигрывать звук гачи; параметр назвать «Количество фейковых кликов».
2. Разделить параметры UI по двум сценам. В верхней части панели добавить кнопки «Сцена 1. Кошки-мышки» и «Сцена 2. Репка», которые показывают только относящиеся к выбранной сцене параметры и разделы. Общие параметры можно повторять.

## Функциональные требования

- **Количество фейковых кликов:** Существующий UI-параметр количества предварительных отскоков должен называться «Количество фейковых кликов». Его диапазон и текущее поведение счётчика сохраняются.
  - **Пояснение:** Название должно описывать пользовательскую механику, а не внутреннюю защитную логику.
  - **Источник:** «назови параметр “Количество фейковых кликов”»
  - **Acceptance hint:** На UI больше нет названия «Количество защитных кликов»; отображается новое название.

- **Фейковый клик без звука гачи:** При каждом из первых `N` засчитанных кликов по камню в сцене «Кошки-мышки» камень должен отпрыгнуть, но звук гачи не должен воспроизводиться.
  - **Пояснение:** Звук настоящего взаимодействия не должен выдавать фейковый клик.
  - **Источник:** «при фейковых кликах ... не проигрывай звук гачи»
  - **Acceptance hint:** При `N = 3` первые три клика вызывают бесшумный отскок; четвёртый настоящий клик использует обычное звуковое поведение.

- **Сохранение логики фейкового клика:** Фейковый клик не должен включать физику камня, начинать перетаскивание или переводить игру в сцену 2 «Репка». Автоматические отскоки и клики вне камня не расходуют счётчик.
  - **Пояснение:** Меняется только звук и пользовательское название уже существующего предварительного отскока.
  - **Источник:** «при фейковых кликах по камню на сцене “кошки мышки”»
  - **Acceptance hint:** После фейкового клика игра остаётся в preclick-фазе сцены 1, а счётчик увеличивается ровно на один.

- **Настоящий клик:** После исчерпания `N` фейковых кликов следующий подходящий клик должен выполнять существующий сценарий настоящего клика, включая действующее звуковое поведение, физику и переход между сценами.
  - **Пояснение:** Обычный переход в «Репку» не должен измениться.
  - **Источник:** «при фейковых кликах ... не проигрывай звук»
  - **Acceptance hint:** При `N = 3` четвёртый подходящий клик завершает preclick-фазу по существующим правилам.

- **Переключатель сцен в UI:** В верхней части панели параметров должны располагаться две кнопки: «Сцена 1. Кошки-мышки» и «Сцена 2. Репка».
  - **Пояснение:** Кнопки служат переключателем состава видимых настроек.
  - **Источник:** «сверху добавь 2 кнопки “сцена 1. кошки-мышки”, “сцена 2. репка”»
  - **Acceptance hint:** Обе кнопки видны над разделами параметров, одна из них имеет активное состояние.

- **Фильтрация параметров по сцене:** При выборе кнопки UI должен показывать только параметры, используемые в соответствующей сцене. Параметры другой сцены должны скрываться.
  - **Пояснение:** Пользователь должен видеть только релевантную текущей сцене конфигурацию.
  - **Источник:** «по которым показывай и скрывай соответствующие параметры»
  - **Acceptance hint:** Переключение кнопки меняет набор видимых контролов без перезагрузки страницы.

- **Фильтрация разделов:** Если раздел настроек не содержит параметров выбранной сцены, весь раздел, включая его заголовок и контейнер, должен быть скрыт.
  - **Пояснение:** В панели не должны оставаться пустые разделы.
  - **Источник:** «показывай и скрывай ... параметры в разделах и сами разделы»
  - **Acceptance hint:** После выбора сцены в панели нет пустых секций или секций только с параметрами другой сцены.

- **Общие параметры:** Параметры, реально используемые в обеих сценах, могут отображаться в обеих вкладках. Повторённые элементы должны редактировать одно общее значение и синхронно отражать его состояние.
  - **Пояснение:** Повторение относится к представлению, а не к созданию независимых настроек.
  - **Источник:** «можно повторение»
  - **Acceptance hint:** Изменение общего параметра в одной сцене видно после переключения на вторую сцену.

- **Переключение без сброса:** Переключение между сценами не должно сбрасывать, перезаписывать или применять значения по умолчанию вместо пользовательских настроек.
  - **Пояснение:** Фильтрация UI не меняет модель настроек.
  - **Источник:** Требование разделить отображение существующих параметров.
  - **Acceptance hint:** Значения до и после нескольких переключений сцен совпадают.

- **Сохранение настроек:** Все значения параметров должны продолжать сохраняться между запусками приложения независимо от выбранной сцены UI.
  - **Пояснение:** Сохраняется ранее утверждённое требование о персистентности всех UI-параметров.
  - **Источник:** Ранее утверждённое требование: «все параметры на ui должны сохраняться между запусками».
  - **Acceptance hint:** После перезагрузки страницы значения обеих сцен восстанавливаются.

## Нефункциональные требования

- **Понятное активное состояние:** Пользователь должен визуально понимать, какая из двух сцен сейчас выбрана в панели настроек.
  - **Пояснение:** Переключатель не должен выглядеть как две независимые команды без состояния.
  - **Источник:** Требование двух кнопок, управляющих показом параметров.
  - **Acceptance hint:** Активная кнопка визуально отличается от неактивной.

- **Мгновенное переключение:** Показ и скрытие разделов не должны перезапускать игровую сцену, обновлять страницу или заметно задерживать интерфейс.
  - **Пояснение:** Переключатель меняет только представление панели.
  - **Источник:** «по которым показывай и скрывай»
  - **Acceptance hint:** Игровое состояние не меняется при переключении вкладок.

- **Обратная совместимость:** Изменение названия параметра и группировка UI не должны удалять ранее сохранённое значение количества фейковых кликов.
  - **Пояснение:** Меняется UI-метка, а не ключ хранилища.
  - **Источник:** Переименование существующего параметра.
  - **Acceptance hint:** Сохранённое до обновления значение отображается под новым названием.

## Проблемы и замечания, превращённые в требования

- **Звук настоящего клика воспроизводится на фейковом:** Сейчас фейковые клики используют звуковое поведение настоящего клика. Требуемое поведение: звук гачи разрешён только для настоящего клика после исчерпания фейковых.
  - **Источник:** «при фейковых кликах ... не проигрывай звук гачи»
  - **Acceptance hint:** Фейковые клики бесшумны, настоящий клик сохраняет прежний звук.

- **Параметры разных сцен смешаны:** Сейчас параметры разных игровых сцен представлены вместе. Требуемое поведение: пользователь выбирает сцену и видит только относящиеся к ней параметры и разделы.
  - **Источник:** «раздели UI параметры на используемые на разных сценах»
  - **Acceptance hint:** Каждый контрол классифицирован как относящийся к сцене 1, сцене 2 или обеим.

## Не включено / требует уточнения

- Не создаются независимые значения одного общего параметра для каждой сцены. Повторение означает несколько UI-представлений одной настройки.
- Не меняются существующие правила отскока, радиус, максимальная дистанция и момент перехода в «Репку», кроме отключения звука для фейковых кликов.
- Не требуется сохранять между запусками последнюю открытую вкладку сцены; сохраняются значения параметров.
