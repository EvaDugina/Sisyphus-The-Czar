## Исходный текст

- «Звук кликов царя и slaves должен запускаться общий на всю сессию и запускаться одновременно у всех пользователей».
- «Текст "Смертию смерть поправ" не по середине».
- Подтверждённая трактовка: при нажатии master все слышат выбранный звук цепей master; при нажатии конкретного slave все слышат gachi-звук этого slave.

## Функциональные требования

- **Общий звук pointerdown:** Нажатие на камень должно создавать одно аудиособытие сессии, распространяемое всем подключённым пользователям, включая инициатора.
  - **Пояснение:** Role-звук является общим событием комнаты, а не локальным эффектом клиента.
  - **Источник:** «Звук кликов царя и slaves должен запускаться общий на всю сессию».
  - **Acceptance hint:** В двух браузерах один `pointerdown` приводит к одному воспроизведению у каждого клиента.

- **Звук master:** При нажатии master система должна один раз выбрать конкретный вариант звука цепей и воспроизвести этот же файл у всех участников.
  - **Пояснение:** Клиенты не должны независимо выбирать разные варианты цепей.
  - **Источник:** Подтверждение пользователя: «при клике master все слышат выбранный звук цепей master».
  - **Acceptance hint:** Идентификатор аудиофайла совпадает у инициатора и остальных клиентов.

- **Звук slave:** При нажатии slave система должна воспроизвести у всех участников gachi-звук, закреплённый за этим slave.
  - **Пояснение:** Звуковая идентичность конкретного slave сохраняется для всей сессии.
  - **Источник:** Подтверждение пользователя: «при клике конкретного slave все слышат gachi-звук этого slave».
  - **Acceptance hint:** Все клиенты воспроизводят файл, указанный в назначении нажавшего slave.

- **Момент запуска:** Общее аудиособытие должно создаваться при `pointerdown`; `pointerup` и последующий `click` не должны запускать дополнительный звук.
  - **Пояснение:** Звук начинается в момент нажатия.
  - **Источник:** Ранее утверждённое поведение pointerdown и требование общего session-звука.
  - **Acceptance hint:** Счётчик воспроизведений увеличивается после `pointerdown` и не меняется после `pointerup`.

- **Синхронное воспроизведение:** Сервер должен передавать конкретный идентификатор звука и общее время запуска, чтобы все клиенты начинали воспроизведение максимально одновременно.
  - **Пояснение:** Инициатор не должен слышать звук раньше остальных из-за локального запуска.
  - **Источник:** «запускаться одновременно у всех пользователей».
  - **Acceptance hint:** Клиенты получают одинаковые параметры события и планируют запуск по общему времени сессии.

- **Плавное появление:** Каждый клиент должен применять к общему role-звуку fade-in громкости от `0` до `1` за `300 мс`.
  - **Пояснение:** Сохраняется ранее утверждённая плавность появления.
  - **Источник:** Ранее утверждённое требование к звукам master и slave.
  - **Acceptance hint:** Сразу после запуска громкость меньше `1`, после `300 мс` достигает `1`.

- **Центрирование надписи:** Горизонтальный центр текста «СМЕРТИЮ СМЕРТЬ ПОПРАВ» должен совпадать с центром viewport.
  - **Пояснение:** Надпись должна восприниматься визуально центрированной на экране.
  - **Источник:** «Текст "Смертию смерть поправ" не по середине».
  - **Acceptance hint:** Центр bounding box текста совпадает с центром viewport с учётом округления браузера.

- **Адаптивное вмещение надписи:** Надпись должна оставаться одной строкой, полностью помещаться в viewport и не обрезаться слева или справа.
  - **Пояснение:** Фиксированный размер шрифта не должен выводить строку за границы экрана.
  - **Источник:** Приложенный скриншот с обрезанной правой частью надписи.
  - **Acceptance hint:** На desktop и mobile bounding box надписи находится внутри viewport и горизонтального скролла нет.

## Нефункциональные требования

- **Согласованность аудио:** Все клиенты должны использовать одинаковый аудиофайл инициатора и единое время запуска для одного события.
  - **Пояснение:** Session-звук должен быть детерминированным для всех участников.
  - **Источник:** «общий на всю сессию».
  - **Acceptance hint:** Payload, полученный двумя клиентами, содержит одинаковые sound id и время запуска.

- **Защита от дублей:** Одно session-аудиособытие должно воспроизводиться на каждом клиенте ровно один раз.
  - **Пояснение:** `pointerup`, `click` и повторная обработка одного сообщения не должны дублировать звук.
  - **Источник:** Требование одного общего запуска по `pointerdown`.
  - **Acceptance hint:** Один event id учитывается клиентом один раз.

- **Адаптивная типографика:** Размер надписи должен подбираться по доступной ширине с сохранением текущего семейства шрифта, начертания, регистра и вертикального положения.
  - **Пояснение:** Исправление не должно менять художественный характер экрана.
  - **Источник:** Приложенный скриншот и подтверждённое ограничение области изменений.
  - **Acceptance hint:** Строка помещается на проверяемых разрешениях без переноса и обрезания.

- **Отсутствие регрессий:** Изменения не должны нарушать захват камня, распределение gachi-звуков, viewport-синхронизацию, траекторию и звук дождя.
  - **Пояснение:** Исправление затрагивает основной realtime-путь.
  - **Источник:** Контекст существующего поведения приложения.
  - **Acceptance hint:** Релевантные unit/integration и совместный browser smoke проходят.

## Проблемы и замечания, превращённые в требования

- **Локальное role-аудио:** Сейчас role-звук слышит только инициатор. Требуемое поведение: конкретный звук инициатора слышат все участники сессии максимально одновременно.
  - **Источник:** «Звук кликов царя и slaves должен запускаться общий на всю сессию».
  - **Acceptance hint:** Нажатие в одном браузере увеличивает счётчик того же аудиофайла во всех браузерах.

- **Обрезанная финальная надпись:** Сейчас строка шире viewport, обрезается и визуально выглядит смещённой. Требуемое поведение: вся строка видна и симметрично центрирована.
  - **Источник:** «Текст "Смертию смерть поправ" не по середине» и приложенный скриншот.
  - **Acceptance hint:** Левый и правый края текста находятся внутри viewport с симметричными отступами.
