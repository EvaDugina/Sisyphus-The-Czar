## Исходный текст

1. Генерировать ники с пробелами после слова «Царь» и имени, перед номером. Нумеровать каждое имя отдельно и последовательно: первый Константин получает номер 1, второй — 2.
2. В сцене 3 не показывать в таблице пользователей со временем 0, которые не дошли до вершины.
3. В сцене 3 показывать места 1–10, место текущего царя и последнее место; первое место выделять красным, места 2–10 — кислотно-розовым, текущего царя — серым, последнее место — белым.

## Функциональные требования

- **Формат никнейма:** Система должна формировать никнейм как `Царь <Имя> <Номер>`, например `Царь Константин 1`.
  - **Пояснение:** Между словом «Царь», именем и номером должно быть ровно по одному пробелу.
  - **Источник:** «с пробелом после царя и имени, перед числами».
  - **Acceptance hint:** Новый и восстановленный никнейм соответствует шаблону `^Царь [^\s\d]+ [1-9]\d*$`.

- **Случайный выбор имени:** При создании новой личности система должна случайно выбирать базовое имя из существующего списка царских имён.
  - **Пояснение:** Повтор одного базового имени допустим и обрабатывается отдельной нумерацией.
  - **Источник:** «если человеку присвоено случайно имя константин».
  - **Acceptance hint:** Подмена источника случайности позволяет выбрать ожидаемое имя из списка.

- **Отдельная нумерация для каждого имени:** Система должна назначать каждому базовому имени независимую последовательность номеров, начиная с 1.
  - **Пояснение:** Первый Константин получает 1, второй — 2; первый Иван независимо получает 1. Номера одного имени не повторяются.
  - **Источник:** «если он первый с этим именем — номер должен быть 1, если второй раз присвоился константин — номер должен быть 2».
  - **Acceptance hint:** Для нескольких повторов одного имени выдаются номера `1, 2, 3`, а другое имя начинает собственную последовательность с `1`.

- **Учёт сохранённого рейтинга:** Система должна учитывать уже сохранённых царей с тем же именем при назначении следующего номера.
  - **Пояснение:** Перезапуск сервера не должен обнулять последовательности имён.
  - **Источник:** «в зависимости от того какие номера уже есть».
  - **Acceptance hint:** После сериализации и восстановления следующий повтор имени получает номер, следующий за последним восстановленным.

- **Миграция старых никнеймов:** Система должна принимать ранее сохранённые никнеймы без пробелов и преобразовывать их в новый формат с перенумерацией каждого имени по порядку создания.
  - **Пояснение:** Например, старые `ЦарьИван1` и `ЦарьИван65` становятся `Царь Иван 1` и `Царь Иван 2`, не теряя результаты рейтинга.
  - **Источник:** Утверждённая трактовка совместимости существующих данных.
  - **Acceptance hint:** Восстановление legacy-снимка сохраняет записи и результаты, нормализует имена и сериализует уже новый формат.

- **Исключение нулевых результатов:** Таблица сцены 3 должна полностью исключать царей с результатом `0`, включая текущего царя и кандидата на последнее место.
  - **Пояснение:** Нулевой результат означает, что пользователь не дошёл до вершины.
  - **Источник:** «не отображай в таблице людей с временем 0, которые не дошли до вершины».
  - **Acceptance hint:** Ни одна отображаемая строка не содержит `00:00:00`.

- **Состав таблицы:** Таблица сцены 3 должна показывать места 1–10, затем текущего царя вне top-10 и последнее место среди дошедших до вершины, если соответствующая запись ещё не показана.
  - **Пояснение:** Для каждой строки показывается абсолютное место. Один царь отображается не более одного раза.
  - **Источник:** «1-10 место ... + место текущего царя ... + последнее место».
  - **Acceptance hint:** При рейтинге длиннее 11 участников таблица содержит до 12 уникальных строк: top-10, текущего вне top-10 и последнего.

- **Цветовое оформление рейтинга:** Система должна окрашивать первое место красным, места 2–10 кислотно-розовым, дополнительную строку текущего царя серым, дополнительную строку последнего места белым.
  - **Пояснение:** При пересечении ролей используется приоритет top-10 → текущий царь → последнее место.
  - **Источник:** «1 место — красным цветом, 2-10 место кислотно розовым ... текущего царя серым ... последнее место белым».
  - **Acceptance hint:** Каждая выведенная строка получает класс своей итоговой роли и соответствующий цвет.

## Нефункциональные требования

- **Стабильность личности:** Система должна сохранять назначенный никнейм после перезагрузки страницы и восстановления серверного состояния.
  - **Пояснение:** Изменение формата не должно ломать существующий 24-часовой lifecycle личности.
  - **Источник:** Утверждённое требование учитывать уже существующие номера.
  - **Acceptance hint:** Повторное подключение с сохранённым leaderboard ID возвращает ту же личность.

- **Совместимость данных:** Система должна загружать legacy-записи без удаления результатов рейтинга и сохранять их в новом формате.
  - **Пояснение:** Обновление не должно требовать ручного сброса server store.
  - **Источник:** Утверждённая трактовка миграции старых никнеймов.
  - **Acceptance hint:** Смешанный снимок старого и нового формата восстанавливается без потери валидных записей.

- **Однозначность рейтинга:** Добавление текущей и последней строк не должно менять действующие правила сортировки результатов и разрешения равного времени.
  - **Пояснение:** Изменяется выбор отображаемых строк, но не смысл места.
  - **Источник:** В исходном запросе изменение сортировки не требовалось.
  - **Acceptance hint:** Для одинакового набора результатов абсолютные места совпадают с прежним порядком.

- **Читаемость:** Четыре ролевых цвета должны быть визуально различимы на текущем фоне сцены 3.
  - **Пояснение:** Используются насыщенный красный, неоновый кислотно-розовый, нейтральный серый и белый.
  - **Источник:** Утверждённое цветовое оформление таблицы.
  - **Acceptance hint:** Вычисленные CSS-цвета строк разных ролей различаются.

## Проблемы и замечания, превращённые в требования

- **Глобальный номер вместо номера имени:** Сейчас номер царя общий для всех имён. Требуемое поведение: вести отдельную последовательность для каждого базового имени.
  - **Источник:** «Присваивай номера последовательно в зависимости от того какие номера уже есть».
  - **Acceptance hint:** Два разных имени могут одновременно иметь номер 1.

- **Недостаточный top-блок:** Сейчас top-блок ограничен девятью строками. Требуемое поведение: показывать места 1–10.
  - **Источник:** «Отображай таблицу так: 1-10 место».
  - **Acceptance hint:** При наличии десяти завершивших сцену отображаются все десять.

- **Нулевая строка текущего царя:** Сейчас текущий царь может отображаться со временем 0. Требуемое поведение: не показывать ни одну запись с нулевым результатом.
  - **Источник:** «не отображай в таблице людей с временем 0».
  - **Acceptance hint:** Новый пользователь отсутствует в таблице до появления положительного результата.

- **Нет гарантированной последней строки:** Сейчас snapshot не передаёт последнее место отдельно. Требуемое поведение: добавлять последнего завершившего сцену, если его ещё нет среди показанных строк.
  - **Источник:** «+ последнее место».
  - **Acceptance hint:** В длинном рейтинге последняя запись присутствует и окрашена белым.

- **Неподходящее оформление текущей строки:** Сейчас текущая строка получает единый красный цвет. Требуемое поведение: цвет зависит от итоговой роли строки и утверждённого приоритета.
  - **Источник:** Утверждённая схема цветов.
  - **Acceptance hint:** Текущий царь вне top-10 серый, а текущий царь внутри top-10 сохраняет цвет места.
