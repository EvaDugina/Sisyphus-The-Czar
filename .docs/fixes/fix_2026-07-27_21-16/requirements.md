## Исходный текст

- Для каждой вкладки создавать отдельную комнату и отдельную одноразовую сессию, в которой может находиться не более одного клиента.
- Закрывать сессию, когда пользователь покидает страницу.
- Не показывать уникальный идентификатор сессии в URL и удалить кнопку публикации ссылки.
- Между сессиями синхронизировать только следы траекторий, не меняя существующую отрисовку.
- Загружать историю следов сразу при входе, а новые точки передавать пакетами каждые 30 секунд.
- Показывать `cursor-grab` только при наведении на камень и `cursor-grabbing` во время захвата.

## Функциональные требования

- **Отдельная комната:** Система должна при каждом открытии страницы автоматически создавать новую комнату и сессию для текущей вкладки.
  - **Пояснение:** Две одновременно открытые вкладки должны иметь независимое игровое состояние.
  - **Источник:** "Для каждого пользователя открывай отдельную комнату. На каждого пользователя отдельная сессия."
  - **Acceptance hint:** Две вкладки получают разные внутренние сессии и не изменяют игровое состояние друг друга.

- **Один участник:** Система должна разрешать не более одного активного клиента в пользовательской сессии.
  - **Пояснение:** Второе подключение к той же сессии не должно приводить к совместному управлению.
  - **Источник:** "В одной сессии не больше одного."
  - **Acceptance hint:** Серверное состояние каждой пользовательской комнаты содержит не более одного активного клиента.

- **Закрытие при уходе:** Система должна закрывать текущую сессию при закрытии вкладки, перезагрузке или переходе со страницы; повторное открытие должно создавать новую сессию.
  - **Пояснение:** Покинутая пользовательская комната не должна сохраняться для повторного входа.
  - **Источник:** "Как только пользователь покидает страницу сессия закрывается."
  - **Acceptance hint:** После ухода прежняя сессия недоступна, а новая загрузка страницы получает другой внутренний идентификатор.

- **URL без идентификатора:** Система не должна помещать внутренний идентификатор комнаты или сессии в path, query-параметры или hash страницы.
  - **Пояснение:** Старые параметры сессии должны удаляться из адресной строки.
  - **Источник:** "Убери из url уникальный идентификатор сессии."
  - **Acceptance hint:** Публичный адрес одинаков для разных пользователей и не содержит идентификатора их внутренних сессий.

- **Удаление публикации ссылки:** Система не должна показывать кнопку "Поделиться ссылкой" и выполнять связанное с ней копирование ссылки.
  - **Пояснение:** Кнопка, обработчики и визуальная индикация должны быть удалены во всех вариантах интерфейса.
  - **Источник:** "Убери кнопку поделиться ссылкой."
  - **Acceptance hint:** Кнопка отсутствует в DOM, приложение не предлагает скопировать ссылку на сессию.

- **Изоляция игрового состояния:** Система не должна передавать между пользовательскими сессиями положение камня, физику, управление, настройки, курсоры, звук, роли или другие прикладные данные.
  - **Пояснение:** Единственным общим пользовательским содержимым между сессиями являются следы траекторий.
  - **Источник:** "Синхронизируй между сессиями только следы траектории."
  - **Acceptance hint:** Действия в одной вкладке не изменяют игровой процесс в другой, кроме появления общих следов.

- **Немедленная загрузка истории:** Система должна сразу после входа передавать пользователю накопленную общую историю следов.
  - **Пояснение:** Новая сессия начинает отображение с уже накопленной траектории.
  - **Источник:** "История загружается сразу при входе."
  - **Acceptance hint:** После установления соединения новая вкладка получает существующую историю без ожидания 30-секундного цикла.

- **Пакетная синхронизация новых точек:** Система должна после первоначальной загрузки передавать новые точки из других сессий пакетами с интервалом 30 секунд.
  - **Пояснение:** Пакет содержит точки, появившиеся после предыдущей успешной синхронизации.
  - **Источник:** "Затем новые точки приходят пакетами каждые 30 секунд."
  - **Acceptance hint:** Чужие точки не передаются по одной в реальном времени и появляются после очередного 30-секундного цикла.

- **Локальная траектория без задержки:** Система должна продолжать формировать собственный след пользователя локально с текущим поведением.
  - **Пояснение:** Интервал 30 секунд применяется только к передаче новых точек между сессиями.
  - **Источник:** "Синхронизируй между сессиями только следы траектории. Отрисовку следов не меняй."
  - **Acceptance hint:** Собственный след появляется без ожидания межсессионного пакета.

- **Курсор над камнем:** Система должна показывать `cursor-grab` только при наведении указателя на камень.
  - **Пояснение:** Вне камня используется обычный курсор интерфейса.
  - **Источник:** "Cursor-grab отображается только по наведению на камень."
  - **Acceptance hint:** Рука скрыта вне камня и появляется при `pointerenter`.

- **Курсор при захвате:** Система должна показывать `cursor-grabbing` во время захвата и перетаскивания камня.
  - **Пояснение:** После отпускания камня рука скрывается, если указатель больше не находится над камнем.
  - **Источник:** "У каждого пользователя должна отрисовываться в виде руки cursor-grab или cursor-grabbing."
  - **Acceptance hint:** Открытая рука сменяется сжатой при захвате и возвращается в состояние наведения после отпускания над камнем.

- **Единый вид руки:** Система должна использовать `cursor-grab` и `cursor-grabbing` для всех пользователей без разделения по ролям master/slave.
  - **Пояснение:** Тип изображения руки зависит только от состояния наведения или захвата.
  - **Источник:** "У каждого пользователя должна отрисовываться в виде руки cursor-grab или cursor-grabbing."
  - **Acceptance hint:** Ни один пользователь не получает изображения `hand_open` или `hand_close` из-за сетевой роли.

## Нефункциональные требования

- **Неизменность отрисовки:** Система должна сохранить существующие алгоритм, компонент, стили, сглаживание и параметры отображения следов.
  - **Пояснение:** Меняется только источник поступающих точек.
  - **Источник:** "Отрисовку следов не меняй."
  - **Acceptance hint:** Код и визуальное поведение существующего рендера траектории не изменяются.

- **Изоляция данных:** Межсессионные сообщения не должны содержать прикладные данные других пользователей, кроме траекторий.
  - **Пояснение:** Служебные сообщения транспорта и жизненного цикла соединения допускаются.
  - **Источник:** "Синхронизируй между сессиями только следы траектории."
  - **Acceptance hint:** Межсессионный пакет не содержит состояние камня, курсоры, настройки, звук или роли.

- **Надёжность пакетной доставки:** Временный сбой синхронизации не должен приводить к окончательной потере непринятых точек.
  - **Пояснение:** Непринятые точки остаются доступными для следующего успешного цикла.
  - **Источник:** "Новые точки приходят пакетами каждые 30 секунд."
  - **Acceptance hint:** После восстановления соединения следующий успешный пакет включает ранее не доставленные точки.

- **Чистота адреса:** Создание и восстановление соединения не должны изменять публичный URL или раскрывать внутренний идентификатор.
  - **Пояснение:** Идентификатор используется только внутри сетевого протокола.
  - **Источник:** "Убери из url уникальный идентификатор сессии."
  - **Acceptance hint:** URL остаётся корневым на протяжении жизненного цикла страницы.

- **Согласованность курсора:** Визуальное состояние руки должно соответствовать фактическому состоянию наведения и захвата камня.
  - **Пояснение:** Курсор не должен зависеть от сетевой роли пользователя.
  - **Источник:** "Cursor-grab отображается только по наведению на камень."
  - **Acceptance hint:** Состояния `grab` и `grabbing` переключаются только вслед за событиями взаимодействия с камнем.

## Проблемы и замечания, превращённые в требования

- **Общая постоянная комната:** Сейчас все подключения направляются в одну постоянную root-комнату. Требуемое поведение: отдельная непостоянная комната для каждой вкладки.
  - **Источник:** "Для каждого пользователя открывай отдельную комнату."
  - **Acceptance hint:** Одновременные вкладки подключены к разным сессиям.

- **Несколько участников:** Сейчас одна комната допускает нескольких участников и совместное управление. Требуемое поведение: один клиент на сессию.
  - **Источник:** "В одной сессии не больше одного."
  - **Acceptance hint:** Второй клиент не может присоединиться к активной пользовательской сессии.

- **Избыточная синхронизация:** Сейчас между клиентами синхронизируется вся игровая модель. Требуемое поведение: между пользовательскими сессиями передаются только траектории.
  - **Источник:** "Синхронизируй между сессиями только следы траектории."
  - **Acceptance hint:** Независимые вкладки имеют разные положения камня и настройки.

- **Публикация общей ссылки:** Сейчас интерфейс содержит кнопку копирования общей ссылки. Требуемое поведение: функция удалена.
  - **Источник:** "Убери кнопку поделиться ссылкой."
  - **Acceptance hint:** Элемент `share-session-top` отсутствует.

- **Ролевые изображения руки:** Сейчас изображение руки зависит от роли master/slave. Требуемое поведение: единые `cursor-grab` и `cursor-grabbing`.
  - **Источник:** "У каждого пользователя должна отрисовываться в виде руки cursor-grab или cursor-grabbing."
  - **Acceptance hint:** CSS-класс роли не меняет изображение локальной руки.

- **Синхронизация в реальном времени:** Сейчас чужие изменения распространяются сразу. Требуемое поведение: новые точки чужих траекторий передаются пакетами раз в 30 секунд.
  - **Источник:** "Затем новые точки приходят пакетами каждые 30 секунд."
  - **Acceptance hint:** Между пакетами чужая история не обновляется.
