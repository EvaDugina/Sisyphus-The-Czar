## Исходный текст

Пользователь просит загружать в dev-сборке параметры UI из последнего
сохраненного шаблона, выяснить точные причины визуальных расхождений между
последним сохранением и production, применить к production последнюю
сохраненную конфигурацию с названием `prod`, проверить результат и
закоммитить изменения.

---

## Функциональные требования

- **Последний шаблон при запуске dev:** Dev-сборка должна при открытии
  загружать в UI и активные параметры из последнего сохраненного шаблона по
  `updatedAt`.
  - **Пояснение:** Стартовое состояние dev должно воспроизводить последнее
    явное сохранение, а не отдельный текущий черновик.
  - **Источник:** "Для dev-сборки загружай по умолчанию параметры на UI из
    последнего сохраненного шаблона"
  - **Acceptance hint:** После перезагрузки dev значения и выбранная версия
    соответствуют самому позднему сохраненному шаблону.

- **Безопасный fallback:** При отсутствии сохраненных шаблонов или при
  поврежденном хранилище dev-сборка должна продолжать запускаться со штатными
  значениями.
  - **Пояснение:** Новая логика выбора шаблона не должна ломать первый запуск.
  - **Источник:** "загружай по умолчанию параметры на UI из последнего
    сохраненного шаблона"
  - **Acceptance hint:** Пустой или невалидный список версий не вызывает
    ошибку и сохраняет существующее fallback-поведение.

- **Выбор production-шаблона:** Для production должна использоваться наиболее
  поздняя сохраненная версия с точным названием `prod`; при нескольких таких
  версиях выбирается запись с максимальным `updatedAt`.
  - **Пояснение:** Production должен иметь однозначный источник утвержденных
    параметров.
  - **Источник:** "Примени к prod последнюю сохраненную конфигурацию с
    названием prod"
  - **Acceptance hint:** Зафиксированный production preset совпадает с
    наиболее поздней версией `prod`.

- **Полный перенос конфигурации:** В production должны попасть все
  поддерживаемые параметры выбранного шаблона: физика, shared-настройки и
  локальные визуальные настройки.
  - **Пояснение:** Частичный перенос оставляет визуальные и поведенческие
    расхождения.
  - **Источник:** "Примени к prod последнюю сохраненную конфигурацию"
  - **Acceptance hint:** Поименное сравнение поддерживаемых полей не показывает
    необъясненных отличий.

- **Согласованность общей сессии:** Сохраненное серверное состояние root-сессии
  не должно незаметно возвращать старые physics или room settings поверх
  production-конфигурации. Применение конфигурации не должно сбрасывать
  состояние игры, общее время или создавать новую сессию.
  - **Пояснение:** Root-сессия остается единой и постоянной, а production
    должен фактически отображать утвержденные параметры.
  - **Источник:** "проверь что не совпадает и определи причины"
  - **Acceptance hint:** После подключения production runtime использует
    ожидаемые параметры, при этом идентификатор root-сессии и накопленное время
    сохраняются.

- **Проверка результата:** После переноса должны быть сопоставлены значения
  шаблона `prod`, production preset, фактические runtime-параметры и визуально
  значимые параметры renderer/CSS.
  - **Пояснение:** Проверка должна находить не только различия исходных данных,
    но и расхождения, возникающие после нормализации и подключения к серверу.
  - **Источник:** "И проверь"
  - **Acceptance hint:** Автоматические проверки подтверждают совпадение, а
    smoke-сценарий production проходит.

- **Коммит:** Проверенные изменения, требования и тесты должны быть
  зафиксированы одним Conventional Commit.
  - **Пояснение:** Результат должен быть готов к последующей отправке в
    репозиторий.
  - **Источник:** "Закоммить"
  - **Acceptance hint:** Рабочее дерево чистое, создан один новый коммит с
    Conventional Commit-сообщением.

## Нефункциональные требования

- **Детерминированный выбор:** Выбор последнего шаблона должен одинаково
  работать при любом порядке записей в хранилище.
  - **Пояснение:** Источником порядка является timestamp, а не позиция записи.
  - **Источник:** "последнего сохраненного шаблона"
  - **Acceptance hint:** Перестановка массива версий не меняет выбранную запись.

- **Единая нормализация:** Dev и production должны одинаково обрабатывать
  числовые значения, единицы измерения, цвета, enum и timing-function.
  - **Пояснение:** Различия fallback и преобразований не должны менять
    визуальный результат.
  - **Источник:** "некоторые параметры в prod по визуальному ощущению
    отличаются"
  - **Acceptance hint:** Сравнение выполняется после штатной нормализации
    значений обеих сборок.

- **Совместимость:** Изменение не должно возвращать публичный параметр
  `session`, создавать отдельную комнату или прерывать общее время root-сессии.
  - **Пояснение:** Сохраняются ранее утвержденные ограничения общей сессии.
  - **Источник:** Ранее утвержденные требования проекта.
  - **Acceptance hint:** Production и dev продолжают работать на `/` без
    `session` в URL.

## Проблемы и замечания, превращенные в требования

- **Dev загружает текущий черновик:** Сейчас сохраненные версии читаются
  отдельно, но последняя версия не применяется при старте. Требуемое
  поведение: после чтения списка версий автоматически применить наиболее
  позднюю запись.
  - **Источник:** "Для dev-сборки загружай по умолчанию параметры на UI из
    последнего сохраненного шаблона"
  - **Acceptance hint:** Reload dev-сборки восстанавливает последнюю сохраненную
    версию, даже если текущий localStorage-черновик отличается.

- **Production использует дефолты:** Сейчас `production-preset.mjs` состоит из
  стандартных room settings и physics. Требуемое поведение: preset должен
  соответствовать последнему сохраненному шаблону `prod`.
  - **Источник:** "сейчас некоторые параметры в prod по визуальному ощущению
    отличаются от последнего сохранении"
  - **Acceptance hint:** Тест preset больше не ожидает только стандартные
    значения и проверяет фактический шаблон `prod`.

- **Сервер может перезаписать клиентский preset:** После WebSocket-подключения
  root-сессия присылает сохраненные physics и room settings. Требуемое
  поведение: итоговая production-конфигурация должна совпадать с утвержденным
  preset без сброса игры и времени.
  - **Источник:** "проверь что не совпадает и определи причины"
  - **Acceptance hint:** Интеграционная или smoke-проверка подтверждает
    ожидаемые runtime-значения после получения серверного snapshot.
