## Исходный текст

После первого и второго фейковых кликов должно происходить минимум по одному отдельному hover-отскоку без подпускания. Вероятность подпускания 10% для второго и третьего клика начинает применяться только после соответствующего обязательного hover-отскока. Отскок, выполняемый непосредственно при фейковом клике, в этот минимум не входит.

---

## Функциональные требования

- **Первое подпускание без изменений:** До первого подпускания система должна выполнить три обязательных hover-отскока, после чего гарантированно подпустить камень к первому фейковому клику.
  - **Пояснение:** Начальная последовательность из уже согласованных трёх отскоков сохраняется.
  - **Источник:** «до первого подпускания должно быть 3 отскока» и последующее уточнение, что новая формулировка относится только ко второму и третьему подпусканию.
  - **Acceptance hint:** На первых трёх полных входах курсора камень отскакивает; на четвёртом входе не отскакивает и допускает первый фейковый клик.

- **Обязательный отскок после первого фейкового клика:** После первого фейкового клика следующий валидный hover-вход должен гарантированно вызвать отскок без подпускания.
  - **Пояснение:** На этом входе вероятность 10% не применяется.
  - **Источник:** «после первого ... фейкового клика должно быть произведено минимум одно не подпускания».
  - **Acceptance hint:** Сразу после первого фейкового клика первый полный повторный hover-вход всегда заканчивается отскоком независимо от генератора случайных чисел.

- **Вероятностное второе подпускание:** Только после обязательного hover-отскока, следующего за первым фейковым кликом, каждый новый валидный hover-вход должен независимо давать 10% вероятности подпускания ко второму фейковому клику и 90% вероятности отскока.
  - **Пояснение:** Вероятностная логика не может разрешить немедленное повторное подпускание после первого фейкового клика.
  - **Источник:** «вероятность второго ... подпускания ... 10% начинает работать только после 1 отскока после первого фейкового клика».
  - **Acceptance hint:** После обязательного отскока значение случайной выборки в диапазоне допуска приводит к подпусканию, остальные значения — к отскоку.

- **Обязательный отскок после второго фейкового клика:** После второго фейкового клика следующий валидный hover-вход должен гарантированно вызвать отскок без подпускания.
  - **Пояснение:** На этом входе вероятность 10% не применяется.
  - **Источник:** «после ... второго фейкового клика должно быть произведено минимум одно не подпускания».
  - **Acceptance hint:** Сразу после второго фейкового клика первый полный повторный hover-вход всегда заканчивается отскоком независимо от генератора случайных чисел.

- **Вероятностное третье подпускание:** Только после обязательного hover-отскока, следующего за вторым фейковым кликом, каждый новый валидный hover-вход должен независимо давать 10% вероятности подпускания к третьему, реальному клику и 90% вероятности отскока.
  - **Пояснение:** Вероятностная логика не может разрешить немедленный реальный клик после второго фейкового клика.
  - **Источник:** «вероятность ... третьего подпускания ... 10% начинает работать только после 1 отскока».
  - **Acceptance hint:** После второго обязательного отскока значение случайной выборки в диапазоне допуска приводит к подпусканию, остальные значения — к отскоку.

- **Отдельный учёт hover-входов:** Решения об обязательном или вероятностном подпускании должны приниматься только на валидном повторном hover-входе после полного выхода курсора из области камня.
  - **Пояснение:** Движение курсора внутри области камня не должно многократно расходовать обязательные отскоки или вероятностные попытки.
  - **Источник:** ранее согласованная механика hover-отскоков, сохранённая в актуальном черновике.
  - **Acceptance hint:** Несколько событий движения внутри одного hover-сеанса дают не более одного решения; новое решение возможно после выхода и повторного входа.

## Нефункциональные требования

- **Детерминированная проверяемость:** Обязательные отскоки и границы включения вероятности должны быть покрыты unit- и smoke-тестами с управляемым источником случайности.
  - **Пояснение:** Тесты должны однозначно доказывать, что 10% не применяется раньше времени.
  - **Источник:** утверждённый acceptance-подход для последовательности отскоков.
  - **Acceptance hint:** Тесты отдельно проверяют обе границы: после первого и после второго фейкового клика.

- **Сохранение действующих эффектов:** Изменение не должно нарушать 50%-ный отскок при фейковом клике, звук, popup/эхо, настройки и последующий реальный клик.
  - **Пояснение:** Меняется только момент активации вероятностного hover-подпускания.
  - **Источник:** «отскок самого фейкового клика не считается» и ранее утверждённые требования к фейковому клику.
  - **Acceptance hint:** Существующие проверки эффектов клика продолжают проходить, новые проверки подтверждают обязательные hover-отскоки.

## Проблемы и замечания, превращённые в требования

- **Исключить мгновенное повторное подпускание:** Сейчас вероятность 10% может начать действовать без обязательного hover-отскока после фейкового клика. Требуемое поведение: после каждого из первых двух фейковых кликов система сначала гарантированно не подпускает камень один раз и только затем применяет вероятность 10%.
  - **Источник:** «после первого и второго фейковых кликов должен быть произведено минимум одно не подпускания то есть минимум 2 отскока».
  - **Acceptance hint:** Даже при случайном значении, которое обычно разрешает подпускание, первый hover-вход после каждого фейкового клика всегда приводит к отскоку.

- **Не засчитывать click-hop:** Сейчас отскок непосредственно при фейковом клике можно ошибочно принять за обязательный отскок перед следующим вероятностным подпусканием. Требуемое поведение: обязательный минимум состоит из двух отдельных hover-отскоков — по одному после каждого фейкового клика.
  - **Источник:** подтверждённое прочтение «отскок самого фейкового клика не засчитывается».
  - **Acceptance hint:** Сразу после click-hop следующий валидный hover-вход всё равно гарантированно отскакивает.

## Не включено / требует уточнения

- Не меняется начальная последовательность из трёх обязательных hover-отскоков перед первым подпусканием.
- Не меняется вероятность подпускания 10% после снятия соответствующего обязательного барьера.
- Не меняется параметр 50%-ного отскока непосредственно при фейковом клике.
- Не добавляется более одного обязательного hover-отскока после каждого фейкового клика.
