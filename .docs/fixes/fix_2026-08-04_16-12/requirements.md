## Исходный текст

Пользователь потребовал максимально оптимизировать и исправить механизм свечения, вывести параметры его оптимизации в UI, а также отключать UI-параметры, которые неактуальны для выбранного значения `select`.

---

## Функциональные требования

- **Новый механизм свечения:** система должна исключить применение `shadowBlur` отдельно к каждому сегменту траектории. Базовая линия и свечение должны отрисовываться раздельно, а свечение — одним пакетным проходом по подготовленной маске.
  - **Пояснение:** стоимость размытия не должна линейно умножаться на число сегментов.
  - **Источник:** «Максимально оптимизируй и исправь механизм свечения».
  - **Acceptance hint:** за одно обновление выполняется ограниченное число проходов размытия независимо от длины исходной траектории.

- **Ограниченная сложность:** для слоя свечения должен использоваться отдельный ограниченный бюджет точек с прореживанием траектории, в том числе при включённом `trailUnlimited`.
  - **Пояснение:** длина базовой траектории не должна создавать неограниченную стоимость свечения.
  - **Источник:** «Максимально оптимизируй».
  - **Acceptance hint:** число точек glow-слоя не превышает выбранный бюджет.

- **Отрисовка только при изменениях:** слой свечения и его Fold-копия должны обновляться только после изменения траектории, прокрутки, размера viewport или настроек, влияющих на изображение.
  - **Пояснение:** неподвижная сцена не должна расходовать ресурсы на повторное копирование неизменного canvas.
  - **Источник:** «исправь механизм свечения».
  - **Acceptance hint:** при неизменном trail revision Fold не выполняет повторный `drawImage` траектории.

- **Оптимизация UI-событий:** визуальное применение непрерывных настроек должно объединяться до одного обновления за animation frame, а сохранение и сетевая синхронизация — выполняться после подтверждённого изменения.
  - **Пояснение:** движение ползунка не должно запускать несколько полных синхронных перерисовок в одном кадре.
  - **Источник:** «Максимально оптимизируй».
  - **Acceptance hint:** серия `input`-событий в одном кадре приводит максимум к одной визуальной перерисовке.

- **Режим оптимизации свечения:** UI должен содержать `select` со значениями `Авто`, `Производительность`, `Баланс`, `Качество` и `Ручной`; режимом по умолчанию должен быть `Баланс`.
  - **Пояснение:** пользователь может выбрать готовый профиль либо настроить бюджет вручную.
  - **Источник:** «дай параметры оптимизации свечения на UI».
  - **Acceptance hint:** select присутствует в группе настроек траектории и сохраняется между перезагрузками.

- **Ручные параметры оптимизации:** в режиме `Ручной` UI должен предоставлять масштаб glow-буфера `25–100%`, частоту обновления `15–60 FPS`, максимум точек glow-слоя `100–2000` и уровень прореживания `1–10`.
  - **Пояснение:** параметры определяют ограниченный бюджет отрисовки свечения.
  - **Источник:** «дай параметры оптимизации свечения на UI».
  - **Acceptance hint:** поля доступны только в ручном режиме и применяются без перезагрузки.

- **Автоматический режим:** в режиме `Авто` UI должен предоставлять целевой FPS со значениями `30`, `45` и `60`; качество должно адаптироваться локально по времени кадра.
  - **Пояснение:** устройства разной мощности должны самостоятельно подбирать стоимость эффекта.
  - **Источник:** «Максимально оптимизируй».
  - **Acceptance hint:** автоматический профиль меняет внутренний бюджет, не изменяя сохранённые ручные значения.

- **Отключение свечения:** при радиусе свечения `0` glow-буфер не должен перерисовываться или копироваться.
  - **Пояснение:** выключенный эффект не должен создавать скрытую нагрузку.
  - **Источник:** «исправь механизм свечения».
  - **Acceptance hint:** glow revision не растёт при изменении траектории и `glow = 0`.

- **Зависимости от select:** система UI-настроек должна поддерживать декларативные условия активации по конкретному значению или набору значений checkbox/select.
  - **Пояснение:** механизм должен подходить для текущих и будущих настроек.
  - **Источник:** «при выборе параметров из select делай disabled параметры которые актуальны только для конкретных выбранных пунктов из select».
  - **Acceptance hint:** зависимости пересчитываются после ручного изменения, загрузки настроек, выбора версии и серверной синхронизации.

- **Зависимости стиля линии:** при `Сплошная` должны быть отключены «Длина штриха» и «Интервал»; при `Пунктир` доступны оба поля; при `Точечная` отключена «Длина штриха», а «Интервал» доступен.
  - **Пояснение:** UI не предлагает параметры, которые не используются выбранным алгоритмом штриха.
  - **Источник:** требование о зависимых параметрах select.
  - **Acceptance hint:** поля получают настоящий `disabled` сразу после выбора стиля.

- **Зависимости режима свечения:** ручные поля доступны только при `Ручной`, целевой FPS — только при `Авто`; в готовых пресетах обе группы недоступны.
  - **Пояснение:** готовые профили должны иметь однозначное поведение.
  - **Источник:** требования о параметрах оптимизации и select-зависимостях.
  - **Acceptance hint:** переключение режима не сбрасывает значения скрытых параметров.

- **Зависимости темы:** при фиксированной тёмной теме должно отключаться неиспользуемое смешивание траектории для светлой темы; при фиксированной светлой теме должны отключаться параметры blur-подложки дождя для тёмной темы; при `Авто` обе группы доступны.
  - **Пояснение:** UI должен отражать фактическое применение параметров движком.
  - **Источник:** требование о зависимых параметрах select.
  - **Acceptance hint:** зависимости корректно работают между разными группами меню.

- **Сохранение отключённых значений:** disabled-поле не должно сбрасываться; после повторной активации восстанавливается последнее значение.
  - **Пояснение:** переключение режимов не должно разрушать пользовательскую настройку.
  - **Источник:** требование о disabled-параметрах.
  - **Acceptance hint:** цикл выбора двух режимов сохраняет исходное значение зависимого поля.

## Нефункциональные требования

- **Производительность:** стоимость glow-слоя должна быть ограничена выбранным бюджетом и не зависеть от полной длины неограниченной траектории.
  - **Пояснение:** устранить деградацию производительности по мере накопления точек.
  - **Источник:** «Максимально оптимизируй».
  - **Acceptance hint:** профилирование не показывает посегментный `shadowBlur` и постоянное копирование неизменного trail canvas.

- **Плавность UI:** изменение радиуса и параметров качества свечения не должно синхронно блокировать интерфейс полной перерисовкой на каждое событие.
  - **Пояснение:** управление должно оставаться отзывчивым на длинной траектории.
  - **Источник:** «исправь механизм свечения».
  - **Acceptance hint:** обновления объединяются через animation frame.

- **Визуальная совместимость:** существующие радиус, цвет и общая форма свечения должны сохраниться; степень упрощения геометрии определяется выбранным режимом качества.
  - **Пояснение:** оптимизация не должна превращать эффект в другой визуальный стиль.
  - **Источник:** «исправь механизм свечения».
  - **Acceptance hint:** нулевое свечение совпадает с прежней базовой линией, положительное создаёт визуально непрерывный ореол.

- **Доступность:** неактуальные элементы должны получать настоящий `disabled`, визуальное состояние отключения и объясняющую подсказку.
  - **Пояснение:** состояние должно быть понятно визуально и вспомогательным технологиям.
  - **Источник:** «делай disabled параметры».
  - **Acceptance hint:** disabled-поля недоступны с клавиатуры и имеют состояние на контейнере.

- **Персистентность:** новые локальные параметры оптимизации должны сохраняться между перезагрузками, а существующие настройки и текущий пользовательский шаблон не должны перезаписываться при миграции.
  - **Пояснение:** параметры производительности относятся к конкретному устройству.
  - **Источник:** approved трактовка требования.
  - **Acceptance hint:** после обновления схемы старые значения сохраняются, новые получают безопасные defaults.

- **Совместимость маршрутов:** изменения должны одинаково действовать на основной странице и `/drafts`.
  - **Пояснение:** оба маршрута обслуживают один интерфейс.
  - **Источник:** актуальная архитектура продукта.
  - **Acceptance hint:** smoke-проверка выполняется на обоих маршрутах.

## Проблемы и замечания, превращённые в требования

- **Посегментное размытие:** сейчас `shadowBlur` применяется к каждому сегменту, а вся траектория рисуется заново. Требуемое поведение: отдельный ограниченный пакетный проход свечения.
  - **Источник:** «Максимально оптимизируй и исправь механизм свечения».
  - **Acceptance hint:** базовая линия и glow-маска имеют раздельные render passes.

- **Постоянное Fold-копирование:** сейчас Fold копирует canvas каждый animation frame независимо от изменений. Требуемое поведение: синхронизация по ревизии содержимого.
  - **Источник:** проблема выявлена при анализе требования об оптимизации.
  - **Acceptance hint:** счётчик копирований не меняется на статичной сцене.

- **Неограниченная стоимость:** сейчас `trailUnlimited` и плотные точки создают неограниченную стоимость свечения. Требуемое поведение: независимый ограниченный glow-бюджет.
  - **Источник:** проблема выявлена при анализе требования об оптимизации.
  - **Acceptance hint:** glow path ограничен даже при росте основной траектории.

- **Ограниченные UI-зависимости:** сейчас UI умеет зависеть только от состояния checkbox. Требуемое поведение: условия по значениям checkbox и select.
  - **Источник:** «при выборе параметров из select делай disabled параметры».
  - **Acceptance hint:** декларативное условие поддерживает одно значение и массив допустимых значений.

- Конкретные внутренние бюджеты пресетов `Производительность`, `Баланс` и `Качество` подбираются профилированием в ходе реализации и закрепляются автоматическими тестами.
