# Demo — Sisyphus The Czar

## Паспорт

- **Стадия:** POC B
- **Последнее обновление:** 2026-08-11
- **Dev URL:** `http://127.0.0.1:18082/`
- **Участники:** два независимых browser context

## Подготовка

```bash
docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml ps
```

Проверить `GET /healthz`, открыть `/` в двух независимых браузерах и отдельно убедиться, что `/drafts`, `/drafts/` и `/drafts/assets/missing.js` отвечают `404`. Для демонстрации препятствия заранее разрешить всплывающие окна для `127.0.0.1:18082`; сначала полезно оставить их заблокированными и показать диагностический статус.

## Короткий сценарий

### Проверка помеченной конфигурации

1. Открыть отдельное окно настроек, сохранить именованную версию с изменённым тяготением и выключенным «Звуком руки», затем поставить флаг в её строке.
2. Повторно изменить тяготение в той же помеченной версии, сохранить её и убедиться, что статус по-прежнему показывает имя выбранной production-конфигурации.
3. Быстро перезагрузить ранее открытую личную сессию и убедиться, что её настройки не сбросились, затем создать новую сессию в отдельном browser context и проверить в ней значения помеченной версии и звук при наведении на камень.

Ожидается: кнопка флага доступна, отметка остаётся единственной, повторное сохранение обновляет все параметры помеченной версии. Новая личная сессия получает последние сохранённые physics/room settings, включая `handAudioEnabled=false`, и не воспроизводит «Кандалы». Ранее открытая комната при reload/reconnect сохраняет собственные настройки и игровое состояние; новый preset не сбрасывает её задним числом.

### 0. Сцена «кошки-мышки» со смехом

1. Запустить dev-сборку и открыть новую стартовую сессию.
2. Разрешить popup для сайта. Вверху настроек выбрать «Сцена 1. Кошки-мышки»: должны остаться только относящиеся к ней и общие разделы. Раскрыть общую «Траекторию», включить линию, изменить толщину или цвет и убедиться, что после перехода во вкладку «Репка» видны те же значения. Вернуться в первую вкладку; в «Камне» установить «Количество фейковых кликов» `3`, радиус `100%`, максимальный отскок `100%`, несрабатывание `0%`, скорость `1200 px/s` и заметно нелинейную кривую.
3. Дважды медленно войти мышью в радиус слева с полным выходом между входами: камень должен каждый раз прыгнуть вправо и нарисовать след без `Смех.mp3`. На третьем входе отскока также быть не должно; движение внутри радиуса не создаёт повторных проверок и auto-hop не расходует три фейковых клика.
4. Нажать по камню в точке третьего сближения. Камень должен оттолкнуться по фейковому клику, а реальное окно с `ВЗГЛЯД.jpg` — открыться центром на месте клика, сохранить пропорции картинки, заполнить её целиком и закрыться по клику или примерно через две секунды. Gachi, физика и серверное управление не запускаются.
5. Полностью выйти и снова войти в радиус: при `0%` камень снова обязан отскочить без смеха. Задать `100%`, повторить выход/вход и убедиться, что отскок не сработал. Вернуть `0%`, сделать оставшиеся два фейковых клика и проверить image-popup и один `Смех.mp3` на каждый клик; четвёртый клик удерживать — без gachi должны материализоваться wrapped-позиция и включиться физика. Следующий клик сцены 2 должен воспроизвести выбранный звук.
6. Вернуться в старт через «Начать сначала», задать максимальный отскок `150%`, сравнить скорость камня при `300` и `3000 px/s`, затем проверить уход вправо/вниз/по диагонали. После seamless-переноса камень не должен оказаться в исходной точке или снова в зоне руки; небезопасный полный перенос должен сократиться или отклониться.
7. Изменить размер камня и viewport, убедиться, что радиус масштабируется вместе с визуальной шириной, затем reload: шесть настроек hop должны сохраниться.

Ожидается: первые два входа руки гарантированно запускают hop, третий гарантированно пропускается, после чего работает выбранная вероятность. Первые N кликов открывают неблокирующее окно с `ВЗГЛЯД.jpg`, запускают hop со смехом и оставляют видимую линию в общем trail-buffer, но только клик N+1 начинает игровую физику. Раздел «Траектория» и его значения одинаковы в обеих сценовых вкладках. Радиус следует за текущим размером камня, максимальная дистанция — за направлением и пропорциями viewport, а duration — за длиной пути и заданной скоростью. Границы остаются бесшовными; reload сохраняет настройки, restart также обнуляет click-счётчик и цикл обязательного третьего пропуска.

### 1. Личные сессии

1. Открыть `/` в двух браузерах.
2. В DevTools сравнить query `session` у WebSocket.
3. Поднять камень во втором браузере.

Ожидается: session ID различаются; движение второго камня не меняет первый. В каждой сессии один клиент и одна рука.

### 2. Отставание слабой руки

1. Открыть настройки → «Камень».
2. Установить массу и тяготение так, чтобы `Fhand < m · g`.
3. Захватить камень и быстро переместить руку вверх и в сторону.

Ожидается: захват сохраняется, камень следует за рукой с заметным плавным отставанием по X и Y. Увеличение `Fhand / Fg` уменьшает отставание; движение остаётся плавным при разных частотах рендера.

### 3. Независимые переключатели

1. В группе «Камень» выключить «Случайное выпадение» и оставить «Выпрыгивание вверх».
2. Установить интервал `1 s`, разброс угла `0°` и разброс силы `0%`, удерживать камень.
3. Затем включить случайное выпадение и выключить выпрыгивание.

Ожидается: в первом случае через секунду происходит только вертикальный прыжок; во втором сохраняется только выпадение в окне `0.5–2 s`. Выключение прыжка блокирует все три связанных range-контрола, но не checkbox случайного выпадения.

### 4. Направление и разброс выпрыгивания

1. Включить выпрыгивание, установить интервал `1 s`, разброс угла `180°` и разброс силы `100%`.
2. Несколько раз подхватить камень и дождаться события.

Ожидается: камень отделяется от руки; направление меняется симметрично влево и вправо по всей верхней полуплоскости, а величина импульса варьируется. При одновременном deadline прыжка и выпадения приходит `reason="jumped"`.

### 5. Main, 3D Fold и удалённый draft URL

1. На `/` открыть настройки → `3D Fold` и проверить defaults: положение `0%`, высота панели `20 vh`, угол `30°`, размер линзы `20 vh`, включённое смешивание и `cubic-bezier(0.333, 0, 0.667, 1)`.
2. Установить положение `60%`, высоту панели `35 vh`, изменить угол и размер линзы, выключить/включить смешивание; при размере линзы `0` Fold должен исчезнуть.
3. Вернуться на `/`, прокрутить страницу вверх и вниз: Fold должен двигаться вместе со сценой, а не оставаться у верхнего края viewport. При положении `100%` нижняя граница панели не должна выходить за нижнюю границу страницы.
4. Перезагрузить `/`, снова открыть `3D Fold` и проверить сохранённые значения. Затем открыть `/drafts`, `/drafts/` и `/drafts/assets/missing.js`.

Ожидается: `/` показывает основную сцену с полноширинной Fold-панелью в выбранной точке документа и основной панелью настроек без плавающего блока `Draft / 3D Fold`; высота панели не меняет размер линзы, Fold не закреплён к viewport, изменённые значения сохраняются после reload. Все три legacy URL возвращают `404`.

### 5a. Изображения камня и независимый пульс

1. В настройках → «Камень» выбрать `rock2.png` для основного камня и `rock.webp` для fold-зеркала.
2. Сохранить версию и настройки комнаты, вернуться на сцену и сравнить основной камень, отпечаток и верхнее fold-зеркало.
3. Включить пульс, задать уменьшение при нажатии `7%`, при пульсе `30%` и дождаться фазы сжатия.
4. Нажать и удерживать камень во время пульса, затем выключить пульс и проверить доступность его процента.

Ожидается: основной камень и отпечаток используют `rock2.png`, fold независимо показывает `rock.webp`. Без нажатия пульс достигает выбранных `30%`; во время нажатия масштаб определяется только `7%`. При выключенном пульсе его ползунок виден, но недоступен. После reload выбор восстанавливается.

### 5b. Вход в стены и сохранение UI

1. В настройках → «Камень» проверить «Вход в нижнюю и боковые стены, %»: диапазон `0–50`, шаг `1`, default `20`.
2. Установить `20%`, изменить ещё один shared-параметр и локальный профиль свечения, затем сохранить версию и настройки комнаты.
3. На сцене переместить камень к нижней, левой и правой границам, после чего перезапустить страницу и создать новую личную сессию в том же браузере.

Ожидается: у нижней стены скрывается 20% визуальной высоты камня, у боковой — 20% визуальной ширины, верхняя граница не меняется. После reload и новой сессии все изменённые UI-параметры восстановлены и совпадают с фактическим поведением; первый запуск чистого browser context по-прежнему использует production preset.

### 5c. Размер камня и камера сцены 2

1. Выбрать «Сцена 2. Репка» и проверить в группе «Камень» последовательность: «Начальный размер, %», «Размер после запуска физики, %», «Конечный размер, %». Переключиться в сцену 1 и убедиться, что этих трёх полей там нет.
2. Задать заметно различающиеся начальный и послеактивационный размеры, запустить физику, дать камню уменьшиться и подобрать его рукой снизу.
3. Поднимать камень несколькими длинными движениями: viewport должен плавно идти вверх с коэффициентом `cameraFollowLerp`, без скачка при входе в верхнюю область. Затем опустить камень ниже текущего viewport-anchor.

Ожидается: при подборе после запуска физики камень за `300 ms` увеличивается в руке до начального размера. При default-настройках камера lerp-движением следует вниз за падающим камнем и не прокручивается вверх; включение «Автоскролл в верхней области» разрешает lerp-прокрутку вверх, а выключение «Следовать при падении» запрещает движение камеры вниз.

### 6. Препятствие «Окна»

1. На `/` открыть настройки и убедиться, что категория называется «Рука», затем открыть «Препятствия → Окна».
2. При заблокированных popup нажать «Проверить открытие окна».
3. Разрешить всплывающие окна для сайта, повторить проверку, закрыть пустое test window кликом.
4. Включить препятствие, оставить высоту `1000–1500vh`, interval `0.5–1.5 s`, ширину `240–640 px`, высоту `160–480 px`.
5. Поднять центр камня в диапазон. Не закрывать первое окно и дождаться второго; затем одно закрыть кликом, другое оставить на две секунды.
6. Пока окно активно, попробовать захватить камень; затем вывести камень из диапазона и вернуться.

Ожидается: при блокировке статус объясняет, что popup нужно разрешить, и автоматические показы не идут. После разрешения появляются реальные пустые browser windows случайных размеров; они закрываются независимо. Пока открыт хотя бы один obstacle popup, захват недоступен, но камень продолжает физическое движение. После последнего закрытия управление возвращается. Выход отменяет только новые окна, повторный вход начинает новый случайный interval.

### 7. След из 10 000 точек и локальные render-профили

1. Открыть «Траектория», убедиться, что настройки неограниченного следа нет, установить «Хранимых точек» в `10000` и переключить локальный профиль `Low → Mobile → Desktop → High → Auto`.
2. В двух личных сессиях накопить общий след, обновить третий клиент и убедиться, что он получает ровно последние 10 000 точек без визуального дубликата при первом snapshot.
3. На активном клиенте продолжить движение: старая линия должна оставаться стабильной, новые точки — появляться в session-слое, а после checkpoint объединяться с history без разрыва.
4. Сделать небольшой scroll внутри текущего трёхэкранного окна, затем перейти через его границу. В первом случае history не должен перестраиваться, во втором — должен обновиться один раз.
5. Переключить стиль линии между сплошным, точечным и пунктирным, затем тему между светлой и тёмной. Установить силу свечения `0`, оставить сцену без движения на 1,2 секунды и проверить debug-счётчики.

Ожидается: canonical state не превышает 10 000 точек, профиль меняет только render-бюджет, history использует не более 50 stroke batches, а в idle не растут revisions, Fold copy count и не остаётся активного rAF. При `glow=0` glow-canvas больше не обновляется.

### 8. Shared trail и шаблоны

1. Двигать камни в разных личных сессиях.
2. Проверить обмен подтверждаемыми trail-дельтами, пакеты append до 16 точек/50 ms и resync полной FIFO-историей при устаревшем cursor.
3. В debug открыть настройки, изменить параметр, ввести название версии и убедиться, что отдельной кнопки «Сохранить для комнаты» нет. Нажать компактную кнопку рядом с названием и дождаться статуса «Версия и настройки комнаты сохранены».
4. Проверить новое значение в игровой комнате и именованный шаблон в `config/settings-templates.json`.
5. Назначить сохранённый шаблон production preset и открыть `config/production-preset.json`.

Ожидается: физика камней не объединяется, shared trail агрегируется отдельно. Одна compact-кнопка сохраняет версию без дубликата и применяет room settings; общий успех появляется после обоих подтверждений. Каталог шаблонов и production preset записываются атомарно и видны в Git.

### 9. Постоянный preclick-hop

1. Запустить dev-сборку и до первого клика покрутить колесо: камера не должна сдвинуться.
2. В категории «Рука» проверить режимы «Показывать всегда», «Показывать по hover» и «Не показывать». Установить задержку `300 мс`; настоящий захват после фейковых кликов должен начинаться сразу, а изображение руки — меняться примерно через `300 мс`. Затем навести указатель на settings-toggle и открытую settings-panel: фото-рука должна уступить место нативному курсору.
3. В группе «Камень» установить `Количество фейковых кликов = 3`, радиус `100%`, максимальный отскок `150%`, несрабатывание `0%`, скорость `1200 px/s` и пользовательскую кривую; убедиться, что старых hop/parallax-полей в сохранённой конфигурации нет.
4. Дважды войти в радиус после полного выхода, затем войти в третий раз: первые два входа должны оттолкнуть камень, третий — пропустить руку. Нажать по камню и проверить image-popup и отскок по фейковому клику. При следующем входе `0%` должен снова дать hop; движение внутри радиуса не создаёт повторов.
5. Проверить перенос через левую/правую, верхнюю/нижнюю границы и угол с сохранением overshoot.
6. Установить число фейковых кликов `0`, затем в «Рука» задать радиус захвата `4 vh`, нажать рядом с краем перенесённого камня и продолжить двигать его вверх.
7. После включения физики выбрать в сцене 2 `Camen`, затем несколько раз быстро нажать непосредственно на камень: каждый click/tap должен запустить отдельный экземпляр `Camen.mp3`, и звуки должны накладываться. Выбрать другой gachi-файл и убедиться, что следующий клик использует его. Отпустить камень: с началом падения активные gachi должны остановиться, а при первом приземлении должен один раз прозвучать `СимуляцияОргазма.mov`. Последующие отскоки должны молчать; после нового касания рукой следующий отдельный контакт с землёй снова должен прозвучать ровно один раз.
8. Сначала перезагрузить страницу до первого захвата и убедиться, что hop, scroll lock и viewport у низа восстановлены. Затем захватить камень, поднять его, перезагрузить страницу и убедиться, что восстановлены та же сессия и camera-follow. После этого нажать «Начать сначала» и убедиться, что сцена вернулась в стартовый hop lifecycle без reload, а настройки сохранились.

Ожидается: в постоянном режиме фото-рука видна по всей сцене, в hover-режиме — только над камнем, в скрытом режиме не видна даже при клике и захвате. Настроенная задержка влияет только на смену спрайта руки. Первые два radius-entry дают hop без смеха, третий — forced miss, последующие используют выбранную вероятность; быстрый вход увеличивает дистанцию, а UI-скорость и кривая управляют временем и профилем движения камня. Wrapped-позиция безопасна относительно старта и руки. Mouse-клик в пределах `4 vh` от визуального прямоугольника захватывает камень, touch-зона не расширяется. При N>0 первые N кликов открывают `ВЗГЛЯД.jpg`, воспроизводят смех и отталкивают камень без gachi; клик N+1 бесшумно завершает hop и включает физику. Каждый последующий click/tap сцены 2 создаёт независимый экземпляр выбранного gachi; падение прекращает активные экземпляры, а impact-звук имеет одноразовый допуск «новое касание рукой → первое приземление».

Reload до первого захвата сохраняет preclick-состояние и после применения серверной высоты комнаты открывает низ сцены. Reload после начала игры восстанавливает прежнюю серверную сессию, оставляет preclick завершённым и возвращает камень в поле зрения camera-follow при сохранённых значениях UI.

Кнопка «Начать сначала» видна на `/`, доступна с клавиатуры и выполняет явный полный restart. Она не меняет семантику reload: перезагрузка продолжает восстановление, а не сброс игры.

### 10. Общий SVG-курсор

1. Открыть настройки → «Курсор» и убедиться, что «Показывать курсор» выключен, а размер `32 px` виден, но недоступен.
2. Включить флаг: поверх фото-руки должен появиться `handopen.svg`, а ползунок размера стать доступным.
3. Установить `64 px`, нажать и удерживать основную кнопку мыши: SVG должен смениться на `handgrabbing.svg`; после отпускания — вернуться к открытому состоянию.
4. Навести указатель на настройки и toolbar сессии: локальная рука и SVG скрываются, остаётся нативный курсор.
5. В двух debug-клиентах проверить общий флаг/размер и удалённую руку. Затем обновить Git-конфигурацию production, собрать новую версию и перезагрузить production-страницу.

Ожидается: SVG отображается дополнительно к фото-руке только на fine pointer, повторяет её позицию, видимость и grabbing-состояние для локального и удалённого участника. Настройки входят в черновик, именованную версию, `config/settings-templates.json` и production preset. Активному production-клиенту live-обновление не требуется — новая конфигурация применяется после reload обновлённой сборки.

## Техническая проверка

```bash
docker exec sisyphus-the-czar-dev npm run lint
docker exec sisyphus-the-czar-dev npm run build
docker exec sisyphus-the-czar-dev npm test
```

Дополнительно выполнить production smoke, UI/Fold smoke и постоянный `preclick-hop`. Критерий передачи: проверки зелёные, `/healthz` возвращает `status=ok`, legacy `/drafts*` возвращает `404`, автоматические wrapped-отскоки проходят без смеха, фейковые клики — со смехом, а reload/restart/scroll lock и кликабельность после переноса сохраняются.

## Что не входит в демонстрацию

- точная модель мышц, сухого трения и деформации захвата;
- межпользовательское совместное удержание одного камня;
- автоматические Git commit/push/pull;
- настройка двухсекундного срока жизни, содержимого obstacle-popup или `ВЗГЛЯД.jpg` в preclick-popup, перетаскивание окон, внутриигровая имитация и обход browser popup policy;
- другие препятствия и физические столкновения окон с камнем;
- горизонтальное масштабирование session store.
