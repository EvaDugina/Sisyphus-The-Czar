# Demo — Sisyphus The Czar

## Паспорт

- **Стадия:** POC B
- **Последнее обновление:** 2026-08-06
- **Dev URL:** `http://127.0.0.1:18082/`
- **Участники:** два независимых browser context

## Подготовка

```bash
docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml ps
```

Проверить `GET /healthz`, открыть `/` в двух независимых браузерах и `/drafts/` в третьей вкладке. Для демонстрации препятствия заранее разрешить всплывающие окна для `127.0.0.1:18082`; сначала полезно оставить их заблокированными и показать диагностический статус.

## Короткий сценарий

### 0. Parallax до первого клика

1. Запустить dev-сборку и открыть настройки → «Камень».
2. Проверить defaults: начальный/конечный максимум `0.6/0 vw`, радиус `50 vw`, начальная/конечная задержка `0/1000 ms`, transition duration `30 s`, две linear cubic-bezier-кривые и возврат `400 ms` с прежней кривой.
3. Установить начальный/конечный максимум `20/0 vw`, duration `1 s`, активно двигать рукой внутри радиуса около половины секунды и остановиться: максимум должен уменьшиться, а во время остановки — не меняться.
4. В категории «Рука» выключить и включить «Показывать руку всегда», установить радиус захвата `4 vh`. В hover-режиме фото-рука должна появляться только над камнем; клик рядом с визуальной границей, но внутри `4 vh`, должен захватить камень.
5. Не кликая камень, перезагрузить страницу, покрутить колесо и провести рукой внутри радиуса, затем резко вывести её наружу и войти снова: новый вход должен использовать начальные значения.
6. В категории «Камера» проверить lerp `0.1`, кликнуть камень и переместить его вверх.

Ожидается: до захвата физика и камера статичны, колесо не прокручивает сцену, а parallax стабильно работает после reload и при системном reduced motion. Внутри радиуса камень следует за указателем только позиционным смещением; активное движение меняет delay/max по двум графикам, статичное время не учитывается, выход сбрасывает progress. Снаружи камень возвращается к исходной позиции. Прямой или расширенный mouse-захват включает физику, отключает parallax, а камера через lerp удерживает камень по центру высоты viewport. Размер и пропорции камня не меняются.

### 1. Личные сессии

1. Открыть `/` в двух браузерах.
2. В DevTools сравнить query `session` у WebSocket.
3. Поднять камень во втором браузере.

Ожидается: session ID различаются; движение второго камня не меняет первый. В каждой сессии один клиент и одна рука.

### 2. Отставание слабой руки

1. Открыть настройки → «Камень».
2. Установить массу и тяготение так, чтобы `Fhand < m · g`.
3. Захватить камень и быстро переместить руку вверх и в сторону.

Ожидается: захват сохраняется, камень следует за рукой с заметным плавным отставанием по X и Y. Увеличение `Fhand / Fg` уменьшает отставание; движение остаётся плавным при разных частотах рендера.

### 3. Независимые переключатели

1. В группе «Камень» выключить «Случайное выпадение» и оставить «Выпрыгивание вверх».
2. Установить интервал `1 s`, разброс угла `0°` и разброс силы `0%`, удерживать камень.
3. Затем включить случайное выпадение и выключить выпрыгивание.

Ожидается: в первом случае через секунду происходит только вертикальный прыжок; во втором сохраняется только выпадение в окне `0.5–2 s`. Выключение прыжка блокирует все три связанных range-контрола, но не checkbox случайного выпадения.

### 4. Направление и разброс выпрыгивания

1. Включить выпрыгивание, установить интервал `1 s`, разброс угла `180°` и разброс силы `100%`.
2. Несколько раз подхватить камень и дождаться события.

Ожидается: камень отделяется от руки; направление меняется симметрично влево и вправо по всей верхней полуплоскости, а величина импульса варьируется. При одновременном deadline прыжка и выпадения приходит `reason="jumped"`.

### 5. Main, 3D Fold и совместимый draft URL

1. На `/` открыть настройки → `3D Fold` и проверить defaults: `30°`, `20 vh`, включённое смешивание, `cubic-bezier(0.333, 0, 0.667, 1)`.
2. Изменить угол и размер зоны, выключить/включить смешивание; при размере `0` Fold должен исчезнуть.
3. Перезагрузить страницу через `/drafts/` и снова открыть `3D Fold`.

Ожидается: `/` и `/drafts/` показывают одну и ту же основную сцену с верхней Fold-зоной и основной панелью настроек без плавающего блока `Draft / 3D Fold`; изменённые значения сохраняются между URL.

### 6. Препятствие «Окна»

1. На `/` открыть настройки и убедиться, что категория называется «Рука», затем открыть «Препятствия → Окна».
2. При заблокированных popup нажать «Проверить открытие окна».
3. Разрешить всплывающие окна для сайта, повторить проверку, закрыть пустое test window кликом.
4. Включить препятствие, оставить высоту `1000–1500vh`, interval `0.5–1.5 s`, ширину `240–640 px`, высоту `160–480 px`.
5. Поднять центр камня в диапазон. Не закрывать первое окно и дождаться второго; затем одно закрыть кликом, другое оставить на две секунды.
6. Пока окно активно, попробовать захватить камень; затем вывести камень из диапазона и вернуться. Повторить через `/drafts/`.

Ожидается: при блокировке статус объясняет, что popup нужно разрешить, и автоматические показы не идут. После разрешения появляются реальные пустые browser windows случайных размеров; они закрываются независимо. Пока открыт хотя бы один obstacle popup, захват недоступен, но камень продолжает физическое движение. После последнего закрытия управление возвращается. Выход отменяет только новые окна, повторный вход начинает новый случайный interval. UI и поведение совпадают на обоих URL.

### 7. Оптимизированное свечение и зависимости UI

1. Открыть «Траектория» и переключить профили `Баланс`, `Авто`, `Ручной`.
2. Убедиться, что целевой FPS доступен только в `Авто`, а четыре ручных параметра — только в `Ручной`.
3. В ручном режиме установить glow-буфер `25%`, glow FPS `15`, лимит `100` точек и прореживание `10`; включить неограниченный след и подвигать камень.
4. Переключить стиль линии между сплошным, точечным и пунктирным, затем тему между светлой и тёмной.
5. Установить силу свечения `0` и перезагрузить страницу через `/drafts/`.

Ожидается: значения сохраняются локально, но не попадают в именованный серверный шаблон; неактуальные поля остаются видимыми и получают `disabled`. Длинный след не вызывает резкого роста стоимости glow, при `glow=0` glow-canvas больше не обновляется, основная страница и `/drafts/` ведут себя одинаково.

### 8. Shared trail и шаблоны

1. Двигать камни в разных личных сессиях.
2. Проверить обмен подтверждаемыми trail-дельтами.
3. В debug сохранить именованный шаблон и открыть `config/settings-templates.json`.
4. Назначить сохранённый шаблон production preset и открыть `config/production-preset.json`.

Ожидается: физика камней не объединяется, shared trail агрегируется отдельно, каталог шаблонов и production preset записываются атомарно и видны в Git.

### 9. Настраиваемая подсказка parallax

1. Запустить dev-сборку и до первого клика покрутить колесо: камера не должна сдвинуться.
2. В категории «Рука» переключить постоянный и hover-режим, затем навести указатель на settings-toggle и открытую settings-panel: фото-рука должна уступить место нативному курсору.
3. В группе «Камень» установить начальный/конечный максимум `3.6/0 vw`, радиус `70 vw`, начальную/конечную задержку `0/1000 ms` и duration `10 s`; проверить две независимые cubic-bezier-кривые и подписи осей `vw`, `ms`, `0–10 s`.
4. С каждой стороны перемещать руку от границы круга к центру: смещение должно расти до `3.6 vw` и оставаться направленным в сторону руки.
5. Нажать «Инвертировать parallax» и повторить движение: величина должна сохраниться, а направление смениться на противоположное.
6. Вывести руку дальше `70 vw`, вернуть внутрь и убедиться, что задержка стартовала заново. В «Рука» установить радиус захвата `4 vh`, нажать рядом с краем камня и продолжить двигать его вверх.
7. Отпустить камень, перезагрузить страницу и дважды повторить цикл «дождаться parallax → захватить камень → reload»; убедиться, что кнопки «Начать сначала» в интерфейсе нет.

Ожидается: в постоянном режиме любое основное нажатие показывает захвативший спрайт, в hover-режиме фото-рука видна только над камнем. Внутри радиуса parallax растёт при приближении к центру, но его текущий максимум уменьшается только во время активного движения; остановка сохраняет progress, выход сбрасывает его и отменяет ожидание. По умолчанию камень смещается в сторону руки, кнопка инверсии меняет направление. Mouse-клик в пределах `4 vh` от визуального прямоугольника захватывает камень, touch-зона не расширяется. Первый успешный захват отключает parallax, включает физику и camera-follow.

После каждого reload ожидаются заново активный preclick parallax и статичная камера при сохранённых значениях UI.

## Техническая проверка

```bash
docker exec sisyphus-the-czar-dev npm run lint
docker exec sisyphus-the-czar-dev npm run build
docker exec sisyphus-the-czar-dev npm test
```

Дополнительно выполнить production smoke, draft smoke и preclick-guidance smoke. Критерий передачи: проверки зелёные, `/healthz` возвращает `status=ok`, default-рука видна сразу, hover-режим ограничивает её камнем, parallax переживает reload/reduced-motion и соблюдает delay/radius/max, расширенный mouse-захват работает в `vh`, до первого захвата camera scroll заблокирован, после него камера следует за камнем, `/` и `/drafts/` имеют одинаковые сцену/Fold/настройки/obstacle UI.

## Что не входит в демонстрацию

- точная модель мышц, сухого трения и деформации захвата;
- межпользовательское совместное удержание одного камня;
- автоматические Git commit/push/pull;
- настройка двухсекундного срока жизни, содержимое или перетаскивание popup, внутриигровая имитация и обход browser popup policy;
- другие препятствия и физические столкновения окон с камнем;
- горизонтальное масштабирование session store.
