# Demo — Sisyphus The Czar

## Паспорт

- **Стадия:** POC B
- **Последнее обновление:** 2026-08-09
- **Dev URL:** `http://127.0.0.1:18082/`
- **Участники:** два независимых browser context

## Подготовка

```bash
docker compose -f docker-compose.dev.yml up -d --build
docker compose -f docker-compose.dev.yml ps
```

Проверить `GET /healthz`, открыть `/` в двух независимых браузерах и отдельно убедиться, что `/drafts`, `/drafts/` и `/drafts/assets/missing.js` отвечают `404`. Для демонстрации препятствия заранее разрешить всплывающие окна для `127.0.0.1:18082`; сначала полезно оставить их заблокированными и показать диагностический статус.

## Короткий сценарий

### Проверка помеченной конфигурации

1. Открыть отдельное окно настроек, сохранить именованную версию с изменённым тяготением и выключенным «Звуком руки», затем поставить флаг в её строке.
2. Повторно изменить тяготение в той же помеченной версии, сохранить её и убедиться, что статус по-прежнему показывает имя выбранной production-конфигурации.
3. Быстро перезагрузить ранее открытую личную сессию, затем создать новую сессию в отдельном browser context и проверить значения формы и звук при наведении на камень.

Ожидается: кнопка флага доступна, отметка остаётся единственной, повторное сохранение обновляет все параметры помеченной версии, а перезагруженная и новая личные сессии получают последние сохранённые physics/room settings, включая `handAudioEnabled=false`, и не воспроизводят «Кандалы». Игровое состояние при reload сохраняется; чужая уже открытая сессия live не сбрасывается.

### 0. Baseline parallax до первого клика

1. Запустить dev-сборку с `EXPERIMENT_PRECLICK_ROCK_HOP=false` и открыть настройки → «Камень».
2. Проверить defaults: начальный/конечный максимум `0.6/0 vw`, радиус `50 vw`, начальная/конечная задержка `0/1000 ms`, transition duration `30 s`, две linear cubic-bezier-кривые и возврат `400 ms` с прежней кривой.
3. Установить начальный/конечный максимум `20/0 vw`, duration `1 s`, активно двигать рукой внутри радиуса около половины секунды и остановиться: максимум должен уменьшиться, а во время остановки — не меняться.
4. В категории «Рука» выключить и включить «Показывать руку всегда», установить радиус захвата `4 vh`. В hover-режиме фото-рука должна появляться только над камнем; клик рядом с визуальной границей, но внутри `4 vh`, должен захватить камень.
5. Не кликая камень, перезагрузить страницу, покрутить колесо и провести рукой внутри радиуса, затем резко вывести её наружу и войти снова: новый вход должен использовать начальные значения.
6. В категории «Камера» проверить lerp `0.1`, кликнуть камень и переместить его вверх.

Ожидается: до захвата физика и камера статичны, колесо не прокручивает сцену, а parallax стабильно работает после reload и при системном reduced motion. Внутри радиуса камень следует за указателем только позиционным смещением; активное движение меняет delay/max по двум графикам, статичное время не учитывается, выход сбрасывает progress. Снаружи камень возвращается к исходной позиции. Прямой или расширенный mouse-захват включает физику, отключает parallax, а камера через lerp удерживает камень по центру высоты viewport. Размер и пропорции камня не меняются.

### 0a. Эксперимент отскока со смехом

1. Запустить обычную dev-сборку и открыть новую стартовую сессию: экспериментальный отскок включён по умолчанию.
2. В настройках → «Камень» найти «Максимальная длина отскока, vw», установить, например, `80vw`, сохранить общую настройку и обновить сцену.
3. Медленно войти мышью в радиус слева: камень должен один раз прыгнуть вправо примерно на `28%` максимума и запустить `Смех.mp3`.
4. Не выходя из радиуса, двигать мышь: новых прыжков и звуков быть не должно.
5. Выйти из радиуса, убедиться, что камень не возвращается, затем быстро войти снова: дальность должна приблизиться к выбранному максимуму.
6. Задать длину больше расстояния до края и проверить уход вправо/вниз/по диагонали: камень должен появиться слева/сверху/в противоположном углу с сохранением остатка пути.
7. Уменьшить viewport, включить системный reduced motion и повторить вход; после переноса захватить камень.

Ожидается: радиус определяет только момент срабатывания, а «Максимальная длина отскока» — дальность. Второй быстрый прыжок дальше первого и начинается от предыдущей посадки; границы бесшовны по X/Y, reduced motion выполняет мгновенную wrapped-посадку, а число запусков смеха равно числу прыжков. Перенесённый камень остаётся кликабельным, первый захват начинает физику из видимой позиции. Сборка с `EXPERIMENT_PRECLICK_ROCK_HOP=false` сохраняет штатный parallax из сценария 0.

### 1. Личные сессии

1. Открыть `/` в двух браузерах.
2. В DevTools сравнить query `session` у WebSocket.
3. Поднять камень во втором браузере.

Ожидается: session ID различаются; движение второго камня не меняет первый. В каждой сессии один клиент и одна рука.

### 2. Отставание слабой руки

1. Открыть настройки → «Камень».
2. Установить массу и тяготение так, чтобы `Fhand < m · g`.
3. Захватить камень и быстро переместить руку вверх и в сторону.

Ожидается: захват сохраняется, камень следует за рукой с заметным плавным отставанием по X и Y. Увеличение `Fhand / Fg` уменьшает отставание; движение остаётся плавным при разных частотах рендера.

### 3. Независимые переключатели

1. В группе «Камень» выключить «Случайное выпадение» и оставить «Выпрыгивание вверх».
2. Установить интервал `1 s`, разброс угла `0°` и разброс силы `0%`, удерживать камень.
3. Затем включить случайное выпадение и выключить выпрыгивание.

Ожидается: в первом случае через секунду происходит только вертикальный прыжок; во втором сохраняется только выпадение в окне `0.5–2 s`. Выключение прыжка блокирует все три связанных range-контрола, но не checkbox случайного выпадения.

### 4. Направление и разброс выпрыгивания

1. Включить выпрыгивание, установить интервал `1 s`, разброс угла `180°` и разброс силы `100%`.
2. Несколько раз подхватить камень и дождаться события.

Ожидается: камень отделяется от руки; направление меняется симметрично влево и вправо по всей верхней полуплоскости, а величина импульса варьируется. При одновременном deadline прыжка и выпадения приходит `reason="jumped"`.

### 5. Main, 3D Fold и удалённый draft URL

1. На `/` открыть настройки → `3D Fold` и проверить defaults: `30°`, `20 vh`, включённое смешивание, `cubic-bezier(0.333, 0, 0.667, 1)`.
2. Изменить угол и размер зоны, выключить/включить смешивание; при размере `0` Fold должен исчезнуть.
3. Перезагрузить `/`, снова открыть `3D Fold` и проверить сохранённые значения. Затем открыть `/drafts`, `/drafts/` и `/drafts/assets/missing.js`.

Ожидается: `/` показывает основную сцену с верхней Fold-зоной и основной панелью настроек без плавающего блока `Draft / 3D Fold`; изменённые значения сохраняются после reload. Все три legacy URL возвращают `404`.

### 5a. Изображения камня и независимый пульс

1. В настройках → «Камень» выбрать `rock2.png` для основного камня и `rock.webp` для fold-зеркала.
2. Сохранить версию и настройки комнаты, вернуться на сцену и сравнить основной камень, отпечаток и верхнее fold-зеркало.
3. Включить пульс, задать уменьшение при нажатии `7%`, при пульсе `30%` и дождаться фазы сжатия.
4. Нажать и удерживать камень во время пульса, затем выключить пульс и проверить доступность его процента.

Ожидается: основной камень и отпечаток используют `rock2.png`, fold независимо показывает `rock.webp`. Без нажатия пульс достигает выбранных `30%`; во время нажатия масштаб определяется только `7%`. При выключенном пульсе его ползунок виден, но недоступен. После reload выбор восстанавливается.

### 6. Препятствие «Окна»

1. На `/` открыть настройки и убедиться, что категория называется «Рука», затем открыть «Препятствия → Окна».
2. При заблокированных popup нажать «Проверить открытие окна».
3. Разрешить всплывающие окна для сайта, повторить проверку, закрыть пустое test window кликом.
4. Включить препятствие, оставить высоту `1000–1500vh`, interval `0.5–1.5 s`, ширину `240–640 px`, высоту `160–480 px`.
5. Поднять центр камня в диапазон. Не закрывать первое окно и дождаться второго; затем одно закрыть кликом, другое оставить на две секунды.
6. Пока окно активно, попробовать захватить камень; затем вывести камень из диапазона и вернуться.

Ожидается: при блокировке статус объясняет, что popup нужно разрешить, и автоматические показы не идут. После разрешения появляются реальные пустые browser windows случайных размеров; они закрываются независимо. Пока открыт хотя бы один obstacle popup, захват недоступен, но камень продолжает физическое движение. После последнего закрытия управление возвращается. Выход отменяет только новые окна, повторный вход начинает новый случайный interval.

### 7. Оптимизированное свечение и зависимости UI

1. Открыть «Траектория» и переключить профили `Баланс`, `Авто`, `Ручной`.
2. Убедиться, что целевой FPS доступен только в `Авто`, а четыре ручных параметра — только в `Ручной`.
3. В ручном режиме установить glow-буфер `25%`, glow FPS `15`, лимит `100` точек и прореживание `10`; включить неограниченный след и подвигать камень.
4. Переключить стиль линии между сплошным, точечным и пунктирным, затем тему между светлой и тёмной.
5. Установить силу свечения `0` и перезагрузить `/`.

Ожидается: значения сохраняются локально, но не попадают в именованный серверный шаблон; неактуальные поля остаются видимыми и получают `disabled`. Длинный след не вызывает резкого роста стоимости glow, при `glow=0` glow-canvas больше не обновляется.

### 8. Shared trail и шаблоны

1. Двигать камни в разных личных сессиях.
2. Проверить обмен подтверждаемыми trail-дельтами.
3. В debug открыть настройки, изменить параметр, ввести название версии и убедиться, что отдельной кнопки «Сохранить для комнаты» нет. Нажать компактную кнопку рядом с названием и дождаться статуса «Версия и настройки комнаты сохранены».
4. Проверить новое значение в игровой комнате и именованный шаблон в `config/settings-templates.json`.
5. Назначить сохранённый шаблон production preset и открыть `config/production-preset.json`.

Ожидается: физика камней не объединяется, shared trail агрегируется отдельно. Одна compact-кнопка сохраняет версию без дубликата и применяет room settings; общий успех появляется после обоих подтверждений. Каталог шаблонов и production preset записываются атомарно и видны в Git.

### 9. Настраиваемая подсказка parallax

1. Запустить dev-сборку и до первого клика покрутить колесо: камера не должна сдвинуться.
2. В категории «Рука» переключить постоянный и hover-режим, затем навести указатель на settings-toggle и открытую settings-panel: фото-рука должна уступить место нативному курсору.
3. В группе «Камень» установить начальный/конечный максимум `3.6/0 vw`, радиус `70 vw`, начальную/конечную задержку `0/1000 ms` и duration `10 s`; проверить две независимые cubic-bezier-кривые и подписи осей `vw`, `ms`, `0–10 s`.
4. С каждой стороны перемещать руку от границы круга к центру: смещение должно расти до `3.6 vw` и оставаться направленным в сторону руки.
5. Нажать «Инвертировать parallax» и повторить движение: величина должна сохраниться, а направление смениться на противоположное.
6. Вывести руку дальше `70 vw`, вернуть внутрь и убедиться, что задержка стартовала заново. В «Рука» установить радиус захвата `4 vh`, нажать рядом с краем камня и продолжить двигать его вверх.
7. Несколько раз быстро нажать непосредственно на камень: каждый основной click/tap должен запустить отдельный случайный gachi-звук, и звуки должны накладываться. Отпустить камень: с началом падения все gachi должны остановиться, а при первом приземлении должен один раз прозвучать `СимуляцияОргазма.mov`. Последующие отскоки должны молчать; после нового касания рукой следующий отдельный контакт с землёй снова должен прозвучать ровно один раз.
8. Сначала перезагрузить страницу до первого захвата и убедиться, что preclick parallax сохранил начальный режим, viewport открыл низ сцены и камень виден. Затем захватить камень, поднять его, перезагрузить страницу и убедиться, что восстановлены та же сессия и поднятое состояние, камень виден в viewport camera-follow и чёрного экрана нет. После этого нажать «Начать сначала» и убедиться, что сцена вернулась в стартовый preclick lifecycle без reload, а настройки сохранились.

Ожидается: в постоянном режиме любое основное нажатие показывает захвативший спрайт, в hover-режиме фото-рука видна только над камнем. Внутри радиуса parallax растёт при приближении к центру, но его текущий максимум уменьшается только во время активного движения; остановка сохраняет progress, выход сбрасывает его и отменяет ожидание. По умолчанию камень смещается в сторону руки, кнопка инверсии меняет направление. Mouse-клик в пределах `4 vh` от визуального прямоугольника захватывает камень, touch-зона не расширяется. Первый успешный захват отключает parallax, включает физику и camera-follow. Каждый непосредственный click/tap создаёт независимый gachi; падение прекращает все экземпляры, а impact-звук имеет одноразовый допуск «новое касание рукой → первое приземление».

Reload до первого захвата сохраняет preclick-состояние и после применения серверной высоты комнаты открывает низ сцены. Reload после начала игры восстанавливает прежнюю серверную сессию, оставляет preclick завершённым и возвращает камень в поле зрения camera-follow при сохранённых значениях UI.

Кнопка «Начать сначала» видна на `/`, доступна с клавиатуры и выполняет явный полный restart. Она не меняет семантику reload: перезагрузка продолжает восстановление, а не сброс игры.

### 10. Общий SVG-курсор

1. Открыть настройки → «Курсор» и убедиться, что «Показывать курсор» выключен, а размер `32 px` виден, но недоступен.
2. Включить флаг: поверх фото-руки должен появиться `handopen.svg`, а ползунок размера стать доступным.
3. Установить `64 px`, нажать и удерживать основную кнопку мыши: SVG должен смениться на `handgrabbing.svg`; после отпускания — вернуться к открытому состоянию.
4. Навести указатель на настройки и toolbar сессии: локальная рука и SVG скрываются, остаётся нативный курсор.
5. В двух debug-клиентах проверить общий флаг/размер и удалённую руку. Затем обновить Git-конфигурацию production, собрать новую версию и перезагрузить production-страницу.

Ожидается: SVG отображается дополнительно к фото-руке только на fine pointer, повторяет её позицию, видимость и grabbing-состояние для локального и удалённого участника. Настройки входят в черновик, именованную версию, `config/settings-templates.json` и production preset. Активному production-клиенту live-обновление не требуется — новая конфигурация применяется после reload обновлённой сборки.

## Техническая проверка

```bash
docker exec sisyphus-the-czar-dev npm run lint
docker exec sisyphus-the-czar-dev npm run build
docker exec sisyphus-the-czar-dev npm test
```

Дополнительно выполнить production smoke, UI/Fold smoke, штатный preclick-guidance smoke, `preclick-hop` и `preclick-hop-off`. Критерий передачи: проверки зелёные, `/healthz` возвращает `status=ok`, legacy `/drafts*` возвращает `404`, штатный parallax сохраняется при flag-off, включённый эксперимент использует общий максимум, делает накопительные wrapped-отскоки со смехом и оставляет камень кликабельным после переноса.

## Что не входит в демонстрацию

- точная модель мышц, сухого трения и деформации захвата;
- межпользовательское совместное удержание одного камня;
- автоматические Git commit/push/pull;
- настройка двухсекундного срока жизни, содержимое или перетаскивание popup, внутриигровая имитация и обход browser popup policy;
- другие препятствия и физические столкновения окон с камнем;
- горизонтальное масштабирование session store.
